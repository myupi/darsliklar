# Бриф для ИИ: структура, дизайн и функции детского урока

Oct 12, 2026 · @Zarin · версия 2 от 15.10.2026 — обновлена по урокам 1 и 2 курса HTML

## Как пользоваться брифом

Этот документ целиком вставляется в другой ИИ первым сообщением. После него ИИ получает тему урока и пишет по этой структуре сначала сценарий, потом JSX-файл.

Основа — канон курса HTML (`canon/html/canon-v1.jsx`). Он собран скриптом `tools/build-canon.mjs` из эталона Курса 0 (инфра-блок, реестр экранов, библиотека механик, лесенка подсказок, движок озвучки) и героя курса — робота Коди. Эталонные уроки — `lessons/html/01-struktura-dokumenta.jsx` и `lessons/html/02-zagolovki-i-tekst.jsx`, эталонная практика — `lessons/html/01p-struktura-dokumenta.jsx`.

Что ИИ должен выдавать на каждый новый урок:

1. Сценарий по шаблону из последнего раздела: экраны, механики, все реплики на трёх языках.
2. После утверждения сценария — один JSX-файл: канон дословно сверху, урок ниже пометки «УРОК».

> Для Claude Code в проекте (заказчик, 16.10.2026): работа идёт по навыку `/novyy-urok`. Сценарий по умолчанию не ждёт утверждения — урок доводится до проверенного результата самостоятельно; на утверждение сценарий показывается, только если заказчик прямо об этом попросил. Ученики курса — 11–14 лет.

Правило для ИИ: если тема урока требует нарушить правило из этого брифа, он спрашивает, а не придумывает обход. Канон внутри урока не правится никогда. Нужна правка канона — она делается в `tools/build-canon.mjs` или `canon/html/*.part.jsx`, канон пересобирается и дословно переносится во все уроки курса.

## Суть продукта

Урок — интерактивная история для детей. Один урок — один самодостаточный JSX-файл с React-компонентом по умолчанию. Платформа монтирует его, передаёт имя, язык и адрес сервиса озвучки и ждёт один вызов `onFinished`.

Возраст берётся из плана курса: урок 1 курса HTML — 8–10 лет, с урока 2 — 11–14. Тон и сложность заданий подстраиваются под возраст, остальные правила одинаковы.

Урок ведётся голосом. Герой проговаривает каждую реплику, ребёнок слушает и отвечает касаниями. 90% детей проходят урок с телефона, поэтому телефон — основной экран, а не адаптация.

Принципы, на которых держится всё остальное:

- **Понятно с первого взгляда.** На каждом экране ребёнок сразу видит, что делать. Если для этого нужно рассуждать — экран переделывается.
- **Времени нет.** Ни таймеров, ни «успей за 10 секунд».
- **Очков нет.** Ошибка ничего не отнимает, попытки не ограничены.
- **Красного нет.** Ошибка показывается движением и подсказкой, а не цветом.
- **Телефон главнее.** У любой механики есть путь «ткнул — ткнул», перетаскивание никогда не единственный способ.
- **Говорит герой.** Механика не показывает текст сама, а отдаёт реплику герою.
- **Урок не запирает ребёнка.** Каждая блокировка имеет предохранитель по времени, а бездействие подсвечивает, куда нажать.

## Качество урока

Главное требование заказчика (15.10.2026): ученик минимально затрудняется, максимально понимает тему, ему не скучно весь урок и он хочет заниматься дальше. Интерактивность при этом не теряется. **Число экранов не ограничено**: экранов столько, сколько нужно для понимания. Лучше лишний простой экран, чем один перегруженный.

| Правило | Как это выглядит в уроке 2 |
| --- | --- |
| Одно действие на экран. Два дела — два экрана | Старый экран «допиши `</p>` + напиши третий абзац» разделён; осталось одно дело |
| Задание называет конкретную вещь на экране, а не абстракцию. Термин сначала показывается, потом используется | Вместо «Нажми часть раздела «Правила»» — «Нажми заголовок внутри «Правил»» |
| Новое — по шагам: показать → повторить → сделать самому | Уровни заголовков: «Лесенка» (показ с нажатиями) → «Какая цифра?» (три быстрых раунда) → «Расставь сам» (настоящий код) |
| Результат действия виден сразу: живое превью рядом с кодом | Мини-браузер обновляется на каждую букву; нет переключателя «Код / Результат» |
| Каждый выбор проверяется сразу, «Проверить» — только там, где ребёнок пишет теги | «Расставь сам», «Разложи по абзацам», афиша: верный выбор зеленеет, неверный не ставится |
| Ошибиться нельзя — нет и кнопки «Готово» | Текст в поле засчитывается сам после паузы в наборе (1 с); `</p>` — как только набран верно |
| У задания один однозначный ответ. Задания «на вкус» — только как мнение без проверки | «Режь, где меняется тема» заменено на «Разложи по абзацам»: предложение однозначно про правила или про время |
| Открытое задание — только с ясной целью и видимым «готово» | Песочница стала мини-заданием «Новый раздел» из 4 шагов со счётчиком «2/4» |
| Подсказка встаёт на место строки задания, а не отдельной плашкой: экран не растёт | `ask` с классом `ask-hint`: «Посмотри на план: «…» стоит на третьей ступеньке» |
| Неверная кнопка гаснет, после двух промахов светится верная | «Какая цифра?»: выбор сужается, застрять нельзя |
| Не скучно: история, чередование механик, видимый прогресс, быстрая реакция | Счётчики шагов, живые страницы, Коди комментирует каждое действие |

## Контракт с платформой

Контракт — это то, что платформа проверяет у каждого урока. Нарушение любого пункта ломает урок на проде, даже если он красиво выглядит.

| Пункт | Правило |
| --- | --- |
| Пропсы | `{ studentName, lang, ttsApiBase, voiceGender, onFinished }`. Дев-пропсы `startAt` и `onExit` платформа не передаёт. |
| `lang` | `'uz' \| 'ru' \| 'en'`. Неизвестное значение — откат на `'ru'`. Переключателя языка внутри урока нет. |
| `studentName` | Только в видимом тексте («Автор: …»). В озвучку не попадает: сервер кеширует озвучку по тексту, имя ломает кеш. |
| `voiceGender` | `'f' \| 'm'` от LMS; без него — женский. Корень урока первым делом зовёт `setLmsVoice(voiceGender)`. |
| Импорты | Только `react`. Ни `@lesson/runtime`, ни framer-motion, ни lucide. |
| Озвучка | Движок канона: `GET {ttsApiBase}/api/tts?text=<маркер + реплика>&g=f\|m&lesson_id=…&lesson_name=…`. `lesson_id` и `lesson_name` (на языке урока) берутся из `META`. Без `ttsApiBase` или если сервис не отдал звук — голос браузера; без него — реплика печатается. |
| Маркер языка | Ставит движок: `[O'zbekcha tallaffuz] `, `[Русское произношение] `, `[English pronunciation] `. В тексте реплик маркер не пишется. |
| Текст реплики | Полные предложения, до ~25 с (60–80 слов). Символов `% / ² + = ×` нет — только слова. Теги в угловых скобках проговариваются словами автоматически (`SpokenTags`). |
| Медиа | Арт рисуется SVG прямо в коде. Внешних картинок и шрифтов урок не грузит. |
| Прогресс | Живёт в памяти (`store`) до конца урока. localStorage не используется. |
| `onFinished` | Вызывается РОВНО один раз, с защитой через `ref`. Повторный вызов запрещён даже после «Пройти ещё раз». |

Payload без оценки. Поля-заглушки нужны раннеру платформы, поэтому они есть всегда:

```js
{
  lessonId, lessonTitle,          // lessonTitle — на языке урока
  module, student, lang,
  durationSec,
  answers,                        // журнал log(): один ряд на экран
  totalQuestions: null, correctAnswers: null, scorePercent: null,
  finalScore: 0, finalTotal: 0, passed: null,
  ...extraPayload(store)          // артефакт урока: страница ученика { type: 'html-page', title, ... }
}
```

## Архитектура файла

Файл делится пометкой «УРОК» на две части. Сверху канон, одинаковый во всех уроках курса и копируемый дословно. Снизу всё, что принадлежит только этому уроку. Порядок слоёв фиксирован.

**Канон (не править внутри урока)** — собирается `node tools/build-canon.mjs`, совпадение проверяет `node tools/check-canon.mjs`:

1. Дизайн-токены `T`.
2. Персонаж — палитра `BOT`, система движения (`POSE_SET`), рисунок Коди `RobotSVG`, слой лица `KODI_CSS`.
3. Язык — `LANGS`, `usePick()`; `pick({ uz, ru, en })` возвращает строку нужного языка.
4. Текст для озвучки — `markLang`, `buildTtsUrl`, `estimateMs`.
5. Движок озвучки `useAudioEngine` — запросы к сервису, прогрев, резервный голос браузера, флаги `playing` и `failed`.
6. Звуки — `sfx()` через WebAudio без файлов.
7. Журнал и стор — `buildPayload`, `useStore`, `useLog`.
8. Речь героя — `PersonaBubble`.
9. Голос экрана — `useVoice` (очередь реплик плюс реакции `sayNow`) и `useNarration` (рассказ, ведущий анимацию).
10. Гейты — `useCanAnswer`, `useAdvanceGate` с предохранителями; подсказка при бездействии `useIdleLed`, `useIdleCoach`.
11. Похвала и подбадривание — `nextPraiseL`, `nextEncourageL`, `joinL`.
12. Каркас экрана — `Stage`, `PauseBtn`, `HintChromeBtn`, `VoiceDot`, `BackBtn`, `NextBtn`.
13. Мелкие компоненты — `Icon`, `Led`, `FitLine`.
14. Библиотека механик (раздел «Механики»).
15. Типовые экраны — `MissionScreen`, `WhyScreen`, `AchievementScreen`, `ByeScreen`.
16. Корень — `useLessonRoot` и `Shell`.
17. Базовые стили — `CSS_BASE`, `CANON_UI_CSS`, `CANON_SCREEN_CSS`.

**Пометка:** `// ==============================  У Р О К  ==` и шапка урока: курс, модуль, номер, название, возраст, замысел, дуга экранов, особые правила.

**Урок:**

18. `META` — `lessonId`, `module`, `lessonTitle` на трёх языках.
19. `C` — все тексты урока, сгруппированные по id экрана; `UI` — подписи интерфейса урока.
20. Общие помощники курса HTML — `Tag`, код (`Src` / `CodeLines`), `MiniBrowser`, `Page`, `InlineInput`, `SpokenTags` и др. (раздел «Механики курса HTML»).
21. `SPOKEN` и `NOT_SPOKEN_IN` — какие ключи `C` являются репликами: по ним урок заранее прогревает озвучку экрана и следующего.
22. Экраны `S1…Sn` и мини-механики, нужные только этому уроку.
23. `SCREENS` — реестр экранов и `SCREEN_RESET`.
24. Корневой компонент — `export default`.
25. `LESSON_CSS` — стили урока.

Все тексты живут только в `C` и `UI`. Компонент экрана не содержит ни одной строки на естественном языке.

## Корень урока и реестр экранов

Корень ничего не знает о содержании урока. Он берёт реестр `SCREENS`, отдаёт текущий экран в `Shell` и передаёт экрану один объект `p`.

```jsx
const SCREENS = [
  { id: 's1',  code: 'HOOK',     Comp: S1 },
  { id: 's6',  code: 'SHOW',     Comp: S6 },
  { id: 's7',  code: 'LEVEL-2',  Comp: S7 },
  { id: 's7b', code: 'LEVEL-2B', Comp: S7b },   // экран, вставленный позже, получает суффикс
  // ...
];

// Что стирает «Повторить» на каждом экране. Работу ребёнка (свою страницу) не трогаем.
const SCREEN_RESET = { s1: ['s1'], s7b: ['s7b'] };

export default function HtmlLessonN({ studentName, lang, ttsApiBase, voiceGender, onFinished, startAt, onExit }) {
  setLmsVoice(voiceGender);
  const R = useLessonRoot({
    meta: META, total: SCREENS.length, studentName, lang, ttsApiBase, onFinished, startAt, onExit,
    extraPayload: (store) => ({ artifact: makeArtifact(store) })
  });
  // ... прогрев озвучки текущего и следующего экрана по SPOKEN, затем Shell
}
```

`useLessonRoot` держит всё состояние урока:

- `i` — номер экрана; `next`, `prev`, `go(n)` — навигация.
- `store.get/set(key)` — память экранов. Вернувшись «Назад», экран показывает уже решённое состояние, а не играет заново.
- `log(row)` — журнал ответов, один ряд на `screenId`. Пишется только там, где ребёнок действительно отвечал.
- `finish()` — собирает payload и зовёт `onFinished` один раз.
- «Повторить» пересобирает экран с первой реплики.

## Анатомия экрана

Каждый экран обёрнут в `Stage` и состоит из четырёх полос сверху вниз. Их порядок и место кнопок одинаковы на всех экранах.

1. **Шапка.** Полоса прогресса, надзаголовок (`eyebrow`, на телефоне скрыт), служебные кнопки в неизменном порядке, прижатые вправо: выход (только в витрине), кружок с головой Коди (только на телефоне), подсказка, пауза, счётчик `05/19`.
2. **Герой.** `PersonaBubble`: кружок с головой Коди; пока он говорит, вокруг кружка бегут волны голоса. Без голоса печатается облако с репликой. На телефоне Коди — в шапке у подсказки, а под шапкой только облако (без звука); на планшете и компьютере Коди стоит справа снизу над нижней панелью, облако — строкой над кнопками. Пока Коди говорит, экран получает класс `is-speaking`, а кнопки ответов выглядят «отдыхающими», а не сломанными.
3. **Содержание.** Строка задания (`.ask`) и механика. Высота считается от окна, прокрутки страницы нет.
4. **Навигация.** `BackBtn` слева, `NextBtn` справа.

Пропсы `Stage`, которые нужно знать:

| Проп | Что делает |
| --- | --- |
| `hint` | Текст, который вслух повторит лампочка «Подсказка». Без знака «+» и прочих символов. |
| `done` | Условие «экран отработал» — от него пауза превращается в «Повторить». |
| `voiceTop` | Тесный экран на телефоне: на узком экране (до 719 px) и на телефоне лёжа строка героя скрыта (голос звучит и ведёт экран), Коди — маленьким кружком в шапке. На ноутбуке и планшете Коди стоит как обычно — экран обязан влезать вместе с ним (проверять 1280×720). Ставится, когда на 360×640 у содержания меньше ~60 px запаса или оно растёт по ходу задания. |
| `hideSpeaker` | Герой в шапке не нужен, потому что он крупный в самой сцене (прощание). |

Правила, которые держит каждый экран:

- **Сначала дослушать.** Кнопки ответа не живые, пока Коди объясняет задание (`useCanAnswer`). Предохранитель 9 с перезапускается на каждой реплике.
- **«Дальше» после разбора.** Открывается, когда задание решено и разбор «почему так» договорён (`useAdvanceGate`). Предохранитель 20 с.
- **Строка задания не прыгает.** Появилась после вступления — дальше не исчезает, пока Коди отвечает; подсказка встаёт на её место.
- **Подсказка при бездействии (канон, во всех экранах с навигацией).** 8 с без касаний, пока Коди молчит: подпрыгивает открытая «Дальше», а если она закрыта — качается лампочка и загораются светодиоды на месте действия. 20 с — к той же кнопке приходит рука-указатель. Светодиоды на месте действия экран ставит сам через `useIdleLed` (7 с).
- **Память при возврате.** Экран читает `store` при монтировании и показывает решённое состояние.

## Дизайн-система курса HTML

Тёплый светлый фон, белые карточки, оранжевый интерфейс. Оранжевый вернулся в интерфейс курса HTML по решению заказчика (12.10.2026); красного цвета ошибки по-прежнему нет.

| Токен | Цвет | Где используется |
| --- | --- | --- |
| `bg` | `#F6F4EF` | Фон урока |
| `paper` | `#FFFFFF` | Карточки, кнопки шапки |
| `ink` / `ink2` / `ink3` | `#0E0E10` / `#5A5A60` / `#A7A6A2` | Основной, вторичный, приглушённый текст |
| `ui` / `uiSoft` / `uiDk` | `#FF4F28` / `#FFE8E1` / `#B94127` | Кнопки, прогресс, рамки выбора, кружок голоса |
| `success` / `successSoft` | `#1F7A4D` / `#E3F0E8` | Решённое: зелёная строка, галочка |
| `hint` / `hintSoft` | `#8D5E00` / `#FFF6E0` | Подсказка — отдельный канал, не «ошибка»; лампочка, плашка подсказки |
| `shadowBase` | `58, 53, 48` | Все тени: `rgba(58,53,48,a)` |

**Цвета тегов** (`TAGC`, одной светлоты): `html` `#586A83`, `head` `#6F57AB`, `title` `#9F4471`, `body` `#1171A0`, заголовки `#4F46C8`, `p` `#227882`, `b`/`i` `#97368A`. Тег всегда того же цвета в коде, на плане и в подсказке. Оранжевым, жёлтым и зелёным теги не красятся.

**Шрифты.** Manrope — текст и кнопки. JetBrains Mono — код, теги, счётчики. Страница в мини-браузере — Times New Roman, как HTML без CSS.

**Размеры — только через `clamp`, `vw` и `dvh`.** Урок занимает ровно высоту окна (`height: var(--vvh, 100dvh)`). Открытая клавиатура телефона даёт класс `is-kbd` и `--vvh` около 330px: всё, что не нужно для ввода, на это время прячется, но не задание и не образец.

**Мини-браузер** выглядит как Chrome в Windows: вкладка от левого края с фавиконом и крестиком, кнопка «+», справа кнопки окна «— ▢ ✕».

**Движение.** Блок `@media (prefers-reduced-motion: reduce)` обязателен. Пауза замораживает анимации. Никакой анимации появления экрана с `opacity: 0`. Все циклы медленнее 3 Гц.

**Иконки** — только SVG из набора `Icon`. Эмодзи запрещены.

## Герой — Коди

Коди — робот Junior IT Akademiya, единственный герой курса. Он ведёт урок, задаёт вопросы и разбирает ответы.

**Облик (рисунок v4, заказчик 17.10.2026): только голова в кружке.** Широкий приземистый кремовый шлем из матового винила; медная рамка экрана почти во весь шлем; на тёмном экране круглые светящиеся глаза-точки и тонкий рот-дуга; по бокам медные уши-вставки вровень с силуэтом. Голова стоит в белом кружке и занимает 90% его диаметра. Тела, рук и ног нет — место отдано контенту.

**Где стоит.** Телефон — в шапке, рядом с кнопкой подсказки (кнопки шапки прижаты вправо); отдельной строки героя нет, без звука под шапкой — только облако реплики. Планшет и компьютер (от 760 px) — справа снизу, чуть выше нижней панели, у самого правого края экрана; облако реплики (без звука) — строкой над кнопками слева от Коди. На экранах уже 1200 px у содержания снизу запас на высоту кружка.

**Волны голоса.** Пока Коди говорит, вокруг кружка бегут три полупрозрачных оранжевых контура — цвет интерфейса курса, как у Алисы и Siri. Их форма, размах и вращение меняются случайно, «по слогам», — рисунок всегда хаотичный. Замолчал — волны уходят за кружок. При «меньше движения» волн нет, речь показывает тонкое оранжевое кольцо.

**Не стоит без дела.** Ученик ничего не трогает 5 с, а Коди молчит — лицо само меняет выражение: оглядывается, улыбается, задумывается, удивляется, смущается (держит 2–3 с, потом пауза). Через 30 с без касаний задрёмывает, касание его будит. Голоса при этом нет.

**Позы** называются по ситуации урока, а не по эмоции. Эмоцию показывает только лицо: форма и размер глаз, взгляд, веки, рот, румянец и цвет свечения экрана. Голова в кружке не качается и не прыгает.

| Поза | Когда |
| --- | --- |
| `explain` | Спокойный рассказ, по умолчанию |
| `point` | «Смотри сюда» — взгляд в сторону, глаза шире |
| `rule` | Разбор «почему так» |
| `think` | Ребёнок ошибся: «давай посмотрим вместе» |
| `wonder` | «Ого!» — единственное удивление в сцене |
| `smile` / `cheer` / `celebrate` | Получилось / похвала / финал |
| `hello` / `bye` | Приветствие / прощание |
| `curious`, `shy` | Любопытство, смущение |
| `sleep` | Выключен — один раз за курс, до первого щелчка |
| `sorry` | Ошибся сам Коди. Никогда — в ответ на действие ребёнка |

Цвет экрана меняется только вместе с состоянием: бирюзовый — спокойно, жёлтый — радость, голубой — «ого», серый — выключен.

**Размер.** Диаметр кружка — `--av`: телефон ~54–70 px, планшет и компьютер 84–128 px. Волны выходят за кружок на четверть его диаметра.

**Где Коди нет.** На тесных экранах урока на телефоне — `voiceTop` (Коди маленьким кружком в шапке). На ноутбуке строка героя в уроке всегда на месте. В практике Коди не рисуется вовсе — ни на телефоне, ни на ноутбуке.

## Механики

Механики канона не знают ничего о конкретном уроке. Урок выбирает механику и отдаёт ей данные из `C`.

| Механика канона | Что делает ребёнок | Когда брать |
| --- | --- | --- |
| `HintLadder` | Выбирает один ответ из 3–4 карточек | Главная проверка понимания |
| `Guess` | Выбирает вариант без оценки | «Как думаешь?» |
| `Hotspots` | Находит элементы на картинке | «Найди кнопку» |
| `PairMatch` | Соединяет пары тапами | Название ↔ назначение |
| `YesNo` | Отвечает «да/нет» на серию утверждений | Быстрая проверка фактов |
| `Reorder` | Ставит шаги по порядку | Последовательности |
| `DropZones` | Раскладывает предметы по гнёздам | Сборка |
| `TapSort` | Раскладывает по корзинам тапами | Классификация |
| `OddOneOut` | Находит лишнее | Понятие и его границы |
| `Quiz` | Серия вопросов с разбором | Итоговая проверка |
| `FlashCards`, `MemoryPairs` | Переворачивает карточки, ищет пары | Новые слова, закрепление |
| `Compare` | Двигает шторку «было — стало» | До и после |
| `Reflection` | Выбирает ответ без правильного варианта | Рефлексия |
| `CoachMark` | Нажимает подсвеченную настоящую кнопку | Тур по кнопкам, только урок 1 |

**Общий контракт механики:** `stored` (решённое состояние), `canAnswer` (пока `false` — касания не работают), `onSay(text, pose)` (реплики героя), `onSolved`/`onResolved` (итог `{ correct, firstTry, attempts }` — экран пишет его в `store` и `log`).

**Механики курса HTML** — из уроков 1 и 2, копируются из эталона:

| Механика | Что делает ребёнок | Правила |
| --- | --- | --- |
| Мини-браузер + код | Видит код и страницу рядом | Страница обновляется на каждое изменение кода. Код ученика никогда не исполняется — из него берутся название и текст |
| Лесенка (`Stairs`) | Читает уровни заголовков по ступенькам | Ступенька = уровень; тег можно скрыть («h?»), строки можно нажимать |
| Выбор тега с мгновенной проверкой | Нажимает строку, потом h1/h2/p | Верный ставится и зеленеет; неверный не ставится, Коди объясняет; после двух промахов светится верная кнопка |
| Набор тега кнопками (`KeyRow`) | Набирает `</p>` кнопками `< / p >` | Ровно набранный тег засчитывается сам; «Проверить» — для разбора неверного |
| Поле в коде (`InlineInput`) | Пишет свой текст между готовыми тегами | Засчитывается после паузы в наборе (1 с) при наличии букв; теги в поле не нужны |
| Выделение слов (`WordLine`) | Нажимает слово, потом `b` или `i` | Одна кнопка на шаге, если нужен один тег |
| Раскладка по коробкам | Нажимает предложение, потом абзац под заголовком | Ответ однозначен по смыслу; страница рядом собирается вживую |
| Пошаговая сборка | Делает страницу по шагам «N/M» | Один шаг — одно действие; кнопка «+ h2» появляется только на своём шаге |
| Предложения-кнопки | Находит предложение в тексте | Каждое предложение — плашка с подчёркиванием, соседние чередуют оттенок |

**Лесенка подсказок** для проверок: направление → сужение → почти ответ; после верного ответа — «почему так» (`why`). В практике подсказка приходит сама после второй неудачной проверки подряд, вместе с разбором «что не так».

## Педагогическая дуга урока

Дуга: крючок, миссия, показ, практика с нарастающей сложностью, проверка, своя работа, итог. Коды экранов в реестре берутся из этого списка.

| Код | Экран | Что происходит |
| --- | --- | --- |
| `HELLO`, `TOUR-n` | Знакомство и тур | Только в первом уроке курса |
| `HOOK` | Крючок | Проблема героя, которую он не решит без ребёнка (стена текста, страница без названия) |
| `MISSION` | Миссия | Шаги урока |
| `SHOW` | Показ | Новое на одном примере, с нажатиями по ходу рассказа |
| `LEVEL-n` | Уровни | Задания с нарастающей сложностью; механики чередуются |
| `CHECK-n` | Проверка | Перенос на новую ситуацию («детектив», задача без образца) |
| `SANDBOX` | Мини-задание | Открытое действие с ясной целью и шагами |
| `RESULT` | Своя работа | Ребёнок делает свою страницу — артефакт урока |
| `ACHIEVEMENT` | Достижение | Своя страница и её код, сохранение |
| `PREVIEW` | Прощание | Мостик к следующему уроку, здесь вызывается `p.finish` |

Правила дуги:

- **Число экранов не ограничено.** Сложная тема раскладывается на «показать → повторить → сделать самому» отдельными экранами.
- **Жанры чередуются.** Двух одинаковых механик подряд нет.
- **Сложность растёт лесенкой.**
- **Проверка понимания, а не памяти.** Задание, которое быстрее угадать перебором, чем понять, запрещено.
- **Крючок через предмет.** Понятие появляется из ситуации героя, а не из определения.

## Практика к уроку

Практика — отдельный файл `lessons/<курс>/<NN>p-<slug>.jsx` после своего урока. Ученик сам пишет код по материалу урока.

- **Коди не рисуется.** Каркас практики (`PStage` в эталоне) кладёт в шапку кружок голоса и лампочку; на телефоне слева голос и лампочка, по центру мини-карта (предыдущий, текущий, следующий объект), справа пауза и счётчик. Текст реплик не печатается — задание всегда написано строкой задания.
- **Одна кнопка подсказки** — лампочка в шапке. Своей кнопки подсказки у задания нет.
- **Проверка — по кнопке «Проверить»** там, где ребёнок пишет теги. Первая неудача — только «что не так»; со второй подряд к этому сразу добавляется следующая ступень подсказки.
- **Образец и задание видны всегда**, в том числе при открытой клавиатуре.
- **Большой редактор** там, где документ пишется с нуля: поле занимает всё свободное место.

## Тон, обращение, языки

Коди говорит с ребёнком как старший друг: коротко, тепло, по делу. Ошибка — повод разобраться, а не оценка.

- **Обращение.** RU — «ты», EN — «you», UZ — «Siz». В RU без рода: «Всё на месте», а не «Ты сам написал».
- **Слова под запретом.** «Неправильно», «ошибка», «ты не смог» — и на узбекском «xato», «noto‘g‘ri». Вместо них: «тег стоит не так», «Здесь всё в порядке. Ищи дальше», ступень подсказки.
- **Похвала конкретная** — что именно получилось.
- **Подбадривание называет способ подумать**, а не ответ.
- **Термины на узбекском.** Вкладку браузера называем `title`; где во фразе уже есть `title` — «sahifa nomi». Слово «varaqcha» не используется.
- **Три языка равноправны.** Каждая строка — `L3(uz, ru, en)`.
- **Подписи кнопок и голос.** Строка с «+ h2» на экране пишется с неразрывным пробелом (`«+ h2»`), а для голоса лампочки у неё отдельное поле без плюса («нажми кнопку h2»).

## Запреты и ошибки, которые уже ломали уроки

Каждая строка ниже — реальная поломка. ИИ проверяет свой код по этому списку до сдачи.

| Чего не делать | Что случается | Как правильно |
| --- | --- | --- |
| Анимация появления экрана с `opacity: 0` | Белая страница навсегда, без ошибки в консоли | Экран меняется сразу; плавность только у элементов внутри |
| Объект `{ ru, uz }` прямо в JSX | React падает с ошибкой #31 | Любой видимый проп переводится через `pick()` |
| `onFinished` без защиты | Повторный вызов после «Пройти ещё раз» | Флаг в `ref` |
| Правка канона внутри урока | Уроки разъезжаются | `build-canon.mjs` → перенос во все уроки → `check-canon.mjs` |
| Переключатель «Код / Результат» в задании | Ребёнок не видит результат своего действия | Живое превью рядом с кодом |
| Чек-лист из пунктов-кружков рядом с заданием | Пункты принимают за переключатели | Одна цель на экран или счётчик шагов «N/M» |
| Подсказка отдельной плашкой под заданием | Экран растёт, задание уходит за край | Подсказка на месте строки задания (`ask-hint`) |
| Строка задания пропадает, пока говорит Коди | Экран прыгает на каждой реплике | Строка держится после вступления |
| Абстракция в задании («часть раздела») | Ребёнок не понимает, что нажимать | Называть вещь на экране |
| Задание «на вкус» с проверкой | Верного ответа нет — ребёнок застревает | Однозначный ответ или мнение без проверки |
| «Проверить» / «Готово», где ошибиться нельзя | Лишний шаг, ребёнок ждёт | Автозасчёт |
| Слово «ошибка» / «xato» в реплике | Нарушение тона курса | «Тег стоит не так» |
| Знак «+» и символы в тексте для голоса | Сервис читает «плюс» или спотыкается | Отдельное поле для голоса, только слова |
| Текст реплик плашкой в шапке | Шапка раздувается, кружок голоса пропадает | В шапке только кружок голоса |
| Проценты в `transform-origin` у вложенной повёрнутой группы | Деталь вращается не вокруг своей оси, а вокруг края (так махала рука Коди v3) | Точка вращения — координатами шарнира |
| Склейка файла поиском по строке без якоря | Метка нашлась в комментарии — часть файла задвоилась | Искать уникальный якорь (с переносом строки) и проверять, что он один |
| Эмодзи, красный цвет ошибки, таймеры, очки | Нарушение правил курса | SVG-иконки, канал подсказки |
| Имя ученика в озвучке | Кеш озвучки ломается для каждого ребёнка | Имя только в видимом тексте |

## Проверка в просмотрщике

1. Запуск: `npm run dev` (порт 5173).
2. Урок: `http://localhost:5173/?lesson=<курс>%2F%23<n>&voice=fast`. Отдельный экран: `/player.html?file=<курс>/<файл без .jsx>&lang=ru&voice=fast&start=<N>`.
3. Журнал: без ошибок, у реплик есть маркер языка, `onFinished` вызван один раз. Голос стартует после первого касания внутри урока.
4. Каждый экран на трёх языках на 360×640, 375×740 и 1440×900: нет переполнения `.stage-content`. Проверяются и состояния по ходу задания — подсказка, все шаги, готовая страница, открытая клавиатура (`is-kbd`, `--vvh: 330px`).
5. Пройти урок глазами ученика на телефоне: на каждом экране сразу ясно, что делать.

## Чек-лист приёмки

Урок сдаётся, только когда отмечены все пункты. ИИ проходит список сам и в ответе перечисляет пункты, которые не смог выполнить.

- [ ] Один JSX-файл, `export default`, импорт только `react`.
- [ ] Канон сверху совпадает с эталоном дословно (`check-canon.mjs`), урок ниже пометки «УРОК».
- [ ] Пропсы `{ studentName, lang, ttsApiBase, voiceGender, onFinished }`, откат языка на `ru`, `setLmsVoice(voiceGender)` в корне.
- [ ] Все тексты в `C` / `UI`, каждый на трёх языках; реплики перечислены в `SPOKEN`.
- [ ] В репликах нет имени ученика, символов `% / ² + = ×` и запретных слов на трёх языках.
- [ ] На каждом экране одно действие, задание называет конкретную вещь, ответ однозначен.
- [ ] Результат действия виден сразу; нет скрытых переключателей и лишних «Проверить» / «Готово».
- [ ] Подсказка встаёт на место строки задания; застрять нельзя (сужение выбора, подсказка при бездействии).
- [ ] Ответы заперты, пока Коди говорит; «Дальше» открывается после разбора; предохранители работают.
- [ ] «Назад» возвращает решённое состояние, «Повторить» перезапускает экран.
- [ ] Нет переполнения на 360×640, 375×740, 1280×720 и 1440×900 во всех состояниях экрана; на тесных экранах — `voiceTop` (действует только на телефоне, на ноутбуке экран влезает с Коди).
- [ ] Нет эмодзи, красного цвета ошибки, таймеров и очков.
- [ ] Есть блок `prefers-reduced-motion`, пауза замораживает анимации.
- [ ] `onFinished` вызывается ровно один раз, payload по схеме.
- [ ] `log()` пишется только на экранах, где ребёнок отвечал.

## Шаблон промпта на новый урок

ИИ заполняет этот шаблон для каждой темы и показывает его на утверждение. Код пишется только после утверждённого сценария.

```markdown
# Урок N · «Название» · курс / модуль

## Паспорт
- lessonId: html-<NN>-<slug>
- module: <id модуля>
- Возраст: из плана курса
- Цель урока одной фразой: ребёнок сможет …
- Новое понятие: …
- Крючок: проблема Коди, которую он не решит без ребёнка
- Изюминка (главная механика): …
- Артефакт урока (уходит в payload): …

## Экраны (столько, сколько нужно для понимания)
| # | id | Код | Механика | Одно действие ребёнка | Что видно сразу | voiceTop | Ключ store | log type |
|---|----|-----|----------|-----------------------|-----------------|----------|-----------|----------|
| 1 | s1 | HOOK | предложения-кнопки | нажимает предложение с ответом | плашка зеленеет | нет | s1 | find |
| … |

Для каждой новой темы — тройка экранов: показать → повторить → сделать самому.

## Тексты по экранам
Для каждого экрана, каждая строка — L3(uz, ru, en):
- eyebrow:
- say: реплики Коди по порядку, с позой
- ask: задание одной фразой, называет конкретную вещь
- hint (для голоса лампочки, если в ask есть символы):
- options / ответ: однозначный
- hints: 3 ступени — направление / сужение / почти ответ
- why: разбор «почему так»
- praise: конкретная похвала

## Арт
- SVG-сцены и предметы, их состояния

## Особые правила урока
- Что отличается от канона и почему (если ничего — «нет»)

## Проверка по чек-листу
- Пункты, которые сценарий пока не закрывает
```

После утверждения ИИ получает команду «пиши код» и выдаёт файл: канон дословно, пометка «УРОК», затем слои 18–25 из раздела «Архитектура файла». В конце ответа — короткий отчёт по чек-листу приёмки.
