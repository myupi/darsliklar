# Бриф для ИИ: структура, дизайн и функции детского урока

Oct 12, 2026 · @Zarin

## Как пользоваться брифом

Этот документ целиком вставляется в другой ИИ первым сообщением. После него ИИ получает тему урока и пишет по этой структуре сначала сценарий, потом JSX-файл.

За основу взят канон Курса 0. Это форк инфра-блока Кибербеза (INFRA v1) с единым реестром экранов, библиотекой механик и лесенкой подсказок. Озвучка при этом идёт через `@lesson/runtime`, как в Кибербезе, а не через собственный движок Курса 0.

Что ИИ должен выдавать на каждый новый урок:

1. Сценарий по шаблону из последнего раздела: экраны, механики, все реплики на трёх языках.
2. После утверждения сценария — один JSX-файл: канон дословно сверху, урок ниже пометки «УРОК».

Правило для ИИ: если тема урока требует нарушить правило из этого брифа, он спрашивает, а не придумывает обход. Канон внутри урока не правится никогда: именно так уроки 1–3 Кибербеза разъехались.

## Суть продукта

Урок — интерактивная история на 11–14 экранов для детей 8–10 лет. Один урок — один самодостаточный JSX-файл с React-компонентом по умолчанию. Платформа монтирует его, передаёт имя и язык и ждёт один вызов `onFinished`.

Урок ведётся голосом. Герой проговаривает каждую реплику, ребёнок слушает и отвечает касаниями. 90% детей проходят урок с телефона, поэтому телефон — основной экран, а не адаптация.

Шесть принципов, на которых держится всё остальное:

- **Времени нет.** Ни таймеров, ни «успей за 10 секунд».
- **Очков нет.** Ошибка ничего не отнимает, попытки не ограничены.
- **Красного нет.** Ошибка показывается движением карточки и подсказкой, а не цветом.
- **Телефон главнее.** У любой механики есть путь «ткнул — ткнул», перетаскивание никогда не единственный способ.
- **Говорит герой.** Механика не показывает текст сама, а отдаёт реплику герою.
- **Урок не запирает ребёнка.** Каждая блокировка имеет предохранитель по времени.

## Контракт с платформой

Контракт — это то, что платформа проверяет у каждого урока. Нарушение любого пункта ломает урок на проде, даже если он красиво выглядит.

| Пункт | Правило |
| --- | --- |
| Пропсы | `{ studentName, lang, onFinished }`. Других в проде нет. Дев-пропс `startAt` (открыть сразу на экране N) платформа не передаёт. |
| `lang` | `'uz' \| 'ru' \| 'en'`. Неизвестное значение — откат на `'ru'`. Переключателя языка внутри урока нет. |
| `studentName` | Только в видимом тексте. В озвучку не попадает: сервер кеширует TTS по тексту, имя ломает кеш. Пусто — обращение без имени. |
| Импорты | Только `react` и `@lesson/runtime` (`useAudio`, `useSfx`, `useAssets`). Ни framer-motion, ни lucide, ни других пакетов. |
| Озвучка | Только `useAudio().pushOneOff(текст, тегГолоса)`. Свой аудиодвижок и `speechSynthesis` запрещены. |
| Маркер языка | Каждая реплика начинается с маркера: ` [Русское произношение]  `, ` [O'zbekcha tallaffuz]  `, ` [English pronunciation]  `. |
| Медиа | Арт рисуется SVG прямо в коде. Растровые файлы — только через `useAssets().resolveUrl`. |
| Прогресс | Живёт в памяти (`store`) до конца урока. localStorage — только если ТЗ курса прямо требует возврата на тот же экран. |
| `onFinished` | Вызывается РОВНО один раз, с защитой через `ref`. Повторный вызов запрещён даже после «Пройти ещё раз». |
| После финиша | Урок рисует только фон. Своего экрана поздравления нет: поверх фона платформа показывает своё окно. |

Payload без оценки. Поля-заглушки нужны раннеру платформы, поэтому они есть всегда:

```js
{
  lessonId, lessonTitle,          // lessonTitle — на языке урока
  module, student, lang,
  durationSec,
  answers,                        // журнал log(): один ряд на экран
  totalQuestions: null, correctAnswers: null, scorePercent: null,
  finalScore: 0, finalTotal: 0, passed: null,
  ...extraPayload(store)          // артефакт урока: значок, выбор ребёнка
}
```

## Архитектура файла

Файл делится пометкой «УРОК» на две части. Сверху канон, одинаковый во всех уроках курса и копируемый дословно. Снизу всё, что принадлежит только этому уроку. Порядок слоёв фиксирован: ИИ не переставляет их и не смешивает.

**Шапка-комментарий.** Курс, модуль, номер и название урока, возраст, список пропсов, число экранов, особые правила урока.

**Канон (не править внутри урока):**

1. Дизайн-токены `T` — все цвета и тени.
2. Персонаж — цвета, позы, SVG-компонент героя.
3. Язык — `LANGS`, `LangCtx`, `usePick()`; `pick({ uz, ru, en })` возвращает строку нужного языка.
4. Текст для озвучки — `sleep`, `estimateMs` (длина паузы без голоса), `sanitizeForTts` (убирает разметку), `markLang` (маркер языка).
5. Озвучка — переходник на `@lesson/runtime`: `speak()` возвращает Promise, есть флаги `playing` и `failed`.
6. SFX — короткие звуки через WebAudio без файлов либо `useSfx()`.
7. Журнал и стор — `useAnswerLog`, `useScreenStore`, `buildPayload`.
8. Речь героя — `PersonaBubble`: сам озвучивает текст и сообщает, когда договорил.
9. Голос экрана — `useVoice`: очередь реплик экрана плюс реакции по ходу.
10. Гейты — `useCanAnswer`, `useAdvanceGate` с предохранителями.
11. Похвала и подбадривание — пулы конкретных фраз.
12. Каркас экрана — `Stage`, `PauseBtn`, `BackBtn`, `NextBtn`, `FitLine`.
13. Мелкие компоненты — `Icon` (набор SVG), `Note`, `Led`, `HintButton`.
14. Библиотека механик — `HintLadder`, `Hotspots`, `PairMatch` и другие (раздел «Библиотека механик»).
15. Типовые экраны — `MissionScreen`, `WhyScreen`, `AchievementScreen`, `ByeScreen`.
16. Корень — `useLessonRoot` и `Shell`.
17. `CSS_BASE` — базовые стили канона.

**Пометка:** `// ===== УРОК N · «Название» · модуль M =====` и абзац о замысле урока.

**Урок:**

18. `META` — `lessonId`, `module`, `lessonTitle` на трёх языках.
19. `C` — все тексты урока, сгруппированные по id экрана.
20. Арт урока — SVG-компоненты сцен и предметов.
21. Экраны `S1…Sn` и мини-механики, нужные только этому уроку.
22. `SCREENS` — реестр экранов и `SCREEN_RESET`.
23. Корневой компонент — `export default`.
24. `LESSON_CSS` — стили урока, дописываются к `CSS_BASE`.

Все тексты живут только в `C`. Компонент экрана не содержит ни одной строки на естественном языке.

## Корень урока и реестр экранов

Корень ничего не знает о содержании урока. Он берёт реестр `SCREENS`, отдаёт текущий экран в `Shell` и передаёт экрану один объект `p`. Всё состояние урока держит `useLessonRoot`.

```jsx
const SCREENS = [
  { id: 's1',  code: 'HOOK',    Comp: S1 },
  { id: 's2',  code: 'MISSION', Comp: S2 },
  { id: 's7',  code: 'CHECK-1', Comp: S7 },
  // ...
  { id: 's15', code: 'PREVIEW', Comp: S15 }
];

// Что стирает «Повторить» на каждом экране. Работу ребёнка (значок, выбор) не трогаем.
const SCREEN_RESET = { s1: ['s1'], s7: ['s7'] };

export default function LessonN({ studentName, lang, onFinished, startAt }) {
  const R = useLessonRoot({
    meta: META, total: SCREENS.length, studentName, lang, onFinished, startAt,
    extraPayload: (store) => ({ badge: 'k0-01-parts' })
  });
  const cur = SCREENS[R.i];
  const p = {
    screen: R.i, total: SCREENS.length,
    next: R.next, prev: R.i > 0 ? R.prev : null,
    finish: R.finish, name: R.displayName
  };
  return (
    <R.Shell css={LESSON_CSS}>
      {!R.done && <cur.Comp key={cur.id + ':' + R.runN} p={p} />}
    </R.Shell>
  );
}
```

`useLessonRoot` возвращает `{ i, lang, audio, store, log, next, prev, go, finish, done, displayName, Shell, runN }`:

- `i` — номер экрана; `next`, `prev`, `go(n)` — навигация.
- `store.get/set(key)` — память экранов. Вернувшись «Назад», экран показывает уже решённое состояние, а не играет заново.
- `log(row)` — журнал ответов, один ряд на `screenId`. Пишется только там, где ребёнок действительно отвечал.
- `finish()` — собирает payload и зовёт `onFinished` один раз; после него `done = true`.
- `runN` входит в `key` экрана: «Повторить» пересобирает экран с первой реплики.
- `Shell` — корневой `div.lesson-root` с провайдерами языка, озвучки, стора и журнала и со стилями `CSS_BASE + css`.

Один реестр вместо двух списков. Нельзя держать метаданные экранов в одном массиве, а JSX-компоненты в другом: они расходятся при первой правке.

## Анатомия экрана

Каждый экран обёрнут в `Stage` и состоит из четырёх полос сверху вниз. Их порядок и место кнопок одинаковы на всех экранах всех уроков: ребёнок не ищет кнопку заново.

1. **Шапка.** Полоса прогресса, надзаголовок (`eyebrow`) с точкой, справа служебные кнопки в неизменном порядке: выход, подсказка, пауза, счётчик `03/14` моноширинным шрифтом.
2. **Пузырь героя.** `PersonaBubble`: маленький герой и текст реплики. Пока герой говорит, экран получает класс `is-speaking`, а карточки выглядят «отдыхающими», а не сломанными.
3. **Содержание.** Вопрос (`.ask`) и механика задания. Высота считается от окна, прокрутки нет.
4. **Навигация.** `BackBtn` слева, `NextBtn` справа.

Типовой экран-проверка целиком:

```jsx
function S7({ p }) {
  const pick = usePick();
  const store = useStore();
  const log = useLog();
  const [rec, setRec] = useState(() => store.get('s7') || undefined);
  const [speaker, say, spoken, sayNow] = useVoice([{ text: C.s7.say, pose: 'think' }]);
  const canTap = useCanAnswer(spoken);          // пока герой говорит — ответы не живые
  const canGo  = useAdvanceGate(!!rec, spoken); // «Дальше» — после ответа И договорённого разбора

  return (
    <Stage hint={C.s7.ask} eyebrow={C.s7.eyebrow} screen={p.screen} total={p.total}
      speaker={speaker} done={canGo}
      nav={<><BackBtn onPrev={p.prev} /><NextBtn disabled={!canGo} onClick={p.next} /></>}>
      <p className="ask">{pick(C.s7.ask)}</p>
      <HintLadder options={opts} correct={2} hints={C.s7.hints} why={C.s7.why}
        stored={rec} canAnswer={canTap}
        onResolved={(r) => {
          const v = { done: true, ...r };
          store.set('s7', v); setRec(v);
          log({ screenId: 's7', type: 'check', correct: r.correct, firstTry: r.firstTry, attempts: r.attempts });
        }}
        onSay={(t, pose) => sayNow(t, pose)} />
    </Stage>
  );
}
```

Правила, которые держит каждый экран:

- **Сначала дослушать.** Кнопки ответа не живые, пока герой объясняет задание (`useCanAnswer`). Предохранитель 9 с перезапускается на каждой реплике.
- **«Дальше» после разбора.** Кнопка открывается, когда задание решено и разбор «почему так» договорён (`useAdvanceGate`). Предохранитель 20 с.
- **Память при возврате.** Экран читает `store` при монтировании и показывает решённое состояние.
- **Подсказка вслух.** Проп `hint` у `Stage` — текст, который повторит кнопка «Подсказка».
- **Повтор.** `PauseBtn` — одна кнопка с тремя ролями: пауза, продолжить, повторить экран с первой реплики. Пауза замораживает и голос, и CSS-анимации.

## Дизайн-система

Визуал общий для всей линейки: тёплый светлый фон, белые карточки, голубой интерфейс, оранжевый только в рисунках. Ребёнок переходит из курса в курс и не должен почувствовать, что попал в другой продукт.

| Токен | Цвет | Где используется |
| --- | --- | --- |
| `bg` | `#F6F4EF` | Фон урока |
| `paper` | `#FFFFFF` | Карточки, кнопки шапки |
| `ink` / `ink2` / `ink3` | `#0E0E10` / `#5A5A60` / `#A7A6A2` | Основной, вторичный, приглушённый текст |
| `ui` / `uiSoft` / `uiDk` | `#1E88E5` / `#E3F2FD` / `#1565C0` | Всё интерактивное: кнопки, прогресс, рамки выбора, рубашки карточек |
| `accent` / `accentSoft` / `accentDk` | `#FF4F28` / `#FFE8E1` / `#D63B16` | Только рисунки и персонажи, не интерфейс |
| `success` / `successSoft` | `#1F7A4D` / `#E3F0E8` | Решённое задание |
| `hint` / `hintSoft` | `#C08A12` / `#FFF6E0` | Подсказка — отдельный канал, не «ошибка» |
| `wrong` / `wrongSoft` | `#E0543F` / `#FFE3DF` | Только в рисунках про опасность, никогда в ответ ребёнку |
| `shadowBase` | `58, 53, 48` | Все тени: `rgba(58,53,48,a)` |

Оранжевый ушёл из интерфейса по решению заказчика: красно-оранжевая кнопка читалась детьми как ошибка.

**Шрифты.** Manrope — основной текст и кнопки. Source Serif 4 — крупные заголовки, `clamp(19px, 3.4vw, 27px)`. JetBrains Mono — счётчик экранов и служебные цифры. У каждого шрифта системный запасной стек.

**Размеры — только через `clamp`, `vw` и `dvh`.** Урок занимает ровно высоту окна (`height: var(--vvh, 100dvh); overflow: hidden`) и не прокручивается. Переменные корня:

- `--pad: clamp(14px, 3.6vw, 48px)` — боковые поля;
- `--limit: 960px` (1060px от 1440px ширины) — ширина колонки;
- `--gap-stack: clamp(10px, 1.6dvh, 18px)` — шаг между блоками;
- `--av: clamp(66px, min(22vw, 13dvh), 138px)` — ширина героя, высота не задаётся;
- `--ctl: clamp(36px, 5.4vw, 42px)` — единый размер круглых служебных кнопок.

Карточки — радиус 16px, белый фон, мягкая двухслойная тень. Текст, который может не влезть, оборачивается в `FitLine` (уменьшает кегль от 15 до 11px).

**Движение.** У героя каждое состояние — это поза, такт и тайминг. Поза меняется через `transition`, такт — `@keyframes` на вложенной группе, чтобы они не затирали друг друга. Радость — 280 мс с перелётом, вторичный слой (руки, голова) отстаёт на 90–140 мс.

- Блок `@media (prefers-reduced-motion: reduce)` обязателен в каждом уроке.
- Класс `.is-paused` ставит все анимации на паузу.
- Никакой анимации появления экрана, стартующей с `opacity: 0`: если она не доиграет на слабом телефоне, ребёнок останется перед белым экраном.

**Иконки** — только SVG из набора `Icon` по имени. Эмодзи запрещены: они по-разному выглядят на Windows, Android и iOS.

## Персонажи и озвучка

У курса один постоянный герой или пара героев на все уроки. Герой ведёт урок, задаёт вопросы и разбирает ответы; ребёнок никогда не остаётся наедине с голым заданием.

**Две проверенные схемы:**

- **Один герой** (Курс 0, робот Бип). Ошибок героя нет, поэтому на неверный ответ он показывает позу «давай посмотрим вместе», а не грусть.
- **Пара** (Кибербез, Симка и Нолик). Наставница слева, голос женский; торопыга справа, голос мужской. Ошибается торопыга, ребёнок его выручает. Наставница никогда не стыдит.

**Как рисовать героя.** Лучше всего — SVG прямо в коде: урок остаётся автономным, поза меняется параметром, цвета берутся из `T`. Позы называются по ситуации урока, а не по эмоции: `explain`, `point`, `think`, `glad`, `wow`. Злость и страх в сторону ребёнка запрещены. Грусть допустима, только когда ошибся сам герой.

**Как устроена реплика.**

- Текст — всегда объект `{ uz, ru, en }` из `C`, переводится внутри компонента через `pick()`.
- В очередь `useVoice` уходит `{ text, pose }`. Следующая реплика начинается, когда предыдущая договорена.
- Перед отправкой текст чистится `sanitizeForTts` (кавычки, стрелки, тире, `**`) и получает маркер языка.
- Для двух голосов тег голоса идёт вторым аргументом `pushOneOff`: `kids-f` для женского, `kids-m` для мужского.

**Когда голоса нет.** Платформа не сообщает конец реплики, есть только флаг `isPlaying`. Переходник выводит конец сам:

- `isPlaying` поднялся и упал — реплика договорена;
- не поднялся за 2,5 с — голоса нет: ставится `failed`, экран обязан показать текст реплики, пауза держится по `estimateMs` (75 мс на символ, от 1,8 до 14 с);
- в любом случае ожидание закрывается через `estimateMs + 8000` мс, чтобы «Дальше» не осталась серой навсегда.

**Тумблера звука нет.** Урок ведётся голосом, поэтому вместо выключения звука есть пауза. Если ТЗ курса всё же требует кнопку звука, при выключенном звуке все реплики печатаются текстом.

## Библиотека механик

Механики лежат в каноне и не знают ничего о конкретном уроке. Урок выбирает механику и отдаёт ей данные из `C`. Новая механика пишется только тогда, когда ни одна из этих не подходит, и сразу по общему контракту.

| Механика | Что делает ребёнок | Когда брать |
| --- | --- | --- |
| `HintLadder` | Выбирает один ответ из 3–4 карточек | Главная проверка понимания |
| `Guess` | Выбирает вариант без оценки | Любопытство, «как думаешь?» |
| `Hotspots` | Находит элементы на картинке | «Найди кнопку на панели» |
| `PairMatch` | Соединяет пары тапами | Название ↔ назначение |
| `YesNo` | Отвечает «да/нет» на серию утверждений | Быстрая проверка фактов |
| `Reorder` | Ставит шаги в правильный порядок | Алгоритмы, последовательности |
| `DropZones` | Раскладывает предметы по гнёздам | Сборка, «что куда встаёт» |
| `TapSort` | Раскладывает по корзинам тапами | Классификация |
| `OddOneOut` | Находит лишнее в нескольких раундах | Понятие и его границы |
| `Quiz` | Отвечает на серию вопросов с разбором | Итоговая проверка |
| `FlashCards` | Переворачивает карточки | Знакомство с новыми словами |
| `MemoryPairs` | Играет в «найди пару» | Закрепление |
| `DualPath` | Смотрит один процесс на компьютере и телефоне | Сравнение устройств |
| `Compare` | Двигает шторку «было — стало» | До и после действия |
| `Reflection` | Выбирает ответ без правильного варианта | Рефлексия в конце |
| `Glance` | Сам запускает показ на секунду | Внимание, без давления временем |
| `CoachMark` | Нажимает подсвеченную настоящую кнопку | Тур по интерфейсу, только урок 1 |

**Общий контракт механики.** Одинаковый набор пропсов позволяет экрану собрать любую механику по одному образцу:

- `stored` — сохранённый результат из `store`, механика показывает решённое состояние;
- `canAnswer` — значение `useCanAnswer`, пока `false`, механика не реагирует на касания;
- `onSay(text, pose)` — реплики героя: похвала, подсказка, разбор;
- `onSolved(result)` / `onResolved(result)` — итог `{ correct, firstTry, attempts, ... }`, экран пишет его в `store` и `log`.

**Лесенка подсказок** — модель обратной связи для проверок. После каждой ошибки карточка качается, все варианты остаются живыми, а герой даёт следующую ступень:

1. Направление — куда смотреть, выбор не сужает.
2. Сужение — отсекает часть вариантов.
3. Почти ответ — последнее действие всё равно делает ребёнок.

После верного ответа герой проговаривает «почему так» (`why`). Застрять нельзя: после третьей ступени ответ почти назван.

**Игровые движки — тоже механики.** Песочница с блоками, предсказание хода программы, «глупое vs умное» из курса Coddy подключаются как механики с тем же контрактом: `stored`, `canAnswer`, `onSay`, `onSolved`.

## Педагогическая дуга урока

Каждый урок проходит одну и ту же дугу: крючок, миссия, показ, практика с нарастающей сложностью, проверка, итог. Коды экранов в реестре берутся из этого списка.

| Код | Экран | Что происходит |
| --- | --- | --- |
| `HELLO`, `TOUR-1`, `TOUR-2` | Знакомство и тур | Только в первом уроке курса: герой представляется, `CoachMark` показывает кнопки шапки |
| `HOOK` | Крючок | Проблема или находка, которую герой не может решить без ребёнка |
| `MISSION` | Миссия | 3–4 шага урока сеткой 2×2 или списком (`MissionScreen`) |
| `WHY` | Зачем это нужно | Где это встретится в жизни (`WhyScreen`), по желанию |
| `SHOW` | Показ | Герой показывает новое на одном примере, ребёнок повторяет |
| `CHECK-1` | Первая проверка | `HintLadder` на понимание, не на память |
| `LEVEL-n` | Уровни | 2–4 задания, каждое чуть сложнее; механики чередуются |
| `CHECK-2` | Вторая проверка | Перенос на новую ситуацию |
| `RESULT` | Результат | Ребёнок собирает или выбирает артефакт урока: значок, рабочее место |
| `ACHIEVEMENT` | Достижение | Кубок и одна фраза о том, чему научился (`AchievementScreen`) |
| `PREVIEW` | Прощание | Мостик к следующему уроку (`ByeScreen`), здесь вызывается `p.finish` |

Правила дуги:

- **11–14 экранов.** Меньше — урок не успевает дать практику, больше — ребёнок устаёт.
- **Жанры чередуются.** Двух одинаковых механик подряд нет: сборка, затем выбор, затем снова сборка.
- **Сложность растёт лесенкой.** Например, 3 → 4 → 5 шагов в заданиях на порядок.
- **Проверка понимания, а не памяти.** Задание, которое быстрее угадать перебором, чем понять, запрещено.
- **Крючок через предмет.** Новое понятие появляется из ситуации героя, а не из определения.

## Тон, обращение, языки

Герой говорит с ребёнком как старший друг: коротко, тепло, по делу. Ошибка — повод разобраться, а не оценка.

- **Обращение.** RU — «ты», EN — «you», UZ к ребёнку — «Siz». Между персонажами на UZ — «sen».
- **Слова под запретом.** «Неправильно», «ошибка», «ты не смог» ребёнку не говорятся. Вместо них — ступень подсказки.
- **Похвала конкретная.** «Верно. По адресу могут прийти к твоему дому», а не «Молодец!». Похвала берётся из текста экрана.
- **Подбадривание называет способ подумать**, а не ответ: «Посмотри, у какой детали есть буквы».
- **Длина.** Одна реплика — 1–3 коротких предложения. Задание звучит одной фразой и повторяется кнопкой «Подсказка».
- **Три языка равноправны.** Каждая строка в `C` пишется сразу на трёх языках через `L3(uz, ru, en)`; машинный перевод одной строкой запрещён.
- **Числа и символы** пишутся так, чтобы TTS прочитал их правильно; стрелки и тире в репликах не используются.

## Запреты и ошибки, которые уже ломали уроки

Каждая строка ниже — реальная поломка из существующих уроков. ИИ проверяет свой код по этому списку до сдачи.

| Чего не делать | Что случается | Как правильно |
| --- | --- | --- |
| `AnimatePresence mode="wait"` или анимация появления с `opacity: 0` | Экран не доигрывает анимацию — белая страница навсегда, без ошибки в консоли | Экран меняется сразу; плавность только у элементов внутри |
| Объект `{ ru, uz }` прямо в JSX | React падает с ошибкой #31, весь экран пропадает | Любой видимый проп переводится внутри компонента через `pick()` |
| `onFinished` без защиты | Повторный вызов после «Пройти ещё раз» | Флаг в `ref`, вызов ровно один раз |
| Правка канона внутри урока | Уроки разъезжаются, у каждого своя версия инфры | Канон правится в одном файле и разносится по всем урокам |
| Копирование CSS-блоков | Один блок повторён 7 раз подряд | Блок стилей один; урок дописывает только своё |
| Метаданные экранов и JSX в двух массивах | Списки расходятся при правке | Один реестр `{ id, code, Comp }` |
| «Дальше» без предохранителя | Озвучка молча умерла — ребёнок заперт | Предохранители 9 с и 20 с |
| Только перетаскивание | На телефоне задание не проходится | Основной путь «ткнул — ткнул» |
| Прокрутка страницы | Задание уезжает за край, кнопки теряются | Высота от окна, `clamp`/`dvh`, `FitLine` |
| Свой аудиодвижок, `speechSynthesis` | Не проходит контракт платформы | Только `pushOneOff` из `@lesson/runtime` |
| Имя ученика в озвучке | Кеш TTS ломается для каждого ребёнка | Имя только в видимом тексте |
| Эмодзи, красный цвет ошибки, таймеры, очки | Нарушение правил курса | SVG-иконки, канал подсказки, без времени и баллов |
| Переключатель языка внутри урока | Противоречит правилу курса | Язык только из пропса `lang` |
| Локальные пути и отладка в комментариях | Утечка из сборки в прод | Комментарии объясняют решения, без путей с машины автора |

## Чек-лист приёмки

Урок сдаётся, только когда отмечены все пункты. ИИ проходит список сам и в ответе перечисляет пункты, которые не смог выполнить.

- [ ] Один JSX-файл, `export default`, импорты только `react` и `@lesson/runtime`.
- [ ] Канон сверху совпадает с эталоном дословно, урок ниже пометки «УРОК».
- [ ] Пропсы `{ studentName, lang, onFinished }`, откат языка на `ru`.
- [ ] Все тексты в `C`, каждый на трёх языках; в компонентах нет строк на естественном языке.
- [ ] Каждая реплика уходит через `pushOneOff` с маркером языка; имени ученика в озвучке нет.
- [ ] При `audio.failed` все реплики видны текстом, урок проходится без звука.
- [ ] Ответы заперты, пока герой говорит; «Дальше» открывается после разбора; предохранители работают.
- [ ] «Назад» возвращает решённое состояние экрана, «Повторить» перезапускает экран с первой реплики.
- [ ] У каждой механики есть путь касаниями; перетаскивание не обязательно.
- [ ] Нет прокрутки на экране 360×640 и на 1440×900.
- [ ] Нет эмодзи, красного цвета ошибки, таймеров и очков.
- [ ] Есть блок `prefers-reduced-motion`, пауза замораживает анимации.
- [ ] `onFinished` вызывается ровно один раз, payload по схеме, после финиша только фон.
- [ ] `log()` пишется только на экранах, где ребёнок отвечал.
- [ ] 11–14 экранов, жанры чередуются, сложность растёт.

- Изюминка (главная механика): …

- Кто ведёт урок, его поза по умолчанию, кто ошибается (если пара)

## Экраны (11–14)
| # | id | Код | Механика | Что делает ребёнок | Ключ store | log type |

- eyebrow:
