# Урок 1 курса HTML «Структура HTML-документа» — полное описание

Документ для другого ИИ (или разработчика), который должен понять урок от и до и сделать похожий. Файл урока: `lessons/html/01-struktura-dokumenta.jsx`. Описание сверено с кодом.

---

## 1. Паспорт урока

| | |
|---|---|
| Курс / модуль | HTML · модуль 1 «Основы разметки» · урок 1 из 9 |
| Тема | Структура HTML-документа: `html`, `head`, `body`, `title`, открывающий и закрывающий тег |
| Возраст | 8–10 лет (урок 2 уже для 11–14) |
| Языки | узбекский, русский, английский. Обращение: UZ — «Siz», RU — «ты», EN — «you» |
| Длительность | 14 экранов, примерно 15–20 минут |
| Герой | Коди — робот Junior IT Akademiya (кремовая голова-шлем, тёмный экран-лицо с пиксельными глазами, тёмно-синий свитер с надписью JUNIOR IT AKADEMIYA) |
| Итог урока | ученик собирает свою первую страницу (название вкладки + текст), она сохраняется как артефакт |

**Замысел одной фразой.** Коди хочет сделать свою первую страницу: с названием на вкладке и приветствием на странице. Главный инструмент — **мини-браузер** (вкладка + страница), связанный с **кодом**: меняешь текст в `title` — меняется вкладка, меняешь текст в `body` — меняется страница. Связь каждый раз показывается цветом тега и анимированным «проводом» от кода к результату.

**Дуга урока.** Показ (что такое тег, из чего состоит документ) → повторение показанного (выбрать название, написать приветствие) → проверка «что менять ради цели» → сборка вложенной структуры → пары тегов → починка (перенести строку, дописать закрывающий тег) → песочница → самостоятельная сборка документа → своя страница → итог.

## 2. Как устроен файл (технический контракт)

- **Один файл = один урок**, `export default` — корневой компонент `HtmlLesson01`.
- **Пропсы:** `{ studentName, lang, ttsApiBase, voiceGender, onFinished }`. Дев-пропсы `startAt` (открыть на экране N) и `onExit` платформа не передаёт.
- **Импорт:** только `react`. Никаких внешних библиотек, картинок и шрифтов: герой и всё оформление рисуются кодом (SVG + CSS).
- **Две части файла:**
  1. **Канон курса** (около 6200 строк, сверху) — общий для всех уроков курса, копируется дословно из `canon/html/canon-v1.jsx`. Там: токены цвета, герой и система поз, язык, движок озвучки, гейты, похвала, каркас экрана, иконки, подсказки, коуч-марк, базовый CSS, корень урока, библиотека механик.
  2. **Урок** — ниже пометки `==  У Р О К  ==`: тексты, механики урока, 14 экранов, реестр, корень, CSS урока.
- **Все тексты** — в объекте `C` по id экрана, каждая строка трёхъязычная: `L3(uz, ru, en)`. Реплики героя звучат; подписи (eyebrow, ask, goal, кнопки) только печатаются.
- **Реестр экранов** `SCREENS = [{ id, code, Comp }]` — 14 записей; `SCREEN_RESET` — что стирает «Повторить» на каждом экране.
- **Память:** `store` (в памяти до конца урока, localStorage не используется). Возврат «Назад» показывает уже решённое состояние экрана.
- **Журнал ответов:** `log({ screenId, type, correct, firstTry, attempts })` — один ответ на экран.
- **Финиш:** `onFinished(payload)` вызывается **ровно один раз** с последнего экрана. В payload оценки нет (`scorePercent: null`, `passed: null`), а в `artifact` — страница ученика: `{ type: 'html-page', title, text, html }`.

## 3. Каркас любого экрана

Каждый экран — компонент канона `Stage`. Сверху вниз:

1. **Шапка:** полоса прогресса (оранжевая), слева метка темы экрана (eyebrow), справа кнопки **«Подсказка»** (лампочка), **«Пауза / Продолжить / Повторить»** и счётчик `05/14`.
2. **Полоса героя:** Коди в нужной позе и облачко реплики. Пока Коди говорит, в облачке — индикатор голоса (полоски). Текст реплики печатается в облачке только когда звука нет (сервис недоступен, звук выключен).
3. **Контент экрана:** строка задания (`ask`), рабочая область, подсказка.
4. **Навигация:** «Назад» слева, «Дальше» справа.

**Главные правила поведения (важны для понимания урока):**

- **Пока герой говорит — экран ждёт.** Кнопки задания заперты (выглядят «отдыхающими», не сломанными), «Дальше» неактивна. Договорил — всё открылось. Страховка: если звук «умер» молча, через 9 с кнопки открываются сами.
- **«Дальше» открывается только после решения** и когда герой договорил итоговую реплику. Открывшаяся «Дальше» наливается оранжевым и пульсирует — зовёт сама.
- **Реакция на действие вытесняет очередь.** Если ученик быстро жмёт несколько раз, герой комментирует последнее действие, а не всю накопленную очередь. Фразу на полуслове не обрывает.
- **Кнопка «Подсказка»** на каждом экране: повторяет вслух задание экрана и сразу зажигает «светодиоды» на месте действия.
- **«Светодиоды» (LED):** если ученик 7 секунд ничего не делает, на нужном элементе загорается мигающая рамка и точка в углу — показывает **место**, но не ответ.
- **Ошибка — не провал.** Нет слов «нет», «неправильно», «ошибка». Звук ошибки — две мягкие ноты, элемент слегка трясётся. Герой на ошибку ученика встаёт в позу «думаю» (`think`), не «грущу».

## 4. Коди: позы, лицо, голос

**Позы** (имя — по ситуации урока, не по эмоции). Каждая поза = положение тела, головы, рук, глаз + свой повторяющийся «такт» + своя скорость:

| Поза | Когда | Как выглядит |
|---|---|---|
| `hello` | приветствие | машет рукой |
| `explain` | спокойный рассказ | лёгкое покачивание |
| `point` | «смотри сюда» | подался вперёд, рука показывает |
| `rule` | разбор «почему так» | спокойно раскрывает руки |
| `think` | ошибка ученика, «разберёмся вместе» | наклон головы, постукивает |
| `curious` | любопытство | наклоняется от пояса, выглядывает |
| `wonder` | «ого!» | подскок, глаза-кольца |
| `smile` | «получается» | двойной прыжок, глаза-дуги |
| `cheer` / `celebrate` | похвала, финал | прыжок, глаза-звёзды, искры |
| `sorry` | ошибся **сам** Коди (экран 10) | оседает, веки вниз |
| `bye` | прощание | машет, уходит |

**Лицо живёт само:** взгляд иногда уходит в сторону, глаза моргают (сжимаются, как пиксели), рот меняет форму по состоянию, при речи рот «говорит» и пульсируют кольца в «наушниках», по стеклу экрана пробегает блик. Свечение экрана: спокойно — бирюзовый, радость — жёлтый, «ого» — голубой.

**Голос:** один, женский детский (`g=f`; если LMS передала `voiceGender`, берётся он).

## 5. Сквозные приёмы объяснения (на них держится весь урок)

1. **Мини-браузер.** Окно с тремя точками, **вкладка** (иконка + название) и **страница**. Страница рисуется как настоящий браузер без CSS: шрифт с засечками, чёрный на белом. Пока `title` пустой, на вкладке курсивом серым — `index.html`. Подписи-«пины» `ВКЛАДКА` и `СТРАНИЦА` называют части.
2. **Код рядом с результатом.** Строки кода с номерами, отступами и **цветными скобками вложенности** слева. На телефоне код и браузер — в колонку, на компьютере — в ряд.
3. **Один тег — один цвет везде** (в коде, на контейнерах, на вкладке и странице):
   - `html` — графит `#586A83`;
   - `head` — фиолетовый `#6F57AB`;
   - `title` — ягодный `#9F4471`;
   - `body` — стальной голубой `#1171A0`.

   Оранжевый `#FF4F28` — только интерфейс (кнопки, «нажми сюда»), жёлтый — подсказки, зелёный — «верно». Красного нет: он читается как ошибка.
4. **«Провод».** После изменения от места в коде к тому, что изменилось (вкладка или страница), рисуется изогнутая линия цвета тега с точками на концах: линия «прорисовывается» за 0,7 с, конец «пульсирует», через 2 с линия бледнеет.
5. **Подсветка части браузера цветом тега:** title → обводка вкладки; head → полоса вкладок + плашка «Сведения о странице»; body → обводка и голубоватый фон страницы; html → обводка всего окна. Вкладка или страница при изменении на миг вспыхивает своим цветом.
6. **Печать по буквам.** Новое название и текст «печатаются» с мигающим курсором (при «меньше движения» — сразу целиком).
7. **Рука-подсказка.** Перед новой механикой нарисованная рука дважды показывает путь «нажми сюда → потом сюда» (с кругом-«касанием») и исчезает от первого касания ученика.
8. **Лесенка подсказок из 3 ступеней** после каждой неудачи:
   - **«Направление»** — куда смотреть;
   - **«Сужаем»** — уже конкретнее;
   - **«Почти ответ»** — почти решено, последнее действие остаётся ученику.

   На экране всегда одна, самая свежая ступень (жёлтая карточка «💡 Направление 1/3»). Верный ответ сбрасывает лесенку. **Если ученик решил только после подробной подсказки (2-я или 3-я ступень), он получает ещё одну короткую задачу на тот же принцип с новым содержимым** — так проверяется, что понял, а не подсмотрел.
9. **Похвала называет действие** («Верно, это закрывающий тег. Косая черта говорит, что часть закончилась»), короткие похвалы ротируются («Правильно! / Молодец! / Отлично! / Точно!»), подбадривание тоже ротируется и никогда не выдаёт ответ.
10. **Проверка структуры, а не поломка.** Ошибка в разметке не рисуется как «сломанный браузер». Есть панель «Проверка структуры» с правилами-галочками; невыполненное правило подсвечено жёлтым.
11. **Теги произносятся словами.** На экране — точная запись (`title`, `</body>`), в озвучку уходит «тайтл», «закрывающий тег бади», «эйч-ти-эм-эль» (обёртка `SpokenTags`).

## 6. Экран за экраном

Ниже: что видит ученик, что делает, что говорит Коди (RU), как устроены ошибки и подсказки, какие анимации.

### Экран 1 · Крючок «Первая страница» (`s1`, HOOK)
- **Видит:** пустой мини-браузер (на вкладке серое `index.html`), поверх — круглая оранжевая кнопка ▶. Браузер мягко «дышит» вверх-вниз, вокруг — оранжевое свечение.
- **Коди:**
  - `hello`: «Привет! Я Коди, робот Junior IT Академии. Я умею делать сайты.»
  - `curious`: «Сегодня я хочу сделать свою первую страницу. Пусть на вкладке будет её название, а на странице — приветствие.»
  - `point`: «Вот что получится. Нажми на браузер и посмотри.»
- **Действие:** нажать на браузер.
- **Результат:** на вкладке печатается «Мой первый сайт», на странице — «Привет! Это моя страница.», появляются пины ВКЛАДКА и СТРАНИЦА, обе части вспыхивают. Коди (`cheer`): «На вкладке — название, в окне — сама страница. Мы соберём это вместе с помощью HTML!» Задание меняется на «Сверху — вкладка, ниже — страница».
- **Зачем:** показать цель урока до объяснений.

### Экран 2 · Миссия «Наш план» (`s2`, MISSION)
- **Видит:** три закрытые карточки (рубашка: тёплая бумага в точку, белый кружок с оранжевым «?», который «дышит», метка `</>`).
- **Коди** открывает их по одной под голос:
  - «Части документа» — «Сначала узнаем, из каких частей состоит HTML-документ.»
  - «Собрать структуру» — «Потом правильно сложим части друг в друга.»
  - «Своя страница» — «А в конце ты сделаешь свою страницу: с названием вкладки и текстом.»

  Карточка, о которой он сейчас говорит, — оранжевая; открытые — белые с иконкой.
- **Тур по кнопкам-помощницам** (урок первый в курсе): затемнение экрана с «окном» вокруг настоящей кнопки шапки:
  1. «Кнопка „Подсказка“: если не знаешь, что делать, нажми эту кнопку. Нажми её прямо сейчас!» — шаг засчитывается настоящим нажатием, подсказка произносится («Вот так: подсказка повторяет задание»).
  2. «Кнопка „Пауза“: если нужно остановиться, нажми „Паузу“. Попробуй!» → «Урок остановился. Нажми ещё раз, чтобы продолжить.» — засчитываются два нажатия.

  Если шаг не выполнен, через 30 с он уступает место следующему (урок не запирает).
- **Финал:** «Отлично! Начинаем.»

### Экран 3 · «Что такое тег» (`s3`, SHOW → практика)
- **Показ:** крупная строка из трёх частей `<body>` · `Привет!` · `</body>`, под ней подписи «Открывающий тег / Содержимое / Закрывающий тег», ниже мини-браузер. Части загораются **синхронно с голосом**:
  1. «HTML — это язык страниц. Он говорит браузеру, что есть на странице.»
  2. «Вот это тег: слово в уголках-скобках. Это открывающий тег: здесь часть начинается.» — подсвечен `<body>`.
  3. «Между тегами стоит содержимое. Именно оно видно на странице.» — подсвечено «Привет!», подсвечена страница браузера.
  4. «А это закрывающий тег. Он такой же, только с косой чертой впереди. Здесь часть заканчивается.» — подсвечен `</body>`, **косая черта залита жёлтым**.
  5. «Сами теги на странице не видны. Это указания для браузера.» — теги бледнеют, на странице пин «ТЕГИ НЕ ВИДНЫ».
  6. «Теперь ты. В новой строке нажми части по очереди.»
- **Практика:** новая строка `<body>Я учу HTML</body>`, нажать части **по порядку**: открывающий → содержимое → закрывающий. Подписи пронумерованы 1-2-3, найденные становятся зелёными с галочкой.
- **Ошибка** (нажата не та часть): часть трясётся, лесенка для текущей части. Например, для открывающего:
  - «Тег — это слово в уголках. Посмотри на начало строки.»
  - «В открывающем теге нет косой черты.»
  - «Нажми на самую левую часть: в ней слово body.»
- **Похвала по частям:** «Верно, это открывающий тег. Часть начинается здесь.» … итог: «Так устроена каждая часть: открывающий тег, содержимое, закрывающий тег.»

### Экран 4 · «Структура документа» (`s4`, SHOW → исследование)
- **Показ:** слева «коробки» вложенности, справа код. Под голос строки кода **въезжают** по одной, а коробки появляются с «пружиной»:
  1. «Каждый HTML-документ начинается со служебной строки. Она сообщает браузеру, что здесь современный HTML.» — `<!DOCTYPE html>` с пометкой «СЛУЖЕБНАЯ СТРОКА».
  2. «Дальше идёт тег html. Это большой контейнер: весь документ внутри него.» — коробка `html`.
  3. «Внутри html первым стоит head. В нём сведения о странице.» — коробка `head` внутри (подпись «Сведения о странице»).
  4. «Под ним стоит body. В нём всё, что видно на странице.» — коробка `body` («видимая часть»).

  Подсвеченный контейнер в коде получает фон своего цвета, остальные строки бледнеют.
- **Исследование:** «Теперь нажми на каждый контейнер: html, head и body.» Нажатие коробки: она выделяется, мини-браузер подсвечивает свою часть (head → полоса вкладок + плашка «Сведения о странице»; body → страница; html → всё окно), Коди объясняет:
  - «html — весь документ…»
  - «head — сведения о странице. На самой странице их не видно, а название попадает на вкладку.»
  - «body — видимая часть страницы. Текст будет здесь.»

  Осмотренные коробки получают галочку. Итог: «Итак, внутри html — head и body. head — о странице, body — то, что на ней видно.»

### Экран 5 · «head и title» (`s5`, LEVEL-1)
- **Видит:** мини-браузер + полный код; строки `head` подсвечены; в `<title>` — «…».
- **Коди:** «Внутри head стоит тег title. Его текст виден на вкладке браузера. Выбери название для вкладки.»
- **Действие:** выбрать одну из трёх кнопок: «Мой сайт» / «Страница Коди» / «Привет, мир».
- **Результат:** название **печатается в коде** между тегами `title` и одновременно на вкладке; вкладка вспыхивает ягодным, рисуется провод от кода к вкладке; на странице пин «БЕЗ ИЗМЕНЕНИЙ». Коди: «Название вкладки изменилось. Его задаёт title. title стоит внутри head и меняет только название вкладки. Страница не изменилась.»
- **Дальше:** можно выбрать другое («Вкладка снова обновилась, а страница прежняя») или **впечатать своё прямо в коде**: в строке `title` появляется поле ввода. Выбор сохраняется (`myTitle`) и используется дальше в уроке.

### Экран 6 · «body» (`s6`, LEVEL-2)
- **Коди:** «Теперь body. Текст внутри него виден на самой странице. Напиши в коде приветствие: нажимай слова или печатай сам.»
- **Видит:** в коде строка `body` с **полем ввода**; под кодом кнопки-слова («Привет!», «Это», «моя», «страница.», «Добро», «пожаловать!»), «стереть слово» и «Готово». Рука-подсказка показывает: слово → поле.
- **Проверка по «Готово»:** пусто → «Напиши для страницы хотя бы пару слов.»; есть `<` `>` → «В тексте не нужны уголки-скобки, только слова.»
- **Успех:** текст на странице, провод от строки body к странице, страница вспыхивает голубым, на вкладке пин «БЕЗ ИЗМЕНЕНИЙ». «Текст появился на странице. Он находится внутри body. То, что внутри body, видно на странице, а название вкладки не меняется.» Сохраняется `myText`.

### Экран 7 · Проверка «что менять ради цели» (`s7`, CHECK-1)
- **Видит:** карточку «ЦЕЛЬ: На вкладке должно быть „Кошки“ 1/2», мини-браузер и код, где **каждый токен — кнопка** (теги и тексты).
- **Коди:** «Теперь реши сам: какое место в коде нужно изменить, чтобы добиться цели? Нажми на это место.»
- **Раунды:** «На вкладке — „Кошки“» → нужен текст в `title`; «На странице — „Я люблю кошек“» → текст в `body`.
- **Верно:** значение печатается в коде, провод к вкладке или странице, вспышка, похвала («Верно! Название вкладки поменялось внутри title»).
- **Неверно — объяснение по тому, что нажато:**
  - тег → «Это тег — он отмечает, где часть начинается или кончается. Менять будем текст, а не тег.»
  - текст body вместо title → «Этот текст виден на странице, он в body. А нам нужна вкладка.»
  - …плюс лесенка («Какая часть документа задаёт название вкладки?» → «Посмотри внутрь head.» → «Нажми на текст между тегами title.»).

  На телефоне подсказка временно занимает место браузера.
- **Подробная подсказка** → добавляется ещё один раунд того же типа («Футбол» / «Сегодня игра»).
- **Итог:** «Название вкладки — внутри title, текст страницы — внутри body.»

### Экран 8 · «Собери документ» (`s8`, LEVEL-3)
- **Видит:** рамку `<html> … </html>` с двумя пустыми пунктирными местами «+ место 1», «+ место 2»; ниже детали `<head>…</head>`, `<body>…</body>`, `<title>…</title>`.
- **Коди:** «Части рассыпались. Поставь их на места: сначала нажми на часть, потом на место.» Рука показывает head → место 1.
- **Управление:** касание детали (она приподнимается) → касание места. Дополнительно можно **перетащить**. Место для `title` открывается **внутри head**, только когда head уже стоит.
- **Ошибки с объяснением:**
  - title в html → «title — это сведения о странице. Его место внутри head.»
  - title в body → «То, что в body, видно на странице. А название вкладки стоит внутри head.»
  - body раньше head → «Внутри html сначала идёт head, потом body.»
  - title до head → «Место для title появится внутри head. Сначала поставь head.»

  Плюс лесенка; 3-я ступень называет конкретное место.
- **Успех:** «Структура собрана! Вот её настоящий код.» — появляется настоящий код со **ступенчатым въездом строк**; на телефоне переключатель «Схема / Код».

### Экран 9 · «Найди пару» (`s9`, LEVEL-4)
- **Видит:** чипы `html head title body` и код, где теги — кнопки.
- **Коди:** «У каждого открывающего тега есть закрывающая пара. Нажми открывающий тег, а потом его пару.» Рука: `<head>` → `</head>`.
- **Успех пары:** оба тега получают мягкую плашку своего цвета, **слева появляется цветная скобка**, показывающая, какую область пара охватывает; чип получает галочку. «Пара найдена: head начинается здесь и заканчивается здесь.»
- **Ошибки:**
  - сначала нажат закрывающий → «Сначала выбери открывающий тег — тот, что без косой черты.»
  - не та пара → «Это пара другого тега. Ищи такое же слово: head.»
  - лесенка: «В закрывающем теге то же слово…» → «…есть косая черта» → «Для head нажми head с косой чертой.»
- **Итог:** «Пары вложены друг в друга: title внутри head, head и body внутри html.»

### Экран 10 · «Почини структуру» (`s10`, CHECK-2)
- **Коди** (`sorry` — ошибся он сам): «Ой, я писал документ в спешке и поставил одну строку не на место. Проверка показывает, какое правило не выполнено. Помоги мне!»
- **Видит:** панель «Проверка структуры»:
  - «Всё внутри html» ✓;
  - «title — внутри head» (жёлтое, текущее);
  - «У каждого тега есть закрывающий».

  В коде строка `title` стоит внутри `body`, а `</body>` нет.
- **Шаг 1 — перенос:** нажать строку не на месте (title) → «Это строка с title. После какой строки она должна стоять?» → нажать строку `<head>`. Строка переезжает, правило становится зелёным. Ошибки: «Эта строка на месте. Посмотри на проверку…», «Посмотри, где заканчивается head…» + лесенка.
- **Шаг 2 — дописать тег:** «Теперь title внутри head. Но проверка видит ещё одно: body не закрыт. Напиши закрывающий тег сам.» Появляется поле в пустой строке кода и кнопки-символы `<` `/` `>` (для телефона), стереть и «Проверить».
- **Разбор набранного:**
  - `<body>` → «Это открывающий тег. В закрывающем нужна косая черта.»
  - нет `<` → «Тег начинается с уголка: <»
  - нет `>` → «Закрой тег уголком: >»
  - не то имя → «Нам нужен закрывающий тег именно для body.»

  Лесенка: «Закрывающий тег похож на открывающий» → «Косая черта стоит сразу после знака <» → поле заполняется `</bod` и остаётся «допиши последнюю букву и >».
- **Подробная подсказка** → ещё одна починка: в другом документе не закрыт head.
- **Итог:** «Теперь body закрыт. Структура полная!»

### Экран 11 · Песочница (`s11`, LEVEL-5)
- **Коди:** «Здесь можно экспериментировать сколько хочешь. Меняй текст внутри title и body и смотри в браузер.»
- **Видит:** код с двумя полями ввода (в title и в body), мини-браузер, переключатель «Было / Стало» и кнопку «Как было».
- **Каждая правка:** вкладка или страница обновляется, провод, вспышка. Первый раз Коди комментирует: «Вкладка обновилась — это сделал title.» / «Страница обновилась — это сделал body.»
- **«Было»** — показывает исходный вид с меткой «БЫЛО» («Это — до изменений. Нажми „Стало“ и сравни»); **«Как было»** — откат.
- **Экран засчитан**, когда изменены оба поля: «Отличный эксперимент! Теперь видно, как код связан с результатом.»

### Экран 12 · Самостоятельная миссия (`s12`, RESULT)
- **Коди:** «Теперь сам. Сделай страницу о своём любимом занятии. Сначала расставь строки по порядку.»
- **Сборка:** `<!DOCTYPE html>` уже стоит, ниже 8 пустых пронумерованных мест; снизу «Строки» — перемешанные детали:

  `</body>` `<title>…</title>` `</html>` `<head>` `текст страницы` `<html>` `<body>` `</head>`

  Касание детали ставит её в следующее пустое место; касание стоящей строки возвращает её. Когда все места заполнены — кнопка «Проверить».
- **Проверка по правилам** (первое нарушенное):
  - «Весь документ — внутри html: он открывается первым и закрывается последним.»
  - «Закрывающий тег стоит после своего открывающего.»
  - «title должен стоять внутри head.»
  - «Текст страницы стоит внутри body.»
  - «Сначала head, потом body.»
  - «head закрывается до того, как начнётся body.»
- **Лесенка:**
  1. правило;
  2. правило + «Посмотри на отмеченные строки» (ошибочные строки подсвечены жёлтым);
  3. всё расставлено, кроме последней свободной строки: «Почти готово: последнюю строку поставь сам».

  После подробной подсказки — повторная сборка только части head.
- **Заполнение:** «Структура верная! Теперь напиши название вкладки и текст страницы.» Поля в `title` и в тексте body (подсказки-примеры «Например: Футбол», «Например: Я люблю футбол»), над кодом мини-браузер обновляется. Проверка: есть буквы, нет тегов.
- **Итог:** «Твоя страница готова: название — в title, текст — в body.»

### Экран 13 · «Мой первый сайт» (`s13`, ACHIEVEMENT)
- **Видит:** «Автор: имя ученика», мини-браузер со страницей ученика (пины ВКЛАДКА / СТРАНИЦА) и её полный код. На телефоне переключатель «Результат / Код».
- **Коди** (`wonder`): «Вот твоя страница! Название на вкладке дал title, а текст — body. Сохрани её.»
- **Действие:** большая кнопка «Сохранить страницу» (с «победным» звуком) → зелёная плашка «✓ Сохранено». «Сохранено! Эта страница — твоя первая работа.» Страница сохраняется как артефакт для payload.

### Экран 14 · Итог (`s14`, PREVIEW)
- **Видит:**

## 8. Озвучка

- **Движок канона** обращается к сервису LMS: `GET {ttsApiBase}/api/tts?text=<маркер языка + реплика>&g=f&lesson_id=html-01-struktura-dokumenta&lesson_name=<название урока на языке ученика>`. Кодирование — как у эталона математики: пробел `%20`, квадратные скобки маркера как есть. Сервис синтезирует голос (ElevenLabs).
- **Маркер языка** в начале каждой реплики: `[O'zbekcha tallaffuz]` / `[Русское произношение]` / `[English pronunciation]`.
- **Правила текста:** имени ученика в озвучке нет (имя только на экране); символов `% / ² + = ×` нет; теги произносятся словами; реплика — полные предложения, до ~25 с.
- **Прогрев:** через 0,7 с после открытия экрана сервису заранее отправляются HEAD-запросы на реплики этого и следующего экрана, чтобы голос на нажатие не запаздывал.
- **Старт:** урок сразу пробует звук. Если браузер запрещает автозапуск, реплика показывается текстом, и первое касание произносит её с начала.
- **Без сервиса** (`ttsApiBase` пуст) — голос браузера; нет и его — текст в облачке.
- **Диагностика:** в консоли браузера строки `[TTS] …` — получен ли `ttsApiBase`, первый запрос, причина перехода на голос браузера.

## 9. Адаптивность

- **Телефон** — главный экран. Код и браузер в колонку, на некоторых экранах переключатель «Код / Результат» или «Схема / Код». Проверено: 360×640 и 320×568, ничего не выходит за экран.
- **Компьютер** — в ряд, крупнее кегль кода и подписи.
- **Открытая клавиатура телефона:** полоса героя и навигация уходят, видны только код с полем, браузер и кнопка проверки; отправка — Enter или «Проверить».
- Поля ввода 16 px (иначе iOS увеличивает страницу). Все действия выполняются касаниями; перетаскивание — только дополнительный путь.

## 11. Если делать похожий урок — короткий чек-лист

1. Канон курса копируется дословно сверху, урок — ниже пометки «УРОК». Импорт только `react`.
2. Сначала результат (крючок), потом план, потом показ под голос, потом действие ученика.
3. Каждое действие → видимое изменение (провод, вспышка, печать) → короткое объяснение причины.
4. Перед новой механикой — рука-подсказка; на бездействие — LED; на ошибку — лесенка из 3 ступеней с объяснением именно этой ошибки; после подробной подсказки — ещё одна задача с новым содержимым.
5. Один тег — один цвет везде; оранжевый — только интерфейс; без красного.
6. Пока герой говорит — экран ждёт; «Дальше» — только после решения.
7. Тексты в `C` на трёх языках, простыми словами; теги в озвучке — словами; имени ученика в озвучке нет.
8. Проверка на 360×640, 320×568 и 1440×900, с подсказкой и с открытой клавиатурой; `onFinished` ровно один раз.
