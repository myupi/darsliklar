# Команда агентов для уроков Darsliklar

Система субагентов Claude Code. Создаёт, проверяет, локализует и исправляет уроки любого модуля: HTML, CSS, JavaScript, Python, алгоритмы, цифровая грамотность и другие. Главный Claude — координатор: ставит задачу, поручает работу агентам и честно собирает результат. Отдельного агента-пересказчика нет.

## Агенты (`.claude/agents/`)

| Агент | За что отвечает | Меняет файлы |
|---|---|---|
| `lesson-methodist` | Цели, опора на изученное, последовательность объяснений и заданий, ошибки, подсказки, самостоятельные проверки, сюжет | нет |
| `subject-reviewer` | Предметная правильность: определения, примеры, решения, код, упрощения; первоисточники | нет (Bash — только запуск примеров во временной папке) |
| `lesson-builder` | Сборка урока из готовых компонентов модуля и исправления; самопроверка — сборка, синтаксис, тексты | **да, один на урок** — только разрешённые постановкой файлы |
| `language-editor` | Все языки, совпадение смысла, термины, озвучка; узбекский на «Siz» | нет — возвращает точные замены |
| `learning-reviewer` | Качество заданий в сценарии; сверка реализации со сценарием; честность журнала и итоговых данных | нет |
| `ux-reviewer` | Урок глазами ученика: ясность, телефон, клавиатура — только по просьбе | нет |
| `qa-tester` | Короткая техническая проверка (свой сервер `--serve`); полный QA — только по прямой просьбе | пишет только отчёты в `work/lesson-team/` |

## Запуск

Навык `/lesson-team` запускается только вручную, задача пишется обычным русским языком:

```
/lesson-team Создай следующий урок по HTML
/lesson-team Создай тестовый урок по Python: условия
/lesson-team Подготовь только сценарий урока по алгоритмам
/lesson-team Проверь существующий урок lessons/test/10-zagolovki-i-tekst-turnir-pixel.jsx без изменений
/lesson-team Проверь только узбекские тексты lessons/test/10-zagolovki-i-tekst-turnir-pixel.jsx
/lesson-team Выполни полный QA урока lessons/test/10-zagolovki-i-tekst-turnir-pixel.jsx
/lesson-team Исправь замечания в указанном тестовом уроке
```

Координатор выбирает самый узкий режим по тексту запроса — параметров нет. Обычный `/lesson-team <создай урок…>` идёт стандартным процессом (60–90 минут для типового урока на существующем каркасе):

1. постановка: тема, аудитория, изученное, профиль модуля, границы изменений;
2. сценарий методиста: цели, объяснения, задания с ответами, ошибки, подсказки, самостоятельная проверка;
3. параллельно — предмет, качество заданий и языки сценария; один список правок → методист, до реализации;
4. сборка из готовых компонентов модуля;
5. параллельно — сверка реализации со сценарием, тексты реализации и короткая техническая проверка; один список правок → исполнитель → повтор затронутого;
6. передача QA-команде заказчика (`shablon-peredachi.md`), статус «готов к QA».

Полную матрицу устройств, языков, ошибок и состояний проверяет QA-команда заказчика; `qa-tester` делает её только по прямой просьбе. «Только сценарий», «только перевод», «только проверка» остаются в своих границах; проверка без изменений файлы урока не меняет. Подробно — `.claude/skills/lesson-team/SKILL.md`.

> **Первый запуск.** Папка `.claude/agents/` создана во время работающей сессии. Claude Code подхватывает агентов из папки, которой не было при старте, только после перезапуска сессии. Навык `/lesson-team` подхватывается сразу.

Существующие навыки `/novyy-urok` и `/praktika` не заменены. Для уроков HTML команда использует их требования и справочники (см. профиль HTML). Для других предметов HTML-шаги не выполняются.

## Правила и профили (`docs/lesson-team/`)

| Файл | Что внутри |
|---|---|
| `pravila-komandy.md` | Цель и бюджет, стандартный процесс, права агентов, готовые компоненты, кто что проверяет, версии, параллельность, повторные проверки, статус «готов к QA» |
| `obshchie-trebovaniya.md` | Универсальные требования к уроку; что не универсально; неоднозначные правила |
| `format-otchyotov.md` | Шапка отчёта, статусы `passed` / `failed` / `not-run` / `blocked`, формат замечания, формат замен текста |
| `shablon-postanovki.md` | Постановка задачи — заполняется в начале каждого запуска |
| `shablon-peredachi.md` | Передача урока QA-команде заказчика — заполняется в конце |
| `moduli/_shablon.md` | Шаблон профиля модуля |
| `moduli/html.md` | Профиль HTML по реальным материалам проекта |

## Подключить новый модуль

1. Скопировать `moduli/_shablon.md` в `moduli/<модуль>.md`. Заполнить только проверенными фактами: аудитория, языки, изученное, образцы, канон, готовые компоненты и сборка, персонажи, озвучка, задания, результат ученика, особенности контракта, адаптер QA.
2. Нет каркаса урока (готовых компонентов и сборщика) — первый урок модуля начинается с отдельной подготовки каркаса; координатор называет её срок.
3. Чего нет (например, канона), так и записать. Команда не выдумывает «утверждённое» и спросит заказчика, если без решения работать нельзя.
4. Если каркас уроков не похож на канон HTML — добавить адаптер QA (`tools/qa/lesson-team/adapters/`, см. README там).
5. Запустить `/lesson-team …`. Координатор передаст агентам путь к профилю — агентов переписывать не нужно.

## QA

Инструменты — `tools/qa/lesson-team/` (описание и формат сценариев — `README.md` там). Раннер открывает урок через существующий плеер. По умолчанию — **короткая техническая проверка**: загрузка и ошибки, основной путь на русском в быстром режиме, основной ввод и его сохранение в итоговых данных, однократный `onFinished`, неизменность файлов во время прогона. Полная матрица (размеры × языки, все ветки, клавиатура, «меньше движения») — только по прямой просьбе; по умолчанию её проверяет QA-команда заказчика.

Сценарий конкретного урока лежит в `tools/qa/lesson-team/scenarios/`. Его пишет `lesson-builder`, запускает `qa-tester`.

## Где отчёты

`work/lesson-team/<run-id>/`:
- `brief.md`;
- versions/ — зафиксированные версии файлов;
- ответы агентов `NN-<агент>.md`;
- `scenario.md` — окончательный сценарий;
- `qa/…` (отчёты, журнал событий, payload);
- `peredacha.md` — передача QA-команде заказчика.

Каталог исключён из git своим `.gitignore`, автоматически ничего не коммитится.

## Что проверяется автоматически, а что — нет

**Короткая техническая проверка (по умолчанию):**
- сборка и синтаксис, наличие текстов и переводов;
- загрузка и ошибки браузера;
- основной путь на русском в быстром режиме;
- основной ввод и сохранение результата в payload;
- однократный `onFinished`;
- версия файлов.

**Раннер умеет, но только по прямой просьбе (полный QA):** переполнение на 360×640, 375×740, 1280×720, 1440×900 на трёх языках; все ветки сценария; эмуляция клавиатуры; маркеры озвучки; «меньше движения».

**Агентами по сценарию и коду:**
- предметная правильность;
- качество заданий и сверка реализации со сценарием;
- качество языков;
- смысл учёта и итоговых данных;
- удобство интерфейса — по просьбе.

**QA-командой заказчика:**
- полная матрица устройств, языков, ошибок и состояний;
- настоящий телефон и его клавиатура;
- живая озвучка сервиса;
- впечатление ученика.
