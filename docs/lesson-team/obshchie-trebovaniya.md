# Общие требования к уроку (для любого модуля)

Короткий список, по которому работает вся команда. Предметные и технические детали — в профиле модуля (`moduli/<модуль>.md`). Если требование профиля строже — действует профиль.

## Универсальные требования

| # | Требование | Как проверить |
|---|---|---|
| 1 | **Понятная учебная цель.** Урок ведёт к 2–5 умениям «после урока ученик сможет …» — действия, а не «узнает о …» | Цели записаны в сценарии; каждое умение где-то применяется самостоятельно |
| 2 | **Соответствие возрасту и исходным знаниям.** Возраст и изученное — из постановки и профиля; новое не требуется до объяснения | Сверить с перечнем «изучено / ещё нет» профиля и реальными файлами прошлых уроков |
| 3 | **Объяснение перед самостоятельным применением.** Показать → повторить → сделать самому → перенести | Для каждого нового понятия найдён экран показа до экрана, где его надо применить |
| 4 | **Конкретное задание.** Ученик понимает, что сделать и где, без взрослого | Формулировка называет вещь на экране; одно основное действие на шаг |
| 5 | **Видимое последствие действия.** Результат виден сразу, рядом с действием | Каждое действие меняет что-то видимое (превью, объект, ответ, состояние) |
| 6 | **Объяснение причины ошибки.** Неверный ход получает причину и следующий шаг, без стыда, штрафов и лимитов | Для типичных ошибок есть свои реакции, а не «попробуй ещё» |
| 7 | **Доступная помощь.** Ступени подсказки: направить внимание → объяснить принцип → показать конкретное действие; после сильной помощи — новый короткий пример | Ступени написаны под задание; застрять нельзя |
| 8 | **Осмысленная самостоятельная проверка.** Перенос на новую ситуацию и/или своя работа с видимыми условиями «готово» | Проверка требует понимания, перебором её не пройти |
| 9 | **Сохранение работы ученика по контракту.** Внутри урока ничего не теряется (назад, повтор экрана, правки после «Готово»); после урока — то, что обещает контракт модуля | learning-reviewer: по коду; короткая проверка — основной ввод попал в итог; назад, повтор, правка — QA-команда заказчика |
| 10 | **Достоверный результат завершения.** Завершение вызывается ровно один раз; журнал и достижения отражают то, что ученик сделал сам, с помощью или не сделал | QA: однократное завершение, payload; learning-reviewer: смысл полей |
| 11 | **Удобство на предусмотренных устройствах.** Всё видно и нажимается на заявленных размерах и языках; ввод учитывает клавиатуру; есть режим «меньше движения» | Сценарий и сборка учитывают телефон и клавиатуру; короткая проверка — основной путь; полная матрица размеров × языков и клавиатура — QA-команда заказчика (`qa-tester` — по прямой просьбе) |

## Что НЕ универсально (берётся из задачи и профиля)

- Теги, редактор кода, мини-браузер — только там, где их требует предмет.
- Персонажи (Коди, Пиксель и другие) — только если они есть в профиле модуля или в задаче.
- Результат ученика — страница, программа, схема, решение задачи, последовательность действий или другой объект.
- Возраст, число экранов, сюжет, механики — из постановки и профиля.
- Способ проверить предметное знание зависит от материала: для кода — запуск или разбор, для задачи — решение, для понятия — применение в новой ситуации.

## Платформа: что действует везде

Плеер проекта (`src/player/main.jsx`) одинаково открывает любой урок, поэтому эти пункты общие:

- урок — один файл `lessons/<курс>/<файл>.jsx` с `export default`-компонентом;
- пропсы `{ studentName, lang, ttsApiBase, voiceGender, onFinished }`; дев-пропсы `startAt` / `startScreen` приходят только в просмотрщике;
- `onFinished(payload)` — ровно один раз; повторный вызов — дефект;
- `lang` — `uz | ru | en`;
- имя ученика не попадает в озвучку (сервер кеширует звук по тексту);
- просмотрщик сообщает наружу события `loaded`, `tts`, `finished`, `error` — по ним работает QA.

## Неоднозначные правила — зафиксировано явно

Эти правила записаны в `docs/brif-uroka.md` и навыках для курса HTML. Распространяются ли они на будущие модули, заказчик не решал. До решения: для модуля **без утверждённого профиля** — уточнить у заказчика или явно указать в постановке, какой вариант выбран, и сообщить в отчёте.

| Правило | Где сказано | Почему неоднозначно |
|---|---|---|
| Импорты — только `react` | Бриф, контракт | Эталоны Кибербеза и «Алгоритмов» используют `@lesson/runtime`, `framer-motion`, `lucide-react`, и просмотрщик их поддерживает |
| Прогресс только в памяти, без localStorage | Бриф, контракт | Эталон Курса 0 использует localStorage (`lessons/_reference/_course.js`) |
| Озвучка движком канона по `ttsApiBase` | `CLAUDE.md`, исключение 12.10.2026 | Кибербез и «Алгоритмы» говорят через `@lesson/runtime` |
| Три языка uz / ru / en | Бриф, профиль HTML | Для нового модуля — из профиля; плеер принимает только эти три |
| Ученики 11–14 лет, без преподавателя, с телефона | `CLAUDE.md` для курса HTML | Другие модули (например, 1-класс) — другой возраст |
| Канон копируется дословно сверху файла | `CLAUDE.md` для курса HTML | У CSS и других новых модулей канона нет — его нельзя выдумывать |
