### Задание `cpTask(n, o)`

| Поле | Что |
|---|---|
| `page: (pk) => 'html'` | тело страницы (теги, классы, id); тексты — через `pk(L3)` |
| `given: ['css', …]` | готовые правила над полем: видны тусклыми, применяются (опора: раскладка, прошлые уроки) |
| `code0` | начальный код в поле (`''` — писать с нуля; правило с поломкой — для «почини») |
| `single: true` | поле в одну строку (замена значения) |
| `big: true` | большой редактор (своя страница, задание 5) |
| `syms: ['{','}',':',';','#']` | кнопки символов (по умолчанию `{ } : ;`) |
| `htmlAid: (pk) => ['<p class="new">…</p>', …]` | HTML страницы справкой под браузером — когда нужны имена классов, id, теги |
| `vw: 360` | окно своей ширины (урок 16: телефон 360, компьютер 800) |
| `goal: (D, st) => null \| L3` | цель по готовой странице; `null` — решено; иначе — своя фраза (что видно и что сделать) |
| `answer: 'css'` | верный ответ (для автопроверки; ДОЛЖЕН проходить `goal`) |
| `sample: ['css', …]` | образец третьей ступени — то же правило с **другим** содержимым |
| `drill: { code0, answer, goal, single?, page?, given? }` | дополнительная задача после образца (задания 1–4) |
| `list: [{ t: L3, ok: (D) => bool }]` | условия «готово» (задание 5) — видны сразу, загораются по живой странице |
| `onSolved: (st) => store.set('myCss', st.code.trim())` | задание 5: своя страница в стор (вывод и артефакт) |

### Что и куда писать (10.11.2026, проход «слабого ученика 10 лет» на узбекском)

Заказчик: «обычно ученики не понимают куда писать и что писать». Всё ниже каркас делает сам — в `pNN.jsx` ничего писать не нужно. Полосы «Kerakli so'zlar» (слова с переводом) и «Qoida shakli» были и убраны заказчиком в тот же день: «очень много места занимают» — не возвращать.

| Что | Где | Как |
|---|---|---|
| **Рамка в строке** | задания 1–2 и их дополнительные | отличие `code0` от `answer` — одно место в одной строке (`cpSlotOf`): правило стоит готовым, писать — только в рамку (`CpSlotEditor`). В рамке — старое слово (касание выделяет его, набор заменяет) или подсказка «qiymat» / «selektor» / «xususiyat: qiymat;». Не нужна — `slot: false` в задании |
| **«✎ Kodni shu yerga yozing»** | пустой редактор; пустая строка внутри скобок заготовки | подпись в строке, исчезает с первой буквой; пустые скобки `{  }` заготовки — в пунктирной рамке |
| **Строка причины** | после «Tekshirish» | строка, где `cpDiagnose` нашёл поломку или селектор ничего не выбрал, — подсвечена, пока её не исправили |
| **Кнопки символов** | задание без своего `syms` | `{ } : ;` и знаки из ответа (`( ) " % # . -`); у рамки — только знаки её ответа |

Разбор (`cpDiagnose`, проверка рамки) знает и то, на чём застревает новичок: опечатка в английском слове — «Balki orange demoqchisiz?» (`valueNear`); имя класса без точки и точка перед тегом (`needDot`, `needHash`, `noDot`); слово без правила вокруг (`noRule`); значение без свойства в скобках или в рамке (`declNoProp`, `slotNoProp`); в рамке значения — свойство или скобки (`slotVal`, `slotSel`, `slotDecl`).

`D` (CpDoc): `D.cs(sel, prop)` — вычисленный стиль (как в DevTools); `D.val(sel, prop)` — что ученик написал в правиле с этим селектором (браузер принял); `D.rule(sel)`; `D.kf(name)` — `@keyframes`; `D.rules` — все правила (`{ sel, style, media }`); `D.same(a, b)` — один ли цвет; `D.col(v)`; `D.q(sel)`, `D.qa(sel)`; `D.decls()`; `D.code` — текст ученика.
Общие причины (`cpDiagnose`) проверяются ДО `goal` — в `goal` писать только про цель темы.

### Тексты `C`

- `s1`: `eyebrow`, `say` (страница в стилях; «нажми Обновить»), `broke` (стили пропали), `done` (что делаем; опора на урок), `ask`, `askDone`.
- `t1…t5`: `eyebrow` (имя вкладки), `say` (связка с прошлым + цель), `ask` (короткая строка задания — ЦЕЛЬ, а не диктовка кода), `ok` (живая похвала), `hints[3]` (1 — направление, 2 — место или правило (можно назвать свойство и значение словами), 3 — «образец под кодом…»), свои фразы `goal` (`no`, …), `drill` (строка доп. задачи с маленькой буквы: «теперь …»), `drillNo`.
- `fin`: `eyebrow`, `say: [{ k: null|'a'|'b'|'c'|'d', text }]`, `roles: { a, b, c, d }` (умения; ровно эти 4 ключа), `ask`.

**Звучит:** `say`, `broke`, `done`, `ok`, `hints`, фразы `goal`, `drillNo`, `fin.say` — в них **без символов и кусков кода** (`{ } : ; # % ( ) = /`): только слова и имена свойств/значений буквами (color, font-size, flex-end). Символы можно в `eyebrow`, `ask`, `roles`, `list.t`.

## Правила (заказчик)

- **7 слайдов:** крючок · 5 заданий от лёгкого к чуть сложнее (самое сложное — не сложное) · вывод.
- **Лесенка:** т1 — заменить значение в готовом правиле (одна строка) · т2 — вписать свойство и значение в готовое правило · т3 — правило целиком · т4 — найти и починить 1–2 поломки, типичные для урока · т5 — своя страница (большой редактор, 2–4 условия «готово»).
- **Материал — свой урок** (≈ 3 задания из 4); прошлые — опора (`given`, страница) и смесь в т3–т5; будущих тем — нет.
- **Помощь 1-2-3** на каждом задании; со второй ошибки подряд ступень открывается сама (каркас); на третьей — образец; после образца — дополнительная задача.
- Задание называет **цель** («Сделай заголовок оранжевым»), а не «впиши orange». Новое английское слово можно назвать во второй ступени и в фразе `no`.
- Узбекский — по навыку `/uzbekcha` (`.claude/skills/uzbekcha/SKILL.md`): живая речь, «Siz», апостроф только ASCII `'`, аффикс при английском слове — через слово: «h1 tegiga», «body tegiga», без «xato»/«noto'g'ri» про ученика. RU — «ты» без рода (не «нашёл», «написал»). Проверка: `node .claude/skills/uzbekcha/scripts/tekshir.mjs tools/cssp/pNN.jsx` — ошибок 0.
- Похвала — живая («Огонь!», «Вот это да!»), Коди — напарник; имён персонажей нет.
