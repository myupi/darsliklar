# QA команды уроков (`tools/qa/lesson-team/`)

Воспроизводимые проверки урока в headless Chrome через **существующий плеер** (`/player.html`). Нужен запущенный dev-сервер (`npm run dev`, порт 5173). Зависимостей нет: Node ≥ 22 и установленный Chrome (или путь в `CHROME_PATH`).

## Быстрый старт

```bash
node tools/qa/lesson-team/run.mjs --file test/10-zagolovki-i-tekst-turnir-pixel \
  --scenario tools/qa/lesson-team/scenarios/test-10-zagolovki-i-tekst-turnir-pixel.qa.mjs --langs uz,ru,en
```

Только общие проверки, без сценария (сценарий получит `not-run`):

```bash
node tools/qa/lesson-team/run.mjs --file html/02-zagolovki-i-tekst --checks load,screens,voice --sizes 360x640,1280x720
```

Самопроверка инструментов на изолированной странице (не уроке):

```bash
node tools/qa/lesson-team/selftest/run-selftest.mjs
```

Все параметры: `node tools/qa/lesson-team/run.mjs --help`.

## Как устроено

| Часть | Файл | Что делает |
|---|---|---|
| Раннер | `run.mjs` | Запускает Chrome, открывает урок, выполняет проверки, пишет отчёт |
| Обвязка | `harness.html` | Страница на том же адресе, что плеер: урок в iframe плеера, приём событий плеера (`loaded`, `tts`, `finished`, `error`), действия `window.__ltqa` для сценариев |
| Адаптеры | `adapters/canon-html.js`, `adapters/basic.js` | Знание каркаса платформы: когда урок готов, когда ведущий договорил, где «Дальше», как эмулировать клавиатуру. Ничего не знают о теме, языке и числе экранов |
| Сценарии | `scenarios/<курс>-<файл>.qa.mjs` | Действия и ожидания конкретного урока |
| Версии | `version.mjs` | Хеш набора файлов: отчёт относится к версии |
| Запуски | `new-run.mjs` | Каталог `work/lesson-team/<run-id>/` с постановкой |
| Общее | `lib/` | CDP-клиент, хеши, отчёт и статусы |

`canon-html` без изменений использует `.claude/skills/novyy-urok/scripts/qa.js` и `tools/layout-sweep.js`.

## Проверки

| Проверка | Что проверяет | Нужно |
|---|---|---|
| `load` | Урок отрисован, нет исключений, ошибок консоли и ошибок плеера | — |
| `screens` | Каждый экран × размер × язык: отрисован, без переполнения, горизонтальной прокрутки и ошибок (`tools/layout-sweep.js`, начальные состояния, голос `off`) | адаптер `canon-html`, число экранов |
| `scenario` | Все шаги сценария и ветки (`flows`) выполнены; ошибок нет | сценарий |
| `finish` | `onFinished` ровно один раз там, где проход доходит до конца; payload сохраняется | `expectFinish` в сценарии |
| `keyboard` | **Эмуляция** открытой клавиатуры (видимая высота 330 px) на экранах с вводом: ничего не уходит за край | `inputScreens` или `--kbd-screens` |
| `voice` | Каждая реплика сервиса озвучки начинается с маркера языка урока | голос `fast` / `simulate`, адаптер `canon-html` |
| `version` | Файлы урока и сценария не менялись во время прогона | — |

Статусы: `passed` (условие и доказательство), `failed` (воспроизведение), `not-run` (не выполнялась — причина), `blocked` (не смогли: нет сервера, браузера, тайм-аут, файл изменился). Итог `passed` — только если все проверки `passed`. Код выхода: 0 / 1 / 2 / 3 = passed / failed / blocked / not-run.

## Сценарий урока

```js
// tools/qa/lesson-team/scenarios/<курс>-<файл>.qa.mjs
export default {
  title: 'Урок …',
  file: '<курс>/<файл без .jsx>',
  adapter: 'canon-html',          // или 'basic' / свой
  langs: ['ru'],                  // языки основного прохода
  size: '375x740',
  voice: 'fast',
  screens: 14,                    // для проверки screens
  inputScreens: [2, 13],          // экраны с вводом (1-based) для эмуляции клавиатуры
  expectFinish: true,             // основной проход заканчивается onFinished
  data: { ru: { … }, uz: { … }, en: { … } },   // ожидаемые значения по языкам → qa.data
  steps: [
    { name: 'Экран 1: …', shot: 's1', run: async (qa) => { await qa.platform.ready(); qa.click('…'); await qa.platform.next(); } },
  ],
  flows: [                        // отдельные ветки: свежая загрузка с экрана start (0-based)
    { name: 'ошибки на экране 4', start: 3, langs: ['ru'], data: { default: { … } }, steps: [ … ] },
  ],
};
```

- Функция шага выполняется **в странице**: замыкания на переменные модуля не работают. Данные — только через `qa.data`; общий для веток код — один массив шагов с условием по `qa.data`.
- Действия обвязки: `qa.q`, `qa.qa`, `qa.click`, `qa.clickText(sel, текст)`, `qa.clickNth(sel, n)`, `qa.type`, `qa.text`, `qa.visible`, `qa.waitFor(fn, мс, подпись)`, `qa.expect(условие, сообщение, детали)`, `qa.note`, `qa.shot`, `qa.events(тип)`, `qa.finished()`, `qa.payload()`.
- Адаптер (`qa.platform`): `ready()`, `next()`, `back()`, `replay()`, `hint()`, `nextEnabled()`, `screen()`, `fit()`, `kbd(on)`.
- События плеера приходят асинхронно: ждать их через `qa.waitFor`, а не проверять сразу после нажатия.
- Шаг упал — ветка останавливается, остальные шаги `not-run`; скриншот провала сохраняется.
- **Запрещено** создавать успех обходом заданий: прямой вызов завершения, запись в `store`, `postMessage`, «решено» вручную. Раннер не выполняет такой сценарий (`blocked`). Наблюдать события можно.
- Предметные действия и правильные ответы описывает только сценарий. Универсальный раннер не угадывает ответы нажатием всех кнопок.

## Новый модуль

Каркас урока такой же, как у канона HTML (`.stage`, `.stage-nav`, кнопки шапки) — подойдёт `canon-html`. Иначе:
1. Скопировать `adapters/basic.js` в `adapters/<имя>.js`.
2. Описать готовность, ожидание ведущего, «Дальше» / «Назад», переполнение, эмуляцию клавиатуры.
3. Указать адаптер в профиле модуля и в сценариях.

Раннер и агентов менять не нужно.

## Отчёты

`work/lesson-team/<run-id>/qa/<метка>/` (или `--out`):

- `report.md` и `report.json` — проверки, статусы, условия, доказательства, команды воспроизведения;
- `events.jsonl` — журнал событий плеера (реплики с маркерами, завершение, ошибки);
- `payload-<язык>-<ветка>.json` — данные `onFinished`;
- `screens.json` — строки прогона экранов;
- `shots/*.png` — скриншоты: загрузка, шаги с `shot`, провалы, клавиатура.

Каталог `work/lesson-team/` исключён из git собственным `.gitignore`.

## Что QA не доказывает

- Headless Chrome и эмуляция клавиатуры не заменяют настоящий телефон и его клавиатуру.
- Голос `fast` / `simulate` — тишина нужной длины: качество живой озвучки не проверяется.
- По умолчанию звук разрешён без касания (`--autoplay-policy`) и выключен (`--mute-audio`). Путь «до первого касания» проверяется с `--no-autoplay`.
- `screens` проверяет начальные состояния экранов. Состояния по ходу задания проверяет сценарий.
