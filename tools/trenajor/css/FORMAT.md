# Банк вопросов тренажёра CSS — как писать вопросы

Тренажёр модуля CSS (заказчик, 19.11.2026: «теперь нужно для css создать тренажёр») — так же, как тренажёр HTML
(`tools/trenajor/html/FORMAT.md` — прочитать целиком, всё оттуда действует, если ниже не сказано иначе).
LMS берёт вопросы модуля и случайно выбирает 15 на одну попытку; у каждого вопроса — номер урока (`lesson`), чтобы брать только пройденные.

Файл урока: `tools/trenajor/css/lNN.mjs` (NN = 01…17). Обычный JS-модуль, **без JSX**, `export default [ … ]`.
Проверка: `node tools/trenajor/build.mjs --check --draft css` (пока готовы не все уроки — `--draft`), без `--draft` — когда готовы все.

## Сколько (как в HTML)

- id — `css_lNN_qKK`. Сложность вопросов с выбором в уроке: примерно 4 `easy`, 5 `medium`, 2 `hard`.

## Картинка вопроса `vis` — CSS-вид

В редакторе — **CSS-файл** (вкладка `style.css`, подсветка: селектор, свойство, значение), рядом — окно Chrome с настоящей страницей:
HTML из `html` + все правила из `css`. Браузер рисует честно (iframe без скриптов).

```js
vis: { css: 'h1 {\n  color: green;\n}', html: '<h1>Kodi kafesi</h1>' }      // код CSS и страница с ним
vis: { css: 'p {\n  font-size: ___;\n}' }                                   // только код; ___ — пустое место (рамка «?»)
vis: { css: 'p {\n  color: ___;\n}', html: '<p>Salom</p>' }                 // ___ и страница: на странице правило БЕЗ строки с ___ (как сейчас)
vis: { css: '…', html: '…', goal: 'p { color: red; }' }                    // страница рисуется по goal, а не по css («сделай вот так»)
vis: { css: '…', html: '…', base: '.karta { padding: 8px; }' }             // base — невидимые ученику правила страницы (оформление-основа)
vis: { css: '…', html: '…', mark: [2] }                                     // mark — подсвеченные строки CSS
vis: { css: '…', html: '…', vw: 360 }                                       // ширина страницы в px (урок 16: 360 — телефон, 800 — ноутбук)
vis: { html: '…', base: '…' }                                               // только страница (без кода)
```

- `css`, `html`, `base`, `goal` — строка или `{ uz, ru, en }` (слова страницы — на языке ученика; селекторы, свойства, значения, классы — всегда английские/латиница).
- **На странице правило с `___` выброшено** (вся строка-объявление, где стоит `___`): ученик видит, как сейчас, а задание говорит, что нужно. Если нужно показать цель («сделай как на картинке») — `goal` с готовым CSS, тогда страница рисуется по нему.
- `base` — для красоты и узнаваемости (карточки, полки, кнопки), чтобы в видимом `css` осталось только главное для вопроса. Не прятать в `base` то, о чём вопрос.
- Код CSS: **до 8 строк**, если рядом страница; **до 10**, если только код. Строки до ~40 знаков. Правило — в несколько строк, отступ 2 пробела:
  `h1 {` / `  color: green;` / `}`. Короткое правило можно в одну строку: `h1 { color: green; }`.
- HTML страницы (`html`) — короткий кусок body (не нужен `<!DOCTYPE>`, `head`), до ~6–8 тегов. Классы и id — латиницей: `class="karta"`, `id="logo"`.
- **HTML и CSS вместе в редакторе** (урок 1 — тег `style`; урок 2 — селекторы, когда ученик должен видеть классы в HTML): HTML-вид, как в тренажёре HTML — `vis: { code: '<style>\n  .yangi { color: red; }\n</style>\n<p class="yangi">…</p>', page: true }`. Внутри `<style>` подсветка CSS. С `page: true` в коде не должно быть `___`; ответы-«пустые места» в таком коде — `vis: { code: '…___…' }` без страницы.
- Картинки: в `html` — `<img src="tog.png">`, в CSS — `background-image: url(tog.png);`. Имена-рисунки: `sher.png 🦁, mushuk.png 🐱, it.png 🐶, pingvin.png 🐧, robot.png 🤖, pitsa.png 🍕, tort.png 🎂, top.png ⚽, logo.png 🏕️ (90×90), tog.png 🏔️ (320×180)`; остальные (кроме `logo`, `tog`) — 160×120. Любое другое имя — сломанная картинка (в `img` видно alt, фон — просто нет картинки).
- Основа страницы, которую ставит тренажёр: `html { font-family: Arial; color: #111 }`, `body { margin: 12px }`, `img { max-width: 100% }`; окно белое. Фон `body` заливает всё окно, как в браузере. Рисунки-картинки растягиваются, если задать и `width`, и `height` (как фото). Пунктир целей «нажми» — `outline`, углы не скругляет.
- **`:hover` на странице не срабатывает** (окно не реагирует на мышь). Вопросы про hover (уроки 13–14): код + вопрос «что будет при наведении?» — или страница с `goal`, где правила из `:hover` уже применены, и в `ctx` сказано «sichqoncha tugma ustida» / «мышка над кнопкой».
- `transition` на картинке не виден (страница статичная). `@keyframes`/`animation` на странице **работают и двигаются** — для вопросов урока 15 лучше код без страницы или страница с `goal` (кадр «to»), чтобы не мельтешило.
- `@media` срабатывает по ширине страницы `vw` (по умолчанию она 360–520 px — зависит от экрана ученика!). Поэтому в уроке 16 **всегда** ставить `vw` (360 или 800), если на странице есть `@media`.
- `position: fixed` — относительно окна страницы; высота окна = высота страницы.
- Цвета на странице — те, что в правиле. Не давать похожих оттенков в вариантах, которые нельзя различить на глаз.

## «Впиши ответ» (`type: 'input'`) в CSS

Ответ — **одно слово кода**: свойство (`color`, `font-size`, `padding`), значение (`green`, `center`, `flex`, `space-between`, `bold`),
число с единицей (`20px`, `50%`, `2s`), селектор (`.karta`, `#logo`, `h1`). Сравнение LMS мягкое только в регистре, пробелах по краям и «;»
в конце, но **пробелы внутри не убираются**: `20 px` — не то же, что `20px` (и в CSS это ошибка). Поэтому:

- просить одно слово; не просить «свойство: значение» целиком;
- в `answer` — все честные записи: `['20px']` (не `'20 px'`), цвет — `['red']`, если просим название; hex — `['#ff0000', '#f00']`, если оба верны и вопрос это допускает;
- `mono: true` — ответ это код.

## «Собери» (`type: 'build'`) в CSS

Собирается объявление или правило на месте `___` в `css`: `vis: { css: 'h1 {\n  ___\n}' }`, `pieces: ['color', ': ', 'green', ';']` (склеиваются как написаны).
Страницы у «собери» нет (`html` не ставить). Кусочки уникальны (не два одинаковых `;`) и порядок единственный.

## «Найди ошибку» (`type: 'bug'`) в CSS

`vis: { css: '…', html: '…' }` — страница показывает сломанный результат (браузер выбросил плохую строку). Ошибка — в одной строке:
опечатка в свойстве, `=` вместо `:`, число без `px`, пробел в `20 px`, нет `:`, значение не того свойства (`color: center`), нет точки у класса
в селекторе. «Нет `;`» — ошибка в той строке, где `;` потерялась (браузер ломает и её, и следующую). Код — до 7 строк (с `html` — до 6).

## «Нажми на странице» (`type: 'tap'`) в CSS

`data-t="…"` — в `html` у 3–5 элементов; вопрос — про то, что сделало правило: «На какой элемент подействовало правило `.yangi`? Нажми на него»,
«У какой карточки есть тень?», «Какой блок стоит position: absolute?». Цели не вложены друг в друга, заметного размера.
Пунктир вокруг целей рисует тренажёр (outline) — не давать вопросов, где ответ надо узнать по outline.
