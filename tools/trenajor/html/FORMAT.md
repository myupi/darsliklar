# Банк вопросов тренажёра HTML — как писать вопросы

Тренажёр модуля HTML (заказчик, 18.11.2026): LMS берёт вопросы модуля (сейчас 165) и случайно выбирает 15 на одну попытку.
Вопросы — по урокам 1–9 курса HTML; у каждого вопроса — номер урока (`lesson`), чтобы LMS могла выбирать только из пройденных.
Образец формата — математический тренажёр LMS Junior (`trenajor/obrazec-matematika/`), но вопросы и облик — наши.

Файл урока: `tools/trenajor/html/lNN.mjs` (NN = 01…09). Обычный JS-модуль, **без JSX**, `export default [ … ]`.
Сборщик `node tools/trenajor/build.mjs` превращает их в JSON-банк и проверяет.

## Сколько

- Вопросы с выбором: уроки 1–8 — по **11**, урок 9 (финальный проект, повторение всего курса) — **12**. Всего 100.
- Плюс «впиши ответ» (3, в уроке 9 — 4) и игровые: 2 «собери», 1 «найди ошибку», 1 «нажми на странице» (в уроке 9 — 2, 2, 1) — разделы в конце.
- Сложность в уроке: примерно 4 `easy`, 5 `medium`, 2 `hard`.

## Один вопрос

```js
{
  id: 'html_l04_q01',            // html_lNN_qKK, KK по порядку с 01
  difficulty: 'easy',            // easy | medium | hard
  tags: ['href'],                // 1–2 главных тега/понятия вопроса (латиницей)
  mono: false,                   // true — варианты ответа это код (покажутся моноширинным)
  sort: false,                   // true — варианты показать в естественном порядке (числа, номера строк); иначе перемешает сборщик
  vis: null,                     // картинка вопроса или null, см. ниже
  uz: { ctx: '…', q: '…', opts: ['ВЕРНЫЙ', 'неверный', 'неверный', 'неверный'], why: '…' },
  ru: { ctx: '…', q: '…', opts: [ … ], why: '…' },
  en: { ctx: '…', q: '…', opts: [ … ], why: '…' },
}
```

- `ctx` — одна короткая фраза-ситуация (до ~90 знаков): что происходит на экране, чего хотим. Можно `''`.
- `q` — сам вопрос, одна фраза (до ~70 знаков), с вопросительным знаком.
- `opts` — **ровно 4** варианта, **первый — верный** (сборщик сам расставит верные по местам A–D поровну). Варианты на трёх языках — в одном порядке.
- `why` — пояснение после ответа, 1–2 предложения (до ~170 знаков). Показывается и при верном, и при неверном ответе, поэтому **без похвалы** («Barakalla», «Верно!» — нельзя) и без «вы ошиблись»: просто объясняет, почему верный ответ верный.

## Картинка вопроса `vis`

Тёмный редактор кода (как в уроках) и/или окно Chrome с настоящей страницей (iframe без скриптов — HTML рисует сам браузер).

```js
vis: { code: '<a href="sport.html">Sport</a>', mark: [1] }            // только код; mark — номера строк для подсветки
vis: { code: '<h1>Salom</h1>\n<p>Matn</p>', page: true }               // код и страница из этого же кода
vis: { page: '<h1>Salom</h1><p>Matn</p>' }                             // только страница
vis: { code: '<img ___="pingvin.png">' }                               // ___ — пустое место (рамка «?»)
```

- `code` и `page` могут быть строкой или объектом `{ uz, ru, en }`, если в коде есть слова (тексты страницы — на языке ученика, теги и атрибуты — всегда английские).
- В коде с `page: true` не должно быть `___`.
- Код: **до 8 строк**, если рядом страница; **до 10**, если только код. Строки короткие (до ~40 знаков), отступ — 2 пробела.
- Полный документ (`<!DOCTYPE html>`, `<html>`, `<head>`, `<title>`) — только где вопрос про него (урок 1 и 9); иначе — кусок из body.
- Картинки: `src` с именами `sher.png 🦁, mushuk.png 🐱, it.png 🐶, pingvin.png 🐧, robot.png 🤖, pitsa.png 🍕, tort.png 🎂, top.png ⚽, logo.png 🏕️, tog.png 🏔️` показываются рисунком; любое другое имя — сломанная картинка с alt (как в браузере).
- Ссылки на странице не открываются; формы не отправляются; `:hover` нет.
- Картинка нужна, если без неё вопрос непонятен или с ней интереснее. Примерно у 2/3 вопросов урока — `vis`, у остальных — нет.

## Что проверяем

- Каждый вопрос проверяет **одну главную мысль** урока; задание называет цель («Ссылка должна вести на страницу Sport»), а не диктует код.
- Только материал этого урока **и прошлых** (урок 4 может использовать p и h1, но не img). Финальный урок 9 — всё сразу: целая маленькая страница, части сайта, ошибки из разных уроков.
- Типы вопросов чередовать: «что покажет браузер?», «чего не хватает в коде?», «какая строка верна?», «что вписать в пустое место?», «как называется…», «найди ошибку», «что нужно изменить, чтобы…».
- Неверные варианты — **настоящие ошибки учеников** (перепутанные теги, забытый закрывающий тег, атрибут не в том теге, значение без кавычек), правдоподобные и **не короче верного**. Не «все ответы верны», не шуточные варианты.
- У каждого вопроса **однозначный** ответ; вкусовых вопросов нет.
- Не повторять вопросы тестов курса (`tools/webtest/html/lNN.jsx`, по 5 на урок) — та же тема можно, но другая ситуация и другой код.
- Внутри урока не повторять одну и ту же ситуацию с разными числами.
- Ученикам 11–14 лет, проходят сами. Коротко и ясно, ситуации из жизни: сайт кафе, школы, игры, зоопарка, лагеря, футбольной команды.

## Языки

- **Узбекский — первым и живой речью**, не переводом с русского. Перед работой прочитать навык `.claude/skills/uzbekcha/SKILL.md` и словарь `references/lugat.md`. Обращение на **«Siz»**. Апостроф — **только ASCII `'`** (o', g', ma'lumot), никаких ‘ ’ ʻ. Названия тегов — латиницей как в коде (`h1`, `a` tegi, `href` atributi).
- **Русский** — на «ты», без рода (не «ты нашёл/нашла»; «получилось», «у тебя»).
- **Английский** — простой, без сленга.
- Смысл трёх языков совпадает; варианты — в одном порядке.
- Кавычки в текстах: в uz/ru — «ёлочки», в en — “…”. Внутри JS-строки в одинарных кавычках апостроф `'` экранировать (`\'`) или брать строку в двойные кавычки.

## Вопрос «впиши ответ» (`type: 'input'`, 18.11.2026)

Ученик не выбирает, а сам вписывает короткий ответ с клавиатуры: имя тега, атрибут, тег целиком, значение, число.
В уроках 1–8 — по **3** таких вопроса (номера `q12`, `q13`, `q14`), в уроке 9 — **4** (`q13`…`q16`). Пишутся в конец того же файла `lNN.mjs`.

```js
{
  id: 'html_l04_q12',
  type: 'input',                 // вопрос с полем ввода
  difficulty: 'easy',
  tags: ['href'],
  mono: true,                    // ответ — код (поле моноширинным шрифтом); для числа — false
  answer: ['href'],              // принимаемые ответы: первый — образец, его покажут как верный; остальные — равноценные записи
  vis: { code: '<a ___="sport.html">Sport</a>' },   // как у вопросов с выбором; ___ — то место, куда вписывают
  uz: { ctx: '…', q: '…', why: '…' },             // opts нет
  ru: { ctx: '…', q: '…', why: '…' },
  en: { ctx: '…', q: '…', why: '…' },
}
```

- Ответ **один и однозначный**, короткий (до ~20 знаков), одинаковый на всех языках: код или число. Слова на языке ученика ответом не делать.
- В вопросе сказано, **что именно и в каком виде** вписать: «Bo'sh joyga atribut nomini yozing», «Впиши закрывающий тег целиком», «Сколько…? Напиши числом».
- `answer` — все честные записи верного ответа: `['h1', '<h1>']` если просим имя тега и ученик может написать его в скобках; для закрывающего тега — `['</p>']`; для числа — `['3']`.
- Сравнение мягкое (его делает LMS по README): регистр не важен, пробелы по краям и вокруг `<`, `>`, `/`, `=` не важны, «умные» кавычки равны обычным, `;` в конце не важна. Поэтому `<H1>`, `< h1 >` и `<h1>` писать в `answer` по отдельности не нужно.
- `why` — как у остальных: без похвалы, объясняет, почему ответ такой (показывается и при верном, и при неверном ответе вместе с образцом ответа).
- Лучше всего — код с `___` (пустое место видно рамкой «?») и вопрос «что вписать?».

## Игровые вопросы: «собери», «найди ошибку», «нажми на странице» (18.11.2026)

Чтобы попытка не была 15 раз «вопрос + 4 варианта» (заказчик, 18.11.2026: «тренажёры не должны быть одинаковыми»). В каждом уроке —
**2 «собери»** (`type: 'build'`), **1 «найди ошибку»** (`type: 'bug'`), **1 «нажми на странице»** (`type: 'tap'`); в уроке 9 — 2, 2 и 1.
Номера — дальше по порядку: в уроках 1–8 `q15`, `q16` — build, `q17` — bug, `q18` — tap; в уроке 9 `q17`, `q18` — build, `q19`, `q20` — bug, `q21` — tap.
У всех трёх в языках только `ctx`, `q`, `why` (вариантов `opts` нет); `why` — как везде: без похвалы, объясняет ответ.

### «Собери из кусочков» (`type: 'build'`)

Ученик нажимает кусочки кода по порядку — строка собирается прямо в редакторе на месте `___`. Клавиатура не нужна.

```js
{
  id: 'html_l04_q15', type: 'build', difficulty: 'medium', tags: ['a', 'href'],
  pieces: ['<a', ' href="sport.html"', '>', { uz: 'Sport', ru: 'Спорт', en: 'Sport' }, '</a>'],   // ВЕРНЫЙ порядок
  extra: ['<p', ' src="sport.html"'],                                                         // лишние кусочки, 1–3
  vis: { code: '<nav>\n  ___\n</nav>' },        // код с ОДНИМ ___ — сюда встаёт собранное (без vis — одна пустая строка)
  uz: { ctx: '…', q: "Bo'laklarni tartib bilan bosib, Sport havolasini yig'ing", why: '…' }, ru: { … }, en: { … },
}
```

- Кусочки склеиваются **как написаны**, поэтому пробел перед атрибутом пишется в самом кусочке (`' href="x"'`). На кнопке кусочек показан без пробелов по краям.
- Всего кусочков (верные + лишние) — **4–8**, каждый до ~18 знаков. Тексты кусочков в вопросе **не повторяются** (иначе два одинаковых — неясно, какой нажали).
- Верный порядок — **единственный**: не давать кусочков, которые можно честно переставить (два атрибута подряд — склеить в один кусочек).
- Лишние — настоящие ошибки: не тот тег, атрибут не того тега, закрывающий тег без `/`.
- Слова страницы — на языке ученика (`{ uz, ru, en }`), теги и атрибуты — английские.
- В `q` сказано, что собрать: «Собери ссылку на страницу Sport».

### «Найди ошибку» (`type: 'bug'`)

Код из 3–7 строк, в **одной** строке ошибка — ученик нажимает на эту строку.

```js
{
  id: 'html_l04_q17', type: 'bug', difficulty: 'medium', tags: ['href'],
  line: 2,                                       // номер строки с ошибкой (с 1)
  vis: { code: '<nav>\n  <a href=sport.html">Sport</a>\n  <a href="kino.html">Kino</a>\n</nav>', page: true },
  uz: { ctx: '…', q: "Qaysi qatorda xato bor? Shu qatorni bosing", why: '…' }, ru: { … }, en: { … },
}
```

- Ошибка — **в одной строке однозначно** (опечатка в теге, нет кавычки или `=`, атрибут в закрывающем теге, `src` у `a`, `/` не там). Не брать ошибки, которые «размазаны» по двум строкам (забытый закрывающий тег, который можно поставить в разные места).
- Остальные строки — без ошибок и без подозрительных мест.
- `page: true` можно, если сломанный результат подсказывает (всё стало жирным, картинка сломалась). `mark` не ставить — выдаст ответ.
- Код — до 7 строк (с `page: true` — до 6), строки короткие.

### «Нажми на странице» (`type: 'tap'`)

В окне Chrome — страница; ученик нажимает на то место, которое сделал нужный тег. Места, на которые можно нажать, помечены `data-t` — на странице они обведены пунктиром.

```js
{
  id: 'html_l08_q18', type: 'tap', difficulty: 'easy', tags: ['nav'],
  answer: 'nav',                                 // data-t верного места
  vis: { code: '…', page: true },                // или только page: '…'
  uz: { ctx: '…', q: "Sahifada nav tegi yasagan qismni bosing", why: '…' }, ru: { … }, en: { … },
}
```

- `data-t="…"` (латиницей, без пробелов) — у **3–5** элементов страницы; один из них — верный (`answer`). Значения `data-t` — одинаковые на всех языках.
- Элементы-цели **не вложены** друг в друга и заметного размера (абзац, заголовок, список, картинка, кнопка, меню), а не одно слово внутри строки.
- В коде (`page: true`) атрибуты `data-t` ученику не показываются — тренажёр их прячет.
- Вопрос — про то, что делает тег на странице: «Нажми на то, что сделал тег h2», «Где на странице `<ol>`?», «Какая картинка сломана? Нажми на неё».
