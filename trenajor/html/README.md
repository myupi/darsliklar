# Тренажёр модуля HTML — загрузка в LMS

В LMS загружаются **два файла**:

1. `trenajor_html_v1.jsx` — React-компонент тренажёра. Импортирует только `react`.
2. `savollar_banki_html_v1.json` — банк из 165 вопросов по урокам 1–9 модуля HTML (`block_id: "html"`): 100 с выбором ответа (`single_choice`), 28 «впиши ответ» (`text_input`) и 37 игровых — «собери из кусочков» (`assemble`, 18), «найди ошибку» (`find_error`, 10), «нажми на странице» (`tap_page`, 9).

Оба файла собирает `node tools/trenajor/build.mjs html` — руками их не править.

## Контракт с LMS

Такой же, как у тренажёра математики:

```jsx
<Trainer attempt lang busy onAnswer onFinished onRestart onExit />
```

- `attempt` — попытка от LMS: `kind` (`reward` / `practice`), `status` (`in_progress` / `finished`), `question_count` (15),
  `questions` (открываются по одному: ответов + 1; у неотвеченного `correct_answer: null`), `answers` (`{ question_id, option_id, correct }`),
  `started_at`, `finished_at`, `coins_per_correct`, `points_per_correct`, `correct_count`, `reward` (`{ coins, points }`), `reward_date`.
- `lang` — `uz`, `ru` или `en`.
- `busy` — LMS сохраняет ответ: кнопки неактивны.
- `onAnswer(questionId, optionId)`, `onFinished()` — обязательны. Ответы, итог и награду считает и хранит LMS. Если вызов вернул отклонённый Promise, тренажёр пишет «Saqlab bo'lmadi. Yana bir bor bosing.».
- `onRestart` — кнопка «Yana mashq qilish» на итоговом экране. Не передан — кнопки нет.
- `onExit` — крестик в левом верхнем углу и кнопка «Chiqish» на итоговом экране. Не передан — их нет.
- Вводный экран («Qanday ishlaydi», «Boshlash» / «Mashq qilish») — только в новой попытке (`answers` пустой).
- Высота: тренажёр занимает место от своего верха до низа окна, без прокрутки. Картинка вопроса берёт оставшееся место;
  на маленьком телефоне экран становится плотнее, а если код и страница вместе не читаются — над ними переключатель «Kod / Natija».
  После ответа на маленьком экране картинка может спрятаться, чтобы было видно пояснение.
- Голоса нет (как у тренажёра математики): тексты короткие, ученику 11–14 лет.
- **Миссия «Сайт строится»**: рядом с полосой прогресса — маленький сайт из 15 блоков. Каждый верный ответ строит свой блок
  («+ Menyu» в отклике), неверный оставляет дыру. На итоговом экране — сайт ученика целиком; нажатие на дыру показывает тот вопрос,
  ответ ученика, верный ответ и пояснение. Всё это тренажёр считает сам из `attempt.answers`, LMS ничего добавлять не нужно.

## Вопросы без вариантов A–D — что нужно от LMS

Кроме `single_choice` в банке четыре типа, у которых ответ — **строка**. Правило для LMS у всех одно: сохранить строку и сравнить её мягко (`norm`, ниже)
с `accepted_answers` вопроса.

| `question_type` | Что делает ученик | Что приходит в `onAnswer(questionId, …)` | `options` |
|---|---|---|---|
| `text_input` | вписывает ответ с клавиатуры | вписанный текст | `[]` |
| `assemble` | нажимает кусочки кода по порядку, строка собирается в редакторе | id кусочков по порядку через запятую: `"c,a,d"` | кусочки (до 8) |
| `find_error` | нажимает строку кода с ошибкой | номер строки: `"3"` | `[]` |
| `tap_page` | нажимает место на странице в окне браузера | метка места: `"footer"` | `[]` |

У всех четырёх `correct_answer` — образец (тренажёр покажет его после неверного ответа), `accepted_answers` — все верные записи.
LMS сохраняет ответ как `{ question_id, option_id: строка, correct }` (у `text_input` ещё `answer_text: строка`).

### «Впиши ответ» (`text_input`)

Ученик не выбирает вариант, а сам вписывает короткий ответ с клавиатуры (имя тега, атрибут, тег целиком, число) и жмёт «Tekshirish» (или Enter).

- В банке: `question_type: "text_input"`, `options: []`, `correct_answer` — образец ответа (его тренажёр покажет после неверного ответа), `accepted_answers` — все верные записи.
- Тренажёр вызывает `onAnswer(questionId, текст)` — вторым аргументом приходит **вписанный текст**, а не id варианта.
- LMS сохраняет ответ как `{ question_id, option_id: текст, answer_text: текст, correct }` (тренажёр показывает `answer_text`, а если его нет — `option_id`) и считает `correct` **мягким сравнением**:

```js
const norm = (s) => String(s ?? '').normalize('NFKC')
  .replace(/[‘’ʻʼ`´]/g, "'").replace(/[“”«»„]/g, '"')      // «умные» кавычки = обычные
  .trim().replace(/\s+/g, ' ')                              // пробелы по краям и двойные
  .replace(/\s*([<>/=])\s*/g, '$1')                         // пробелы вокруг < > / =
  .replace(/;+$/, '')                                        // «;» в конце
  .toLowerCase();                                            // регистр
const correct = question.accepted_answers.map(norm).includes(norm(text));
```

- Пока ответ не сохранён, `correct_answer` и `accepted_answers` вопроса тренажёру не нужны (как у вопросов с выбором — LMS может их не отдавать).
- Так же (`accepted_answers.map(norm).includes(norm(строка))`) сравниваются ответы `assemble`, `find_error`, `tap_page`.
- Если LMS пока не умеет какие-то из этих типов, она может их не выбирать (фильтр по `question_type`) — тренажёр работает с любой смесью.
- LMS выбирает вопросы случайно; чтобы попытка была разнообразной, хорошо брать в 15 вопросов разные типы (например, не меньше 3 игровых и 2 «впиши»).

## Банк вопросов

- 165 вопросов: уроки 1–8 — по 18 (11 с выбором, 3 «впиши ответ», 2 «собери», 1 «найди ошибку», 1 «нажми на странице»), урок 9 (финальный) — 21 (12, 4, 2, 2, 1). У каждого `lesson` (1–9) и тег `darsNN`.
- **LMS выбирает по блоку** (`block_id: "html"`, 15 случайных из 165). Чтобы ученик получал вопросы только из пройденных уроков, LMS может фильтровать по `lesson` — поле есть у всех вопросов.
- У `assemble` кусочки в банке уже перемешаны (и никогда не лежат готовым ответом подряд).
- У вопросов с выбором верный ответ стоит на местах A–D поровну (25 / 25 / 26 / 24, и в каждом уроке тоже), так что «жать всегда A» не работает.
- Тексты на трёх языках: `uz` (на «Siz»), `ru` (на «ты»), `en`. `context` — строка-ситуация над вопросом, `solution_explanation` — пояснение после ответа.
- Картинка вопроса `vis` — строка `@htmlvis:{…}` (код в редакторе и/или страница в окне браузера) или `null`. Тренажёр сам её рисует.
- `status: "Approved"` стоит, чтобы LMS могла выбирать вопросы; **методист вопросы ещё не проверял**.
- Поля `grade` нет: у модуля HTML нет класса. Если LMS его требует — нужно договориться, что ставить.

## Проверка

`node tools/trenajor/build.mjs --check html` — число вопросов, 4 варианта на трёх языках, уникальные id, апостроф `'` в узбекском, «ты» в русском, пояснение без похвалы, размер кода, распределение верных ответов.
Просмотр — в просмотрщике уроков, раздел **«Тренажёр»** (`npm run dev`, вкладка «Тренажёр» в боковой панели): попытка с эмуляцией LMS
(язык, экран, режим с наградой или без, пройденные уроки, 15 или 5 вопросов, сохранение сразу / медленно / с ошибкой, onExit и onRestart, журнал
вызовов) и все вопросы банка по урокам — карточка с верным ответом и пояснением, рядом вопрос вживую. Отдельно: `/trainer.html?t=html&lang=uz`
(параметры — в шапке `src/trainer/main.jsx`). Замер раскладки всех вопросов — `tools/trenajor/sweep.js` (как запускать — в его шапке).

## Исходники

- Тренажёр — `tools/trenajor/trenajor.jsx`, вопросы — `tools/trenajor/html/l01.mjs … l09.mjs`, правила вопросов — `tools/trenajor/html/FORMAT.md`.
- В исходнике вопроса верный вариант — первый; сборщик сам расставляет верные по местам.
- Методисту на заметку: «option tegisiz», «Ko'zi ojiz bola» (l08_q07) — слова вне словаря курса; l02_q08 опирается на «h1 обычно один» (так в уроке, строгого правила HTML нет).
