# Darsliklar

Просмотрщик интерактивных JSX-уроков для детей (Vite + React 18). Уроки — самодостаточные файлы в `lessons/`, просмотрщик открывает их в iframe с эмуляцией платформы `@lesson/runtime`. Подробности для пользователя — в README.md.

**Общение — по-русски.** Заказчик пишет кратко и по-русски; отвечать по-русски, без лишних вопросов, проверять самому в браузере и показывать скриншоты.

## Где лежат уроки

- Урок: `lessons/<курс>/<NN>-<slug>.jsx`. `NN` — двузначный номер из плана курса; по нему файл привязывается к плану. `slug` брать из `_course.js`.
- Практика к уроку: `lessons/<курс>/<NN>p-<slug>.jsx` (буква `p` после номера). В списке просмотрщика стоит сразу после своего урока; включается флагом `practice: true` в `_course.js`, финальному проекту (`final: true`) практика не ставится. Своё название практики — `practiceTitle` в строке урока.
- План курса: `lessons/<курс>/_course.js` (title, subtitle, short, color, order, lessons[{ n, slug, title, topics, final? }]).
- Новая тема → строка в `_course.js`. Новый курс → новая папка с `_course.js`.
- `lessons/_reference/` — эталоны других курсов. Только читать, не править.
- `lessons/test/` — «Тестовые уроки», песочница заказчика для экспериментов. Плана нет (`sandbox: true`): любой `.jsx` здесь сразу виден в списке как готовый. Канон сюда не переносится и не проверяется.

## Правила для файла урока

- Один файл = один урок, `export default` корневой компонент.
- Пропсы: `{ studentName, lang, ttsApiBase, voiceGender, onFinished }`; `onFinished(payload)` — ровно один раз. Дев-пропсы `startAt`, `onExit` платформа не передаёт.
- Импорты: только `react`. Озвучка — движок канона: `GET {ttsApiBase}/api/tts?text=<маркер языка + реплика>&g=f&lesson_id=…&lesson_name=…` (id и название — из `META` урока), без `ttsApiBase` — голос браузера, без него — текст.
- Правила текста озвучки (сервис ElevenLabs): маркер `[O'zbekcha tallaffuz]` / `[Русское произношение]` / `[English pronunciation]` и тег эмоции (`[happy]`, `[reassuring]`, `[embarrassed]` … — по смыслу реплики, без автоматического смеха; `emoTag` в каноне, правка 21.10.2026) ставит движок; названия тегов в речи — по-английски во всех языках (`body`, не «бади»); имени ученика в репликах нет; символов `% / ² + = ×` в репликах нет — только слова; реплика — полные предложения, до ~25 с (60–80 слов); экран-объяснение, где без подробного рассказа понятие не объяснить, — 120–220 слов (~1–1,5 мин; заказчик, 03.11.2026).
- Эталоны Кибербеза и «Алгоритмов» говорят через `@lesson/runtime` — его эмуляция в `src/runtime` остаётся для них.
- API эмуляции описан в шапке `src/runtime/index.js` (`@lesson/runtime`) и `tools/vite-tts-service.mjs` (сервис озвучки по `ttsApiBase`). Если урок не работает в просмотрщике, чинится урок, а не эмуляция. В эмуляцию добавляется только то, что реально умеет платформа.

## Качество урока (заказчик, 15.10.2026)

Касается всех уроков — существующих и будущих. Цель: ученик минимально затрудняется, максимально понимает тему, ему не скучно весь урок и он хочет заниматься дальше. Интерактивность при этом не теряется.

- Один экран — одно действие. Если в задании два дела, это два экрана.
- Задание называет конкретную вещь на экране («Нажми «Правила»»), а не абстракцию («часть раздела»). Термин сначала показывается, потом используется.
- Результат действия виден сразу: живое превью рядом с кодом, без скрытых переключателей «Код / Результат» и без лишних «Проверить». Исключение (заказчик, 10.11.2026): **в практиках на телефоне** — переключатель «Kod / Natija», где в редакторе от 7 строк (`useViewToggle` во всех наборах практик: `tools/amaliyot1…9`, `tools/cssp`); после верного ответа он сам показывает результат, после ошибки и подсказки — код; на ноутбуке и планшете видно то и другое. Образец третьей ступени при открытой клавиатуре прячется и возвращается, когда она закрыта (`is-kbd`).
- У каждого задания однозначный ответ. Задания «на вкус» (где граница темы, что важнее) — только как мнение без проверки.
- Открытое задание (песочница, своя страница) — только с ясной целью и видимым условием «готово».
- Новое — по шагам: показать → повторить → сделать самому. Лучше лишний простой экран, чем один перегруженный.
- Не скучно: история и цель, чередование механик, видимый прогресс, быстрая реакция на каждое действие.
- Проверка — пройти урок глазами ученика на телефоне: на каждом экране сразу ясно, что делать, и ничего не уходит за край.
- Реплики Коди живые и интересные (заказчик, 26.10.2026: «скучные реплики… нужно интересовать ученика»): вопрос к ученику, приглашение, интрига, реакция на экран — «Agar veb-sahifa odam bo‘lsa, nima deb o‘ylaysiz, u qanday ko‘rinardi? Keling, shuni ko‘ramiz». Смысл и действие — коротко и точно; правила и примеры — `etalon-bumazhnaya.md`, раздел 6.
- Экран-объяснение (заказчик, 23.10.2026) — показ без действий ученика: вещи меняются сами под речь Коди, после каждой короткой фразы, чтобы не было ощущения АФК (`useKzDemo` в `tools/kollazh/kollazh-kit.jsx`). **Руки, которая «нажимает», и кнопок-обманок на объяснениях нет — никогда** («очень некрасиво… не хочу, чтобы это снова повторялось»). Вещь загорается и меняется сама: штамп, влёт, перелёт. Хук, «сам делает», закрепление, вывод и практики — действия ученика.

## Проверка после создания урока

1. Запуск: `preview_start` с именем `darsliklar` (или `npm run dev`, порт 5173).
2. Открыть урок: `http://localhost:5173/?lesson=<курс>%2F%23<n>&voice=fast` («Быстро» — тихие короткие паузы для прогона).
3. Отдельный экран без просмотрщика: `/player.html?file=<курс>/<файл без .jsx>&lang=ru&voice=fast&start=<N>`.
4. Журнал справа: без ошибок, у реплик есть маркер языка, `onFinished` вызван ровно один раз. Голос стартует после первого касания внутри урока (до него реплики печатаются) — кликни по уроку.
5. Нет переполнения `.stage-content` на 360×640, 375×740, 1280×720 и 1440×900 на трёх языках — прогон `tools/layout-sweep.js` в браузерной панели (как запускать — в шапке файла и в навыке). Отдельно — состояния по ходу задания: подсказка, все шаги, готовая страница, `is-kbd` при `--vvh: 330px` (открытая клавиатура телефона). В просмотрщике есть режим «Телефон с открытой клавиатурой» (кнопка с клавиатурой в «Экран», `device=phoneKbd`; 10.11.2026): телефон 390×844, над нарисованной клавиатурой видно 390×460, урок получает `is-kbd` и `--vvh` — смотреть глазами. Запас высоты меньше ~60 px на 360×640 — экрану `Stage voiceTop` (прячет Коди только на телефоне; на ноутбуке экран должен влезать с Коди).
