# Проверка урока (шаг Д)

Использовать инструменты, которые реально есть в среде:
- браузерная панель: `preview_start`, `javascript_tool`, `computer`, `resize_window`;
- Bash.

Не утверждать, что проверено в браузере, если проверена только сборка. Автоматическая проверка размеров не заменяет взгляд глазами ученика.

## 1. Сборка и код

```bash
npm run canon:check
npx vite build --outDir <scratchpad>/dist --emptyOutDir
npx --yes eslint@8 --no-eslintrc --no-inline-config --parser-options=ecmaVersion:2022,sourceType:module,ecmaFeatures:{jsx:true} --rule '{"no-undef":"error"}' --env browser,es2022 <урок.jsx>
```

- `npm run canon:check` — канон в уроках курса дословный (для тестового урока не нужен: сборщик проверяет канон сам).
- `npx vite build` — урок собирается.
- `eslint` с правилом `no-undef` — неопределённых имён ниже пометки «УРОК» нет.

Плюс текстовые проверки по `C`:
- запретные слова: «ошибк», «неправильн», «xato», «noto‘g‘ri»;
- символы `% / ² + = ×` в репликах (ключи `SPOKEN`);
- имя ученика в репликах;
- каждая строка — `L3` с тремя непустыми языками.

## 2. Открыть урок

- **Сервер:** `preview_start` с именем `darsliklar` (порт 5173).
- **Просмотрщик** (журнал, `onFinished`, payload):
  `http://localhost:5173/?lesson=<курс>%2F%23<n>&lang=ru&voice=fast&start=`
  Пустой `start=` сбрасывает запомненный экран.
- **Один экран без просмотрщика:**
  `/player.html?file=<курс>/<файл без .jsx>&lang=uz&voice=fast&start=<N-1>`
- **`voice=fast`** — тихие короткие паузы для прогона. Голос стартует после первого касания внутри урока, до этого реплики печатаются.

## 3. Помощник `scripts/qa.js`

В `javascript_tool` на открытой странице урока:

```js
const { default: Q } = await import('/.claude/skills/novyy-urok/scripts/qa.js?' + Date.now());
await Q.ready();                      // Коди договорил
Q.state();                            // { screen, ask, page, code, next, fit }
Q.click(Q.btn('ol')); await Q.ready();
Q.type(Q.q('.src .tk-input'), 'вода'); await Q.sleep(1500);   // автозасчёт ~1 с
await Q.keys('</ol>'); Q.check();
await Q.kbd(true); Q.inputVisible(); await Q.kbd(false);       // открытая клавиатура
await Q.next();
```

**Длинный проход** (больше ~40 с) — фоном, потом опрос:

```js
Q.bg(async (log) => { /* шаги */ log('s3'); });
// следующим вызовом: await Q.sleep(40000); __qa.bgState()
```

**Ограничения:**
- После `location.href = …` модуль импортировать заново.
- Во время прогона не править файлы проекта: Vite перезагрузит страницу.

## 4. Что пройти — для каждого экрана

| Ветка | Что смотреть |
|---|---|
| Вступление | Касания заперты, пока Коди объясняет; строка задания появилась и не прыгает; ясно, что и где делать |
| Верный ответ | Результат виден сразу (превью, анимация); реплика называет освоенное; «Дальше» открывается после разбора |
| Неверный ответ | Реакция называет причину; подсказка встала на место задания; экран не вырос; нет красного и запретных слов |
| Ступени 1 → 2 → 3 | Каждая ступень своя и про это задание; после третьей — новая короткая задача, если она в сценарии |
| Сужение выбора | Неверное гаснет; после двух промахов светится верное; застрять нельзя |
| Бездействие | Через ~7–8 с светодиоды на месте действия; лампочка повторяет задание |
| Многошаговое | Все шаги; счётчик «N/M»; промежуточные шаги не запирают касания голосом |
| «Назад» | Вернуться на решённый экран: показано решённое состояние, не игра заново |
| «Повторить» | Экран с первой реплики; стёрты только его данные, работа ученика (проект, страница) цела |
| Открытая клавиатура | На экранах с полем: `Q.kbd(true)` при 360×640 — поле и кнопки символов над клавиатурой, задание видно |
| Без звука | Открыть с `&voice=off`: урок проходится, реплики печатаются, гейты открываются |

## 5. Размеры и языки

**Автоматический прогон начальных состояний**: 4 размера × 3 языка, фоном.

```js
const m = await import('/tools/layout-sweep.js?' + Date.now());
m.sweepBg({ lessons: [{ file: '<курс>/<файл без .jsx>', screens: <число экранов> }] });
// через ~2–3 минуты: m.result() → { done, runs, problems: [] }
// запас высоты (решение о voiceTop):
// await m.sweep({ lessons, langs: ['uz','ru','en'], sizes: [[360, 640]], slack: true }) → rows[].slack
```

`problems` должен быть пустым. Запас меньше ~60 px на 360×640 или экран растёт по ходу задания — `voiceTop`. Запас больше ~110 px с Коди — Коди можно оставить и на телефоне.

**Состояния по ходу задания** — вручную с `Q.fit()` на 360×640 по-узбекски (самые длинные тексты):
- подсказка третьей ступени;
- все шаги;
- готовая страница;
- открытая клавиатура.

Затем выборочно — 375×740 и 1280×720.
- Размер ставится `resize_window`. В конце сбросить: `preset: 'desktop'`.
- Перед переходом на новый размер — перезагрузка страницы.

## 6. Полный проход и завершение

В просмотрщике пройти урок от первого до последнего экрана: фоном через `Q.bg`, урок внутри iframe — помощник это учитывает. Затем `get_page_text`, журнал справа:
- `onFinished: вызван 1 раз`, ошибок 0;
- `answers` — строки на экранах, где ученик отвечал, с осмысленными `type`, `firstTry`, `attempts`;
- `artifact` — работа ученика, `html` корректный;
- у реплик маркер языка и тег эмоции (`[excited]`, `[friendly]` …); теги в речи — английскими словами (`body`, `U L`), без транслитераций вроде «бади».

## 7. Глазами ученика

Скриншоты на 375×740 (`computer` → `screenshot`) ключевых экранов:
- крючок;
- показ;
- трудное задание с подсказкой;
- перенос;
- свой проект;
- итог.

На каждом спросить себя:
- сразу ли понятно, что делать?
- видно ли, что изменилось?
- нет ли лишнего текста?
- не скучно ли?

Найденное исправить и перепроверить затронутые экраны: сборка → экран → размеры.

## 8. Отчёт заказчику

По-русски, кратко:
1. Что сделано: тема, замысел одной фразой, дуга экранов, файл (ссылка), подключение.
2. Решения, которые стоит знать: отступления от сценария и почему, новые цвета или теги.
3. Что проверено и как: проход, ветки, размеры, языки, клавиатура, `onFinished`, без звука.
4. Что не проверено: например, живой голос сервиса, реальный телефон.
5. Скриншоты.

Обновить `docs/plan-peredelki.md` (статус). Коммит и пуш — только по просьбе.
