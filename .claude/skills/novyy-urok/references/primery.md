# Примеры решений и анти-примеры

**Это примеры, а не шаблоны.** Они показывают, *почему* решение сработало или не сработало. Повторять их в новом уроке не нужно. Брать принцип, а не форму.

## Что сработало в уроке 2 (главный эталон)

| Экран урока 2 | Приём | Почему работает |
|---|---|---|
| s1 «Поиск» | Найти факт в «стене текста», потом тот же факт на размеченной странице | Проблема видна руками ученика за 20 секунд; тема урока появляется как решение, а не определение |
| s3 title и h1 | Цель «на вкладке — …» / «на странице — …», нажать в коде текст, который надо поменять | Учит различать два похожих тега через результат; ответ однозначен; после подробной подсказки — «ещё одно, с другими словами» |
| s5 → s6 → s7 → s7b | Шесть уровней (нажимай и смотри) → лесенка (показ) → «Какая цифра?» (быстрые раунды) → «Расставь сам» (код) | Чистая цепочка показ → повтор → сам; управление знакомое, задача растёт |
| s7b «Расставь сам» | Выбор строки, потом кнопки h1/h2/h3; неверный не ставится, после двух промахов светится верная кнопка | Ошибка ничего не стоит, застрять нельзя, каждое действие проверено сразу |
| s8 «Предскажи» | Прогноз «переносы в коде дадут абзацы?», потом браузер показывает правду | Разбивает ложное представление ученика его же руками |
| s13 «HTML-детектив» | В каждом деле одно место стоит не так; «Здесь всё в порядке. Ищи дальше»; лесенка под каждое дело | Перенос и чтение кода, а не набор; ученик ищет причину |
| s14 «Новый раздел» | Песочница стала мини-заданием «N/4»; кнопка «+ h2» появляется только на своём шаге | У открытого задания есть цель и видимое «готово» |
| s15 «Свой проект» | Тема на выбор, страница собирается по шагам, шаг засчитывается сам, превью живое | Свой результат без перегруза и без «Проверить» |
| s16 «Новая задача» | Афиша концерта без образца | Проверка переноса на новую ситуацию |
| s18 «Итог» | Список умений и карточка «Следующий урок» | Ученик видит, чему научился, и знает, что дальше |

## Что заказчик исправлял — анти-примеры с решениями

| Было | Что не так | Как правильно |
|---|---|---|
| «Нажми часть раздела «Правила»» (урок 2) | Абстракция: ученик не понял, что нажимать | Назвать вещь: «Нажми заголовок внутри «Правил»» |
| Песочница «измени что хочешь» | Нет цели и видимого «готово» | Мини-задание по шагам со счётчиком |
| Пять целей-кружков, «Код / Результат», три кнопки «+» и «Проверить» сразу (свой проект) | Перегруз; кружки принимали за переключатели | Шаги по одному действию, превью рядом |
| «Режь, где меняется тема» с проверкой | Ответ «на вкус» — нет верного | «Разложи по абзацам» с однозначной темой предложения |
| «Готово» после ввода текста | Ошибиться нельзя, лишний шаг | Автозасчёт после паузы в наборе |
| Переключатель «Код / Результат» | Ученик не видит результат действия | Код и браузер рядом |
| Код слева, справа пустота (тестовый урок) | Пустая половина, связь с результатом не видна | Окно браузера рядом с кодом, как на остальных экранах |
| Отступы в редакторе «гуляют» | Код выглядит иначе, чем в других экранах | Одинаковые отступы вложенности везде |
| «Тиски» для вложенности (тестовый урок) | Посторонний механизм вместо темы | Образ показывает только html / head / title / body |
| Тур по кнопкам + план + ~20 с слушания (урок 1, s2) | Первые экраны — только слушать | Тур — отдельный экран; карточки плана открывает сам ученик |
| Шесть реплик показа подряд (урок 1, s3) | Всё заперто ~30 с | Показ дробится на нажатия, два экрана |
| Два задания на одном экране (урок 1, s10; практика Т2) | Одно действие на экран нарушено | Два экрана |
| Семь раз подряд «печатай и Проверить» (практика 01p) | Однообразно и тяжело на телефоне | Чередовать с касаниями (обмен местами, найти строку) |
| Коди скрыт и на ноутбуке | Заказчик хотел прятать только на телефоне | `voiceTop` прячет Коди только на узком экране |
| Похвала голосом после каждого шага многошагового задания | Голос запирает касания на 1,5 с | Промежуточные шаги — звуком, голос — на итоге |

## Как из темы рождается ситуация — варианты для размышления

Несколько вариантов на тему показывают сам ход мысли. Брать первый вариант не обязательно: лучше придумать свой под конкретный урок.

- **Ссылки и атрибуты** (`a`, `href`). Умение — связать страницы и вести на нужный адрес. Варианты ситуаций:
  - у Коди три страницы клуба, но с главной никуда не попасть;
  - квест-навигатор, где каждая ссылка ведёт в комнату;
  - гид по игре, где «вернуться к оглавлению» не работает.
  Новое понятие «атрибут» показывается как «настройка тега», которую видно по результату: куда ведёт ссылка.
- **Изображения** (`img`, `src`, `alt`). Варианты:
  - карточки питомцев приюта, где картинки не грузятся и нужен `alt` для незрячего посетителя;
  - витрина магазина роботов.
  Изюминка — честный показ: без `src` пусто, без `alt` экранный диктор молчит.
- **Формы** (`input`, `label`). Варианты:
  - регистрация на турнир, где организатор получает пустые заявки;
  - анкета клуба.
  Ученик видит заявку глазами организатора.

## Удачные приёмы, которые можно переиспользовать как инструменты

Не как сюжет, а как способ показать тему:
- **Живое превью рядом с кодом** — каждая буква сразу в браузере.
- **«Провод»** от строки кода к месту в браузере.
- **Прогноз**, потом правда браузера.
- **Детектив:** одно место стоит не так.
- **Проверка структуры по правилу:** панель правил с галочками, ошибка называется правилом, а не «сломанной страницей».
- **Пошаговая сборка «N/M»** — кнопка шага появляется только на своём шаге.
- **Сужение выбора:** неверное гаснет, после двух промахов светится верное.
- **Новая короткая задача после подробной подсказки.**
