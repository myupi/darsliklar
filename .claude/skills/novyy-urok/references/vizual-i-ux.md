# Визуал, анимации, Коди, телефон, звук

Развивать визуальный язык утверждённых уроков, а не придумывать новый. Подробная дизайн-система — в брифе («Дизайн-система курса HTML»), здесь главное для решений.

## Визуальный язык курса

- **Фон и цвета.**
  - Фон тёплый `#F6F4EF`, карточки белые, интерфейс оранжевый `T.ui`.
  - Решённое — зелёный `T.success`, подсказка — жёлтый канал `T.hint` / `T.hintSoft`.
  - **Красного цвета ошибки нет.**
- **Шрифты:** Manrope — текст и кнопки; JetBrains Mono — код, теги, счётчики; страница в мини-браузере — Times New Roman, как HTML без CSS.
- **Цвета тегов** (`TAGC`) одной светлоты, контраст на белом от ~5:1. Тег всегда того же цвета в коде, на схеме и в подсказке.

  | Семейство | Цвет | Где введён |
  |---|---|---|
  | `html` | `#586A83` графит | урок 1 |
  | `head` | `#6F57AB` фиолетовый | урок 1 |
  | `title` | `#9F4471` ягодный | урок 1 |
  | `body` | `#1171A0` голубой | урок 1 |
  | `h1–h6` (одно семейство) | `#4F46C8` индиго | урок 2 |
  | `p` | `#227882` морская волна | урок 2 |
  | `b`, `i` | `#97368A` пурпур | урок 2 |
  | `ul`, `ol`, `li` (одно семейство) | `#2F6FB0` стальной синий | урок 3 (тестовые версии; в первой пробе `li` ещё оливковый — устарело) |

  Новому тегу:
  - **Семейство.** Сначала решить, не член ли он семейства с общим цветом, как `h1–h6` или списки. Свободных оттенков мало, семейство — нормальный выход.
  - **Свой цвет** нужен только тегу, который ученик должен различать с соседями на одном экране. Подбирать той же светлоты (OKLCH L≈0.5), заметно отличным от таблицы по тону. Не оранжевый (интерфейс), не жёлтый (подсказка), не зелёный (верно), не красный.
  - **Имя и значение атрибута** — свои цвета внутри тега. Например, имя приглушённым цветом тега, значение — `T.ink`. Записать их в шапке урока.
  - **После утверждения урока** дописать сюда строку таблицы.
- **Мини-браузер** — как Chrome в Windows: вкладка с фавиконом и крестиком, «+», кнопки окна. Страница рисуется **честно**, как браузер по умолчанию (размеры заголовков, отступы списков, точки и номера, переносы склеиваются). Отступы уменьшены вдвое.
  - **Чего у окна нет, но нужно теме,** дорисовывается в уроке своей обёрткой над `MiniBrowser`, в том же стиле Chrome. Это не правка канона: помощники урока 2 копируются в урок, и урок может их расширять.
  - Примеры:
    - адресная строка и переход по ссылке (урок «Ссылки»);
    - рамка картинки с текстом `alt` (урок «Изображения»);
    - поля формы (уроки «Формы»).
  - В общий вид всех уроков такое расширение попадает только через помощники урока 2 или канон — с решением заказчика.
- **Иконки** — только SVG из `Icon` канона. Эмодзи запрещены. Новая картинка — SVG прямо в коде урока.
- **Размеры** — через `clamp`, `vw`, `dvh`. Урок занимает ровно высоту окна, прокрутки страницы нет.

## Анимации — у каждой есть функция

| Функция | Пример |
|---|---|
| Показать связь | Строка кода и место на странице подсвечиваются вместе; «провод» от кода к браузеру |
| Показать изменение | Новый пункт въезжает в список; изменённый блок вспыхивает цветом тега |
| Показать порядок | Номера пересчитываются по очереди; шаги загораются один за другим |
| Направить внимание | Светодиоды на месте действия при бездействии; рука-указатель |
| Показать результат | Готовая страница собирается; объект миссии загорается |
| Реакция на неверное | Мягкая тряска элемента и звук `soft` — не цвет и не крестик |

**Правила движения:**
- Плавно и коротко: появления 0,3–0,6 с, без резких скачков. Все циклы медленнее 3 Гц.
- **Никакой анимации появления экрана с `opacity: 0`** — белая страница навсегда. Плавность только у элементов внутри.
- Обязателен блок `@media (prefers-reduced-motion: reduce)`: анимации выключаются, состояние показывается сразу. Таймеры, которые ждут анимацию, укорачиваются (`reduceMotion()`).
- Пауза замораживает анимации.
- Декоративное движение без смысла не нужно: оно отвлекает от кода.

## Коди

- **Облик — только голова в белом кружке** (рисунок v4, заказчик 17.10.2026). Эмоцию показывает лицо: глаза, веки, рот, румянец, цвет экрана. Пока Коди говорит, вокруг кружка бегут хаотичные оранжевые волны, как у Алисы и Siri. Когда ученик ничего не делает, лицо само меняет выражение (без голоса).
- **Место:** телефон — в шапке рядом с подсказкой (кнопки шапки справа), строки героя под шапкой нет; планшет и компьютер — справа снизу над нижней панелью, у правого края экрана, облако без звука — строкой над кнопками. Значит, у содержания нет строки героя сверху, а на ноутбуке справа снизу всегда стоит кружок — не класть туда важное. Тела и рук нет — поза «показывает рукой» больше не работает, на нужное место указывают светодиоды, подсветка и провод.
- **Реагирует на происходящее позой лица и короткой репликой.** Позы (`POSES`):

  | Поза | Когда |
  |---|---|
  | `explain` | Рассказ |
  | `point` | «Смотри сюда» |
  | `rule` | Разбор «почему» |
  | `think` | Ученик ошибся, «давай вместе» |
  | `wonder` | Одно «ого» за сцену |
  | `smile` / `cheer` / `celebrate` | Получилось, похвала, финал |
  | `hello` / `bye` | Приветствие, прощание |
  | `curious` | Любопытство |
  | `shy` | Смущение |
  | `sorry` | Ошибся сам Коди, никогда в ответ на ученика |
  | `sleep` | Один раз за курс |

- **Не закрывает рабочую область.** Строка героя — кружок ~54–70 px на телефоне. На тесных экранах телефона — `Stage voiceTop`: строка героя скрыта только на узком экране, Коди маленьким кружком в шапке. На ноутбуке строка героя видна всегда, экран обязан влезать с ней (1280×720).
  - `voiceTop` ставится, когда на 360×640 у содержания меньше ~60 px запаса или экран растёт по ходу задания.
  - Где запас большой — Коди виден и на телефоне. Это лучше для вовлечения.
- **Не заставляет ждать.**
  - Реплика на действие — 1–2 предложения.
  - Касания заперты, пока Коди объясняет задание (`useCanAnswer`). Поэтому в многошаговых заданиях промежуточные шаги озвучиваются звуком, а голос звучит на итоге.
  - Реакция на действие вытесняет очередь (`sayNow`).
- **В практике Коди нет вовсе.**
- **Облик не меняется** (рисунок v4 — голова в кружке, волны голоса): правки — только через `canon/html/hero-*.part.jsx`, `tools/build-canon.mjs` и `npm run canon`.

## Раскладка: телефон главнее

- **Порядок полос `Stage`:** шапка (прогресс, Коди на экранах `voiceTop`, подсказка, пауза, счётчик) → строка героя (кружок с головой Коди; без звука — облако с репликой) → строка задания и механика → навигация («Назад», «Дальше»).
- **Строка задания (`.ask`) держится** после вступления и не прыгает. Подсказка встаёт на её место (`ask-hint`).
- **Код и превью** (`Work`): на телефоне в колонку (браузер над кодом), на ноутбуке в ряд. Пустых половин нет: если на экране только код, рядом всё равно браузер с результатом.
- **Кнопки ответа** — крупные (от ~44 px по высоте), с понятной подписью. Выбор ul/ol и подобные — с маленькой иллюстрацией того, что получится.
- **Не уменьшать текст**, чтобы влезть: код не мельче ~12 px, текст не мельче ~14 px. Не влезает — дробить экран или ставить `voiceTop`.
- **Открытая клавиатура** (`is-kbd`, `--vvh` ~330 px): прячется всё, что не нужно для ввода (Коди, навигация, иногда превью), но не задание и не образец. Поле ввода и кнопки символов остаются над клавиатурой. Поле ввода — кегль 16 px, иначе iOS увеличивает страницу.
- **Нет обязательного наведения мыши.** Перетаскивание — только с запасным путём «ткнул — ткнул» и без требования точности.
- **Касание, мышь и клавиатура равны:** кнопки — `<button>`, фокус виден (`:focus-visible`), Enter в поле работает.
- **Классы урока** — со своим префиксом (`sp-`, `ln-` …). Общие имена (`opts`, `keys`, `pending`) пересекаются с каноном и ломают вёрстку.

## Звук и озвучка

- **Озвучка** — только движок канона (`ttsApiBase`). Без сервиса говорит голос браузера, без него реплика печатается. Урок обязан проходиться без звука: задание всегда написано, гейты имеют предохранители (9 с на ответ, 20 с на «Дальше»).
- **Пауза и повтор** — кнопки шапки канона. «Повторить» перезапускает экран с первой реплики и стирает только данные этого экрана (`SCREEN_RESET`).
- **Звуки** `sfx`:

  | Звук | Когда |
  |---|---|
  | `ok` | Верно |
  | `soft` | Не так |
  | `tap` | Выбор |
  | `pop` | Деталь встала |
  | `type` | Клавиша |
  | `win` | Задание целиком |
  | `hint` | Подсказка |

  Звук — быстрая реакция на каждое действие, голос — на итог.
- **Праздник похвалы** (канон, заказчик 16.10.2026): реплика Коди с позой `cheer` / `celebrate` запускает хлопушки из нижних углов с конфетти и аплодисменты (`sfx('cheer')`). Ставить `cheer` на настоящие победы (экран решён, страница готова), а не на каждый мелкий шаг — для шага хватит `smile` и `sfx('ok')`. Вызвать вручную — `celebrate()`.
- **Теги в речи — по-английски во всех языках** (заказчик, 17.10.2026: «body, а не бади»): в `TAG_SAY` у ru и uz названия тегов — те же английские слова, что у en (`body`, `title`, `HTML`, `H one`, `U L`, `H ref`). По-местному звучат только слова вокруг: «закрывающий тег», «уголок», «косая черта». Для нового тега — английское название во всех трёх строках.
- **Эмоции голоса ставит движок канона** (`emoTag` рядом с маркером языка, `TTS_EMOTION`): по началу реплики — похвала `[excited]` (часто с `[laughs]`/`[chuckles]`), большая победа `[very excited] [laughs]`, «ого» `[gasps] [amazed]`, «почти» `[reassuring]`, ошибка Коди `[embarrassed]`, привет `[cheerful]`, вопрос `[curious]`, с «!» `[upbeat]`, остальное `[friendly]`. Писать теги в тексты реплик не нужно. Чтобы эмоция сработала, реплику начинать с живого слова: «Огонь!», «Есть!», «Ого,», «Почти!», «Ой!».
- **Код в репликах — как его читать:**
  - **Тег в угловых скобках** (`<li>`, `</p>`) писать можно: обёртка озвучки сама превращает его в слова. Запрет символов `/ = +` касается текста, который останется после этой замены.
  - **Не дублировать слова, которые добавит замена:**
    - `</a>` читается как «закрывающий тег эй». Поэтому «Закрывающий тег </a> …» прозвучит как «закрывающий тег закрывающий тег эй».
    - Писать «А </a> заканчивает ссылку», «</a> esa…», «And </a> ends…».
    - Проверять озвучку в журнале просмотрщика.
  - **Голое имя тега без скобок** заменяется словом, только если оно не совпадает с обычным словом языка. `ul`, `li`, `href` заменять можно. `a` (английский артикль), `i`, `b`, `p` — только в скобках или в кавычках «a» (так и сделано в `spokenHtml` для `p b i`).
  - **Атрибут со значением** (`href="hall.html"`) в реплику не писать: говорить словами — «атрибут href с адресом зала», «адрес — имя файла зала». Точную запись показывает экран.
  - **Имена файлов и адреса** (`hall.html`, `cat.png`) в репликах не произносить: их озвучка коверкает («hall.эйч-ти-эм-эль»). Говорить смыслом: «файл зала», «картинка кота». Если без имени файла никак — добавить в свою функцию озвучки замену `.html` → «точка HTML» на трёх языках.
  - **Строки с «+ h2» и подобным на экране** получают отдельное поле для голоса (`hint`). То же — для любой подписи, где на экране символы, а в голосе нужны слова.
