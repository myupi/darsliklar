# Сценарий, история и игры (шаг В)

Здесь — как придумывать. Готовые решения прошлых уроков — в `primery.md`, и это не шаблоны.

## 1. Ситуация и роль ученика

Начинать с умения, а не с сюжета: **где в жизни это умение нужно?** Из ответа вырастает ситуация.

1. **Перебрать 3–4 ситуации**, где тема естественно нужна, и выбрать ту, где:
   - без умения продвинуться нельзя — проблема видна сразу, а не объясняется;
   - результат можно увидеть в мини-браузере и он нравится подростку: сайт клуба, афиша, гайд по игре, инструкция для робота, меню кафе, карта квеста;
   - сюжет не повторяет предыдущие уроки. Проверить шапки уроков `ЗАМЫСЕЛ`: робофутбол уже был в уроке 2.
2. **Роль ученика** — тот, кто решает и делает: веб-программист клуба, редактор, инженер, детектив разметки, помощник организатора. Ученик главный, Коди — напарник.
3. **Зачем здесь Коди.** Одна из ролей (или смена ролей по ходу урока):
   - заказчик: принёс задачу;
   - неудачник-напарник: сделал криво и просит помочь;
   - экспериментатор: «а что будет, если…»;
   - экзаменатор: прячет поломки для детектива.

   Коди ошибается сам и признаёт это (`sorry`), но **никогда не встаёт в `sorry` в ответ на действие ученика**.
4. **Другие персонажи** — только если без них сюжет хуже: организатор турнира, младший брат, клиент. Они не рисуются новыми героями: живут в тексте страниц, в репликах Коди, в «письмах» или SVG-предметах. Визуальный канон Коди не меняется.
5. **История развивается действиями.**
   - Плохо: вступление на три экрана, потом несвязанные упражнения.
   - Хорошо: каждое задание двигает миссию — страница собирается, база оживает, заказ выполняется. Прогресс миссии виден: счётчик, собранная страница, карта, загорающиеся объекты.
6. **Финал** — результат, созданный или изменённый самим учеником (артефакт урока). Плюс мостик к следующей теме.

## 2. Механики: как подобрать

**Главный критерий: чтобы продвинуться, ученик должен применить изучаемое знание.** Если задание можно пройти перебором быстрее, чем пониманием, оно не годится.

Механика выбирается **под учебное действие**, а не наоборот:

| Учебное действие | Примеры механик (выбор, а не обязательный набор) |
|---|---|
| Увидеть связь кода и результата | Нажать строку кода — подсветить результат; переключить тег — страница меняется; «провод» код → браузер |
| Понять назначение / различие | Эксперимент с прогнозом: «как думаешь, что покажет браузер?», потом браузер показывает; сравнение двух версий |
| Освоить запись | Собрать строку из деталей; набрать тег кнопками `< / x >`; дописать недостающее в живом коде |
| Применить по смыслу | Выполнить заказ: «сделай так, чтобы…»; выбрать тег для каждой строки с мгновенной проверкой |
| Найти и исправить | Детектив: в коде одно место стоит не так; починить решение Коди; проверка структуры по правилу |
| Управлять системой через код | Код управляет объектом (табло, витрина, робот) — правка кода сразу меняет мир |
| Восстановить объект | Разбитая или «стёртая» страница — вернуть разметку по смыслу |
| Перенести | Новая задача без образца (афиша, меню, инструкция) |
| Создать своё | Своя страница по шагам с видимыми условиями «готово» |

**Настоящая работа с кодом обязательна** в каждом уроке программирования: изменить, написать, проверить, исправить. Касания, сортировки и прогнозы — подготовка к ней, а не замена.

**Перетаскивание** можно, если оно естественно (переставить строку, вложить пункт). Но всегда есть путь «ткнул — ткнул», и точное попадание не требуется.

### Анти-паттерны

- Урок из викторин, «выбери правильный вариант» подряд.
- Случайное нажатие: ответ находится перебором 2–3 кнопок без понимания.
- Одна игра под новым названием в каждом уроке.
- Награды без смысла: монеты, конфетти, звёзды, очки.
- Механика сложнее темы: ученик разбирается с управлением, а не с HTML.
- Новая механика на каждом экране. Знакомое управление полезно; разнообразие — в задачах и ситуациях.
- Метафора, не связанная с темой. Пример: «тиски» для вложенности — заказчик отклонил. Образ должен показывать саму тему (коробки-теги, страница, список), а не посторонний механизм.
- Экран «только слушать» дольше пары реплик. Показ идёт с нажатиями ученика.

### Чередование и темп

- Двух одинаковых механик подряд нет. Одинаковые — это одно и то же действие ученика с тем же управлением: «выбрать одну из кнопок-ответов» дважды подряд; «нажать строку кода» дважды подряд на одном материале. Разные: нажать строку кода → набрать тег → собрать из деталей.
- Короткий показ → действие → действие посложнее → проверка → передышка (наблюдение, прогноз) → снова действие.
- Самый трудный экран — не последний перед финалом: после него задание, где ученик чувствует силу (своя работа).

## 3. Дуга урока

Коды экранов из брифа:

| Код | Назначение |
|---|---|
| `HOOK` | Проблема в ситуации, которую видно сразу; интрига и обещание результата — без терминов (`metodika.md`, «Крючок и план») |
| `MISSION` | План урока карточками (`MissionScreen`) — фразы-действия на языке ученика, без названий тегов |
| `SHOW` | Показ нового с нажатиями |
| `LEVEL-n` | Повторение и самостоятельные шаги |
| `PREDICT` | Прогноз результата |
| `CHECK-n` | Перенос, детектив |
| `SANDBOX` | Мини-задание по шагам |
| `RESULT` | Свой проект |
| `TRANSFER` | Новая задача без образца |
| `ACHIEVEMENT` | Сохранение своей страницы |
| `PREVIEW` | Итог и мостик, здесь `p.finish` |

`HELLO` и `TOUR` — только в первом уроке курса. Экран, вставленный позже, получает суффикс: `s7b`.

Дуга — каркас, а не форма для заливки. Можно убрать `MISSION`, если план очевиден из истории. Можно сделать два `SHOW` для двух понятий. Можно поставить `PREDICT` раньше показа. Число экранов — сколько нужно.

## 4. Карточка экрана

Шаблон этого навыка заменяет шаблон в конце брифа: он включает поля брифа (ключ `store`, тип журнала, `voiceTop`) и добавляет педагогические. Строку «показывается на утверждение» из брифа читать с учётом режимов навыка.

Сводную таблицу экранов (как в брифе) можно дать в начале раздела «Экраны», а карточки — для экранов с заданием. Для показа, плана и итога хватит строки таблицы.

Для каждого экрана — в сценарии:

```markdown
### N. sN · КОД · «Короткое название»
- Цель: что ученик поймёт или сделает (одна мысль)
- Видит: что на экране (код, браузер, предметы); voiceTop — да/нет
- Действие: одно основное действие, глаголом («нажми строку li», «набери </ol>»)
- После: что меняется сразу (превью, анимация, звук, реплика)
- Успех: точное условие засчёта
- Затруднение: типичный неверный ход → реакция (текст, движение, сужение выбора)
- Подсказки: 1) направить; 2) сузить; 3) опора
- После подсказки 3: новая короткая задача на тот же принцип (что именно)
- Анимация: что движется и зачем (связь / изменение / порядок / внимание / результат)
- Реплики (L3): вступление; ask; ответы на ходы; why; похвала
- Журнал: log type или «нет» (если ученик не отвечал); ключ store — sN
```

Реплики в файле сценария можно давать на русском, если все три языка сразу пишутся в `C` исходника. В режиме согласования — на трёх языках.

## 6. Чек-лист сценария (до кода)

- [ ] Опирается только на изученное; будущий материал не требуется.
- [ ] Для каждого нового умения есть показ → повторение → самостоятельно → перенос.
- [ ] Помощь убывает, к концу ученик исправляет Коди и делает своё.
- [ ] Сюжет придуман под тему, не повторяет прошлые уроки; история движется действиями.
- [ ] Каждая игра требует применить тему; есть настоящая работа с кодом.
- [ ] На каждом экране одно действие и конкретная формулировка, результат виден сразу.
- [ ] У проверяемых заданий один ответ, у творческих — видимые условия «готово».
- [ ] Подсказки трёх ступеней написаны под задание. После третьей ступени есть новая задача.
- [ ] Механики чередуются, нет экранов «только слушать».
- [ ] Финал — работа ученика; итог называет умения; мостик к следующему уроку.
- [ ] Реплики короткие, без запретных слов и символов, на трёх языках.
- [ ] Урок можно пройти без взрослого и без звука.
