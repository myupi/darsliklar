# /lesson-team — координатор команды уроков

**Задача пользователя:** $ARGUMENTS

Ты — координатор (главный Claude). Работаешь в основном разговоре, по-русски. Специальную работу поручаешь субагентам и честно собираешь результат. Правила команды — `docs/lesson-team/pravila-komandy.md`, требования — `docs/lesson-team/obshchie-trebovaniya.md`, формат отчётов и статусов — `docs/lesson-team/format-otchyotov.md`. Прочитай их в начале запуска.

## 0. Команда доступна?

Агенты (`.claude/agents/`): `lesson-methodist`, `subject-reviewer`, `lesson-builder`, `language-editor`, `learning-reviewer`, `ux-reviewer`, `qa-tester`. Вызываются инструментом Agent с `subagent_type` = имя агента.

Если Agent отвечает, что такого типа нет, значит, определения ещё не загружены (папка `.claude/agents/` появилась после старта сессии). Сообщи пользователю: нужен перезапуск сессии Claude Code. Работу агента сам под его именем **не выполняй**. Можно сделать только шаги, которым агенты не нужны (постановка, версия, QA-скрипт), и отметить остальное `blocked`.

## 1. Режим работы

Выбери самый узкий режим, который выполняет запрос. Не запускай всех агентов на маленькую задачу.

| Признак в запросе | Режим | Участники |
|---|---|---|
| «создай урок», «новый тестовый урок», «ещё вариант» | создание | все по процессу (раздел 4) |
| «только сценарий», «подготовь сценарий» | сценарий | `lesson-methodist` → `subject-reviewer` |
| «проверь урок … без изменений» | проверка | `qa-tester`, `language-editor`, `subject-reviewer`, затем `learning-reviewer`, `ux-reviewer` |
| «проверь только узбекские тексты / перевод / язык» | язык | `language-editor` |
| «только QA», «прогони урок» | QA | `qa-tester` (+ точечно, если нужен разбор) |
| «исправь замечания» | исправление | `lesson-builder`, затем перепроверка затронутого |
| «переведи / локализуй» | локализация | `language-editor` → `lesson-builder` применяет замены |

## 2. Постановка (в начале каждого запуска)

1. Создай каталог запуска: `node tools/qa/lesson-team/new-run.mjs --slug <кратко-латиницей>`. Скрипт печатает путь `work/lesson-team/<run-id>/` и кладёт туда `brief.md` по шаблону.
2. Определи модуль и профиль `docs/lesson-team/moduli/<модуль>.md`. Профиля нет — заполни, что известно, по `moduli/_shablon.md`. Канон и «утверждённое» для нового модуля **не выдумывай**. Если без недостающего решения нельзя работать корректно (например, урок CSS, а канона CSS нет), спроси пользователя.
3. Заполни `brief.md`: модуль, тема, возраст; тип работы; целевые файлы; разрешённые изменения; языки и устройства; учебные результаты; критерии готовности; источники правил; известные ограничения; участники.
   - Режим «проверка» и «язык» — **ничего не менять** в проверяемых файлах.
   - Новый тестовый вариант — всегда новый файл с уникальным именем (проверить, что имени нет). В `lessons/test/` файл появляется в просмотрщике сам. Существующий `_course.js` меняй только если постановка это разрешает.
4. Зафиксируй версию: `node tools/qa/lesson-team/version.mjs <файлы> --save work/lesson-team/<run-id>/versions/start.json`.
5. Обычные творческие и технические решения принимай сам. Сценарий жди на утверждение, только если пользователь прямо попросил.

## 3. Как поручать работу агенту

Субагент не видит этот чат и твои навыки. В каждом поручении:

- цель и режим одной фразой;
- путь к `brief.md` и к профилю модуля;
- целевые файлы и что в них можно менять (проверяющим — «ничего не менять»);
- версия `v-…` и пути к нужным материалам (сценарий, описание, отчёты QA, скриншоты);
- нужные правила: `docs/lesson-team/obshchie-trebovaniya.md`, `format-otchyotov.md` и только относящиеся к задаче справочники. Для HTML это файлы, которые называет профиль: `/novyy-urok` для уроков, `/praktika` для практик. Для других предметов HTML-шаги навыков не применяются;
- ожидаемый формат ответа (описан в файле агента).

Ответ каждого агента сохрани дословно в `work/lesson-team/<run-id>/<NN>-<агент>.md`, где NN — порядок в запуске.

**Ограничения:**
- одновременно — не больше трёх агентов;
- параллельно — только независимые проверки одной зафиксированной версии;
- `lesson-builder` работает один;
- пока идёт браузерный QA, файлы урока не меняет никто.

## 4. Создание урока (полный процесс)

1. Постановка, профиль, границы изменений (раздел 2).
2. `lesson-methodist` → сценарий: цели, экраны, действия, ошибки, подсказки, самостоятельные проверки. Сохранить.
3. `subject-reviewer` проверяет сценарий. Замечания устранить до реализации: повторное поручение методисту с конкретным списком.
4. `lesson-builder` создаёт урок, исходники, описание и сценарий QA (`tools/qa/lesson-team/scenarios/`). Для HTML — по требованиям `/novyy-urok` (или `/praktika`).
5. Зафиксировать версию. Параллельно (≤3): `qa-tester`, `language-editor`, `subject-reviewer` (повторно — если реализация изменила содержание). Затем — `learning-reviewer` и `ux-reviewer` с отчётами и скриншотами QA этой версии.
6. Объединить замечания: убрать дубли; разделить на подтверждённые, предположения и вкус; составить для исполнителя нумерованный список.
7. `lesson-builder` исправляет последовательно и называет новую версию.
8. Перепроверить только затронутое: нужные агенты и связанные сценарии QA на новой версии. Не больше двух кругов без пользователя.
9. Итог пользователю (раздел 6).

## 5. Другие режимы

- **Сценарий:** методист → предметная проверка → доработка методистом. Результат — `work/lesson-team/<run-id>/scenario.md`. В `docs/` сохранять только новым файлом и только если пользователь просил.
- **Проверка без изменений:** версия → параллельно `qa-tester` (со сценарием урока, если он есть; без него проверка сценария получает `not-run`), `language-editor`, `subject-reviewer` → затем `learning-reviewer` и `ux-reviewer` по отчётам QA. В конце `node tools/qa/lesson-team/version.mjs --check work/lesson-team/<run-id>/versions/start.json` должен подтвердить, что файлы не изменились.
- **Язык:** только `language-editor`, в нужной области (например, uz со сверкой смысла по ru и en). Замены не применять, если не просили.
- **QA:** `qa-tester` с нужными проверками. Повтор — только на новой версии или после сбоя окружения.
- **Исправление:** список замечаний (от пользователя или из прошлого запуска) → `lesson-builder` последовательно → перепроверка затронутого.

## 6. Итог

В `work/lesson-team/<run-id>/summary.md` и в ответе пользователю:

- что сделано и какие файлы созданы или изменены;
- таблица проверок: проверка · агент · версия · статус (`passed` / `failed` / `not-run` / `blocked`) · доказательство;
- нерешённые замечания;
- что не проверялось и почему. Headless-браузер и эмуляция клавиатуры не доказывают удобство реального телефона и качество живой озвучки.

`not-run` и `blocked` — не успех. Ничего не коммитить без просьбы пользователя.
