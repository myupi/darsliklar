# /lesson-team — координатор команды уроков

**Задача пользователя:** $ARGUMENTS

Ты — координатор (главный Claude). Работаешь в основном разговоре, по-русски. Специальную работу поручаешь субагентам и честно собираешь результат. Правила команды — `docs/lesson-team/pravila-komandy.md`, требования — `docs/lesson-team/obshchie-trebovaniya.md`, форматы — `docs/lesson-team/format-otchyotov.md` и `docs/lesson-team/shablon-peredachi.md`. Прочитай их в начале запуска.

**Цель стандартного процесса:** за 60–90 минут подготовить содержательно проработанный, работающий урок и передать его QA-команде заказчика. Это бюджет для типового урока на существующем каркасе, а не повод объявлять незавершённое готовым. Главный приоритет — качество обучения: понятные объяснения, правильные примеры, интересные действия, самостоятельное применение и качественные тексты на всех языках.

## 0. Команда доступна?

Агенты (`.claude/agents/`): `lesson-methodist`, `subject-reviewer`, `lesson-builder`, `language-editor`, `learning-reviewer`, `ux-reviewer`, `qa-tester`. Вызываются инструментом Agent с `subagent_type` = имя агента.

Если Agent отвечает, что такого типа нет, определения ещё не загружены: сообщи пользователю, что нужен перезапуск сессии Claude Code. Работу агента сам под его именем **не выполняй**.

## 1. Режим — по тексту запроса, без параметров

| Признак в запросе | Режим | Что делать |
|---|---|---|
| «создай урок», «следующий урок», «тестовый урок по …», «ещё вариант» | **создание** — стандартный процесс | раздел 3 |
| «только сценарий», «подготовь сценарий» | сценарий | шаги 1–3 раздела 3; результат — `scenario.md`, кода нет |
| «только перевод», «проверь узбекские тексты» | язык | только `language-editor`; замены не применять, если не просили |
| «переведи», «локализуй» | локализация | `language-editor` → `lesson-builder` применяет замены → короткая техническая проверка |
| «проверь урок … без изменений», «только проверка» | проверка | раздел 4; **файлы урока не меняются** |
| «исправь замечания» | исправление | один объединённый список → `lesson-builder` → повтор проверок затронутого → передача |
| «полный QA», «проверь на всех устройствах и языках» | полный QA | `qa-tester`, полная матрица. **Только по прямой просьбе** |

Выбирай самый узкий режим. Многочасовые браузерные прогоны, сотни скриншотов и повторные проверки всеми агентами автоматически не запускать.

## 2. Постановка (шаг 1, 5–10 минут)

1. Каталог запуска: `node tools/qa/lesson-team/new-run.mjs --slug <кратко-латиницей>` → `work/lesson-team/<run-id>/brief.md`.
2. Модуль и профиль `docs/lesson-team/moduli/<модуль>.md`: аудитория, языки, изученное, **готовые компоненты и сборка**, персонажи, озвучка, результат ученика, адаптер QA. Профиля нет — заполни известное по `moduli/_shablon.md`; канон и «утверждённое» **не выдумывай**. Если без недостающего решения нельзя работать корректно (например, у модуля нет каркаса урока), спроси пользователя.
3. Тема по плану курса; предыдущие знания — по реальным файлам прошлых уроков; что будет дальше (не забегать вперёд).
4. Заполни `brief.md`: тема, возраст, изученное; режим; целевые файлы и разрешённые изменения (новый тестовый вариант — всегда новый файл с уникальным именем); языки; учебные результаты; критерии «готов к QA»; источники правил; известные ограничения; участники.
5. Нужна **новая механика** или у модуля нет подходящего каркаса — выдели эту подготовку отдельной задачей, оцени, на сколько она удлиняет срок, и сразу сообщи пользователю. Учебную цель молча не упрощай.
6. Запиши время начала (`date`); в передаче укажи время по этапам.

Обычные творческие и технические решения принимай сам. Сценарий жди на утверждение, только если пользователь прямо попросил.

## 3. Создание урока — стандартный процесс

1. **Постановка** — раздел 2.
2. **Сценарий** — `lesson-methodist`: учебные цели, последовательность объяснений, задания с ожидаемыми ответами, типичные ошибки и реакции, подсказки, самостоятельная проверка, итоговые данные. История, примеры и действия — под тему; готовые механики профиля используются, но не превращают урок в однотипную викторину. Сохранить `scenario.md`.
3. **Проверка сценария — параллельно:** `subject-reviewer` (предметная правильность), `learning-reviewer` (качество заданий: подтверждают ли понимание, есть ли самостоятельное применение, нельзя ли пройти перебором), `language-editor` (тексты, термины, языки). Замечания — **один список** → методист вносит → окончательный `scenario.md`. Всё это — до реализации.
4. **Сборка** — `lesson-builder`: урок из существующих компонентов и сборщика модуля по окончательному сценарию; тексты на всех языках; сценарий QA, основной путь которого проходит основной ввод и завершение. Общий код вручную заново не писать, новую библиотеку не начинать. Самопроверка исполнителя — сборка, синтаксис, наличие текстов и переводов.
5. **Сверка и короткая техническая проверка — параллельно** на одной версии:
   - `learning-reviewer` — реализация против сценария: ответы, ветки ошибок и подсказок, учёт, итоговые данные;
   - `language-editor` — тексты реализации на всех языках;
   - `qa-tester` — **короткая техническая проверка** (раздел 4).
   Замечания — **один объединённый список** → `lesson-builder` → повторяются только проверки затронутого (таблица ниже). Вкус и необязательные улучшения в правку не идут — они в передаче.
6. **Передача** QA-команде заказчика — раздел 6. Статус «готов к QA».

**Что повторять после правки:**

| Что менялось | Кто повторяет |
|---|---|
| тексты, реплики | `language-editor` — изменённые места |
| ответы, ветки, подсказки, учёт, итоговые данные | `learning-reviewer` — изменённые места; `qa-tester` — основной путь, если менялось поведение |
| предметные примеры, разбор кода, превью | `subject-reviewer` — изменённые места |
| раскладка, ввод, завершение | `qa-tester` — короткая техническая проверка |

## 4. Проверки

- **Короткая техническая проверка** (по умолчанию, `qa-tester`): синтаксис и сборка; тексты и переводы на месте; основной путь на русском в быстром режиме — `run.mjs --serve --checks load,scenario --flows main --langs ru --voice fast`; основной ввод принят и попал в итоговые данные; `onFinished` ровно один раз. Около 5–10 минут.
- **Полный QA** (только по прямой просьбе): все языки, размеры профиля, все ветки сценария, клавиатура, `--reduced`, состояния по ходу заданий. По умолчанию это работа QA-команды заказчика.
- **Проверка без изменений:** версия `version.mjs … --save versions/start.json` → параллельно `subject-reviewer`, `learning-reviewer`, `language-editor` и короткая техническая проверка; `ux-reviewer` — если просили об интерфейсе или телефоне. В конце `node tools/qa/lesson-team/version.mjs --check work/lesson-team/<run-id>/versions/start.json` подтверждает, что файлы не изменились.
- **Несколько уроков сразу:** у каждого свой исполнитель и своя рабочая копия (`node tools/qa/lesson-team/wt.mjs create --run <run-id>`, перенос — `wt.mjs sync`). Один урок делается в основной копии.

## 5. Как поручать работу агенту

Субагент не видит этот чат. В каждом поручении: цель и режим одной фразой; путь к `brief.md` и профилю модуля; целевые файлы и что можно менять (проверяющим — «ничего»); версия `v-…` и пути к материалам; нужные правила (`obshchie-trebovaniya.md`, `format-otchyotov.md`, справочники из профиля); ожидаемый формат ответа.

- **Исполнителю** — окончательный сценарий или один объединённый список; готовые компоненты из профиля. Полный браузерный QA исполнителю не поручать.
- **Тестировщику** — объём явно: «короткая техническая проверка» или, только по просьбе пользователя, «полный QA».
- Одновременно — не больше трёх агентов; один исполнитель на урок; проверки одного урока — на одной зафиксированной версии; пока идёт браузерный прогон урока, его файлы не меняются.

Ответ каждого агента сохрани дословно в `work/lesson-team/<run-id>/<NN>-<агент>.md`.

## 6. Передача и итог

`work/lesson-team/<run-id>/peredacha.md` по шаблону `docs/lesson-team/shablon-peredachi.md`, коротко — в ответе пользователю:

- ссылка на урок (просмотрщик и плеер), версия `v-…`;
- учебные цели; экраны с ожидаемыми ответами; ветки ошибок и подсказок; итоговые данные (payload);
- выполненные проверки со статусами и доказательствами; невыполненные — и почему (полная матрица устройств, языков, ошибок и состояний — за QA-командой заказчика);
- известные ограничения, необязательные улучшения, время по этапам.

Статус урока — **«готов к QA»**, пока QA-команда заказчика не завершила приёмку. `not-run` и `blocked` — не успех. Ничего не коммитить без просьбы пользователя.
