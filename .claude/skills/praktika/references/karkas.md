# Каркас практики (шаг Г) — по образцу 01p «Бумажная улица»

Эталон кода — исходник `tools/praktika-01/` (заказчик, 22.10.2026: практика 1 переделана «от сценария до стиля» по эталону урока 1). Собранный файл — `lessons/html/01p-struktura-dokumenta.jsx`. Новая практика начинается с копии исходника:

```bash
node .claude/skills/praktika/scripts/shablon.mjs tools/praktika-<NN>
```

Скрипт копирует четыре файла под именами `pNN.*` и правит пути сборки. Дальше:
- общее не трогать;
- то, что под тему, — переписать;
- собрать файл `sobrat.mjs` из навыка урока.

## Из чего собирается практика

```
pNN.src.jsx      шапка · /*@CANON@*/ · META · STREET (объекты карты) · TXT · UI · FB · C
  /*@FILE:../kollazh/kollazh-paper-data.jsx@*/   ← бумажный набор урока 1: шорох бумаги,
  /*@FILE:../kollazh/kollazh-paper.jsx@*/        вырезки Cut, лист Sheet, полоска KzAsk,
  /*@FILE:../kollazh/kollazh-kit.jsx@*/          теги TagK / T_, бумажный браузер PaperBrowser,
  /*@FILE:../kollazh/kollazh-trans.jsx@*/        переход «разбор и сборка», параллакс
  /*@FILE:pNN-engine.jsx@*/                      механика практики
  /*@FILE:pNN-screens.jsx@*/                     задания, вступление, финал, корень
  LESSON_CSS = CANON_SCREEN_CSS + kollazh.css + pNN.css
```

- Бумажный набор **подключается, а не копируется**: стиль курса один.
- Набор ждёт в `UI` ключи `up`, `down`, `mySite`, `hello`, `play`.
- В наборе есть `makeArtifact` урока 1, поэтому артефакт практики называется по-своему (`practiceArtifact`).
- Свою вырезку практики, которая должна разлетаться и собираться при переходе, помечают классом `kz-piece`.
- Помощники урока 2 (`/*@L2_HELPERS@*/`) практике не нужны: в engine свои `spokenHtml`, `InlineInput`, `hasLetters` и т. д. Подключать их вместе — двойные объявления, сборка сломается.

## Конфиг задания (`cfgTn(pick, store, lang)`)

```js
{
  id: 't3', num: 3,               // ключ store; номер задания = объект карты (загорается после решения)
  kind: 'line',                   // тип для журнала: fields | line | block | gap | doc
  C: C.t3,                        // тексты: say, order, hints[3], praise, done, drill …
  spec: {                         // вид редактора
    kind: 'line',                 // fields — поля в строках; line — одна строка; block — несколько;
                                  // gap — выбрать место между строками, потом одна строка; doc — весь документ
    before: [...], after: [...],  // неизменяемая рамка вокруг поля (line, block)
    lines, gaps,                  // gap: строки кода и места-щели (индексы строк, после которых щель)
    ind: 4,                       // отступ строк ввода
    bars: true,                   // полоски вложенности в редакторе
    big: true,                    // doc с нуля: редактор во всё свободное место
    editTitle, editBody, focusBody, ph, empty
  },
  init: () => ({ code: '' }),     // начальное состояние (fields: { title, body }; gap: { at: null, code: '' })
  check: (st) => ({ ok, msg, cat, sub, result }),   // одна самая полезная проблема; sub — «документ собран не полностью»
  pick: (i) => ({ ok, say } | { ok: false, msg }),  // gap: нажатое место
  orderOf: (st) => …,             // строка задания, если меняется по ходу (gap: «нажми место» → «напиши тег»)
  onSolved: (r) => store.set(...),
  hint: (lv, st) => ({ text, cat }),   // ступень 1–3; может зависеть от текущей проблемы
  fx: (rec) => ({ hl, led, ledGap, markLine }),   // подсветка по ступени подсказки
  orderExtra: <… /> | (rec, st) => <… />,         // помощь под заданием — видна сразу
  aids: …,                        // помощь под браузером (на компьютере)
  h3: (rec) => <CodeSample … />,  // образец третьей ступени (с другим содержимым)
  drill: { make: (cat) => ({ order, orderOf, spec, init, check, pick, orderExtra }) }
}
```

**Ход задания** (`useTask`, общий):
- **Неудачная проверка** → заметка «что не так» (`FB`) и реплика; тряска не нужна — заметка листком.
- **Вторая неудача подряд** (`AUTO_HINT_AFTER = 2`) → к этому сразу следующая ступень подсказки.
- **Лампочка в шапке** → следующая ступень по просьбе.
- **Успех после третьей ступени** → дополнительная задача (`drill`). «Дальше» откроется после неё.
- **Store `tN`:** `st`, `checks`, `fails`, `hint`, `note`, `solved`, `done`, `drill`, `result`.
- **Журнал:** `attempts`, `firstTry`, `hintMax`, `drill`.

Похвала — поза `smile`, спокойная. Конфетти — только в финале (`celebrate()`).

## Разбор кода под новую тему

1. **`KNOWN`** — теги своего урока и прошлых, которые встретятся в заданиях. `TAGC` — цвета частей для полосок вложенности.
2. **`lexDoc`** — оставить устройство. В регулярке «тег без уголка» перечислить `KNOWN`. Для атрибутов (урок 4+) научить токен `open` хранить атрибуты: `{ k: 'open', name, attrs: { href } }`.
3. **`analyzeDoc`** — правила учебной страницы темы, по порядку записи, первая проблема:
   - запись тега (`badFb`: нет уголка, нет косой черты, обратная черта, опечатка — `nearTag`);
   - структура (вложенность, пары, порядок);
   - содержимое (текст на месте, свой текст непустой).

   Фразы — в `FB`, по одной на проблему, о правилах «нашей страницы». Без «ошибка», «неправильно», «xato», «noto‘g‘ri». Знак — с названием рядом.
4. **`pageOf`** — что покажет браузер. Для тем с блоками (`h1–h6`, `p`, списки, ссылки) возвращать блоки и рисовать их как в уроке 2: честные размеры заголовков, отступы, точки и номера, синие ссылки. Код не исполнять — только текст.
5. **Проверки заданий** — маленькие функции поверх `analyzeDoc`:
   - `checkLine(code, target)` — строка;
   - `checkBlock(code)` — блок;
   - `checkCloseTag(code, tag)` — один закрывающий тег;
   - `checkDoc(code, need)` — документ (шаги «с нуля» — через `need`);
   - свой текст — `hasLetters`;
   - заданный текст — `normName` (регистр, ё/е, кавычки не важны).

## Проверка практики (дополнительно к `../novyy-urok/references/proverka.md`)

Сценарий автопроверки — по образцу `tools/qa/lesson-team/scenarios/html-01p-struktura-dokumenta.qa.mjs` (шаги выполняются в странице: помощники — прямо в шаге). Поле практики — `.ed-ta` (редактор) или `.cv textarea` (поле в строке); `qa.type` понимает textarea.

- [ ] **Каждое задание:** верное решение; каждая типичная ошибка даёт свою фразу «что не так». Вторая неудача подряд добавляет ступень подсказки; три лампочки подряд дают три ступени, последняя с образцом.
- [ ] **После решения с образцом** — дополнительная задача. Её проверка, потом «Дальше».
- [ ] **Карта:** объект загорается; на телефоне полоса в шапке показывает прошлый, текущий и следующий объект; в финале объект с названием ученика.
- [ ] **«Назад»** на решённое задание: код, подсказки, карта на месте. **«Повторить»** стирает только текущее задание; перенесённые результаты (код прошлых шагов) целы.
- [ ] **Кнопки символов** вставляют в место курсора и не закрывают клавиатуру (`onPointerDown` / `onMouseDown` с `preventDefault`).
- [ ] **Открытая клавиатура** (`Q.kbd(true)`) на 320×568 и 360×640: браузер, поле, «Проверить» и заметка видны.
- [ ] **Проверка терпима:** лишние пробелы, переносы, регистр, текст на трёх языках.
- [ ] **Безопасность:** ввод `<b>`, `&`, `<script>` в своём тексте выводится как текст и в превью, и в артефакте.
- [ ] **Без звука:** задание напечатано, проверка и подсказки читаются в заметке под работой.
- [ ] **Финал:** «Работа готова» (не «Сохранено»), страница и код ученика; `onFinished` один раз, артефакт в payload.
- [ ] **Переход и шорох:** вырезки разлетаются и собираются, шорох вовремя; при «меньше движения» — без анимации.
