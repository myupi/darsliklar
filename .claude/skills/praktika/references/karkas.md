# Каркас практики (шаг Г) — по образцу 01p

Эталон кода — `lessons/html/01p-struktura-dokumenta.jsx`, урочная часть (ниже пометки «УРОК»). Новая практика начинается с копии этой части:

```bash
node .claude/skills/praktika/scripts/shablon.mjs tools/<slug>-p/<slug>-p.src.jsx
```

Скрипт кладёт в исходник шапку, метку `/*@CANON@*/` и всю урочную часть 01p. Дальше:
- общее не трогать;
- урок-специфичное переписать под тему;
- собрать файл `sobrat.mjs` из навыка урока.

Если тема требует помощников урока 2 (модель блоков `blk`, `Page`, `Src`, `KeyRow`), в исходник можно добавить метку `/*@L2_HELPERS@*/`. Тогда придётся убрать из каркаса 01p одноимённые `Tag`, `MiniBrowser`, `InlineInput`, `SegToggle` и прочее — повторное объявление ломает сборку. Обычно проще остаться на помощниках 01p и расширить их.

## Конфиг задания (`cfgTn(pick, store, lang)`)

```js
{
  id: 't3', n: 3,                 // ключ store и номер объекта карты (зажигается объект n)
  kind: 'line',                   // тип для журнала: fields | line | block | doc
  C: C.t3,                        // тексты: say, order, hints[3], praise, done, drill …
  spec: {                         // вид редактора
    kind: 'line',                 // fields — поля в строках; line — одна строка; block — несколько строк; doc — весь документ
    before: [...], after: [...],  // неизменяемая рамка вокруг поля (line, block)
    ind: 4,                       // отступ строк ввода
    big: true,                    // doc с нуля: редактор во всё свободное место
    editTitle, editBody, focusBody, empty
  },
  init: () => ({ code: '' }),     // начальное состояние (fields: { title, body, title0, body0 })
  check: (st) => ({ ok, msg, cat, result }),   // одна самая полезная проблема; result — для артефакта и следующих заданий
  onSolved: (r) => store.set(...),             // перенос результата (название базы → задание 2)
  hint: (lv, st) => ({ text, cat }),           // ступень 1–3; может зависеть от текущей проблемы
  fx: (rec) => ({ hl, led, bays, marks }),     // подсветка по ступени подсказки
  orderExtra: (rec, t) => <… />,  // помощь под заданием (на телефоне)
  aids: (rec, t) => <… />,        // помощь под браузером (на компьютере)
  h3: (rec) => <CodeSample … />,  // образец третьей ступени (с другим содержимым)
  drill: { make: (cat) => ({ order, spec, init, check, aids }) }  // дополнительная задача после образца
}
```

**Ход задания** (`useTask`, общий):
- Неудачная проверка → заметка «что не так» (`FB`) и реплика.
- Вторая неудача подряд (`AUTO_HINT_AFTER = 2`) → к этому сразу следующая ступень подсказки.
- Лампочка в шапке → следующая ступень по просьбе.
- Успех после третьей ступени → дополнительная задача (`drill`). «Дальше» откроется после неё.
- **Store `tN`:** `st`, `checks`, `fails`, `hint`, `note`, `solved`, `done`, `drill`, `result`.
- **Журнал:** `attempts`, `firstTry`, `hintMax`, `drill`.

## Разбор кода под новую тему

1. **`KNOWN`** — теги своего урока и прошлых, которые встретятся в заданиях. `TAGC` — их цвета из таблицы навыка урока (`vizual-i-ux.md`).
2. **`lexDoc`** — оставить устройство. В регулярке «тег без уголка» перечислить `KNOWN`. Для атрибутов (урок 4+) научить токен `open` хранить атрибуты: `{ k: 'open', name, attrs: { href } }`.
3. **`analyzeDoc`** — правила учебного документа темы, по порядку записи, первая проблема:
   - запись тега (`badFb`: нет уголка, нет косой черты, опечатка — `nearTag`);
   - структура (вложенность, пары, порядок);
   - содержимое (текст на месте, свой текст непустой).

   Фразы — в `FB`, по одной на проблему, о правилах «нашего учебного документа».
4. **`pageOf`** — что покажет браузер. Для тем с блоками (`h1–h6`, `p`, списки, ссылки) возвращать блоки и рисовать их как в уроке 2: честные размеры заголовков, отступы, точки и номера, синие ссылки. Код не исполнять — только текст.
5. **Проверки заданий** — маленькие функции поверх `analyzeDoc`:
   - `checkLine(code, target)` — строка;
   - `checkBlock(code)` — блок;
   - `checkDoc(code)` — документ;
   - свой текст — `hasLetters` / `wordCount`;
   - заданный текст — `normName` (регистр, ё/е, кавычки не важны).

## Проверка практики (дополнительно к `../novyy-urok/references/proverka.md`)

Помощник `qa.js` работает и здесь. Поле практики — `textarea` редактора (`.ed-edit textarea` или `.tk-input`); `Q.type` понимает и textarea.

- [ ] **Каждое задание:** верное решение; каждая типичная ошибка даёт свою фразу «что не так». Вторая неудача подряд добавляет ступень подсказки; три лампочки подряд дают три ступени, последняя с образцом.
- [ ] **После решения с образцом** — дополнительная задача. Её проверка, потом «Дальше».
- [ ] **Карта:** объект загорается; на телефоне полоса в шапке показывает прошлый, текущий и следующий объект; в финале объект с названием ученика.
- [ ] **«Назад»** на решённое задание: код, подсказки, карта на месте. **«Повторить»** стирает только текущее задание; перенесённые результаты (название базы) целы.
- [ ] **Кнопки символов** вставляют в место курсора и не закрывают клавиатуру (`onPointerDown` / `onMouseDown` с `preventDefault`).
- [ ] **Открытая клавиатура** (`Q.kbd(true)`) на 320×568 и 360×640: задание, поле и «Проверить» видны; образец и схема не спрятаны.
- [ ] **Проверка терпима:** лишние пробелы, переносы, регистр, текст на трёх языках.
- [ ] **Безопасность:** ввод `<b>`, `&`, `<script>` в своём тексте выводится как текст и в превью, и в артефакте (`escHtml`).
- [ ] **Без звука:** задание напечатано, проверка и подсказки читаются в заметке под работой.
- [ ] **Финал:** «Работа готова» (не «Сохранено»), страница и код ученика; `onFinished` один раз, артефакт в payload.
